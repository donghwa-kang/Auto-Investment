# 분석 모형의 별도 프로세스 실행

승인된 합성 자료만 별도 Node 프로세스에 전달하고 결과를 다시 검증합니다. **고정된 자체 모형 코드용 실행 제한이며, 실제 Codex 연결이나 악성 코드용 OS 샌드박스가 아닙니다.** 거래 정책·장부·학습 모델에 결과를 자동 적용하지 않습니다.

## 사용과 정상 확인

[README의 설치 조건](../README.md#실행-환경)을 먼저 확인하세요. 이 실행 경로는 Windows와 Node **24.20.0**만 허용합니다. 패키지 전체의 지원 범위보다 좁은 별도 분석 조건입니다. 다른 버전/운영체제 또는 빌드 파일 누락이면 분석만 비활성화하며 기존 함수나 실제 모델로 자동 전환하지 않습니다.

프로젝트 루트에서 실행합니다. 새 의존성·API 키·로그인은 필요 없습니다.

```powershell
npm run build
npm run portfolio:web
```

1. 서버가 안내하는 주소(기본 `http://127.0.0.1:4184/?view=portfolio`)와 로컬 연결 코드로 접속합니다.
2. **Codex 분석 · 모형**에서 고정 예시 또는 [기록 전용 합성 자료](ANALYSIS_RECORDS.md)로 새 요청을 만듭니다.
3. 전달 JSON과 함께 별도 프로세스 실행 표시, 코드 SHA-256, Node/통신 버전, OS 격리 미완료 안내를 확인합니다.
4. 두 동의 → **이 자료의 모형 전달 승인** → **승인된 모형 1회 실행** 순서입니다. 생성/승인만으로 자식 프로세스를 시작하지 않습니다.
5. 정상 결과는 `모형 결과 검증 통과`, 모형 호출 1·외부 0입니다. 이는 자료 대조 결과이지 모델 성능이나 투자 수익의 증거가 아닙니다.

현재 실행 중인 구버전 서버를 자동 교체하지 않습니다. 변경 화면이 필요하면 [저장·종료 안내](PORTFOLIO_WEB.md#중지청산복구)를 따라 사용자가 종료 후 다시 빌드/시작해야 합니다. 종료는 청산과 다릅니다. 기존 완료 결과는 조회할 수 있지만 대기/실행 중 요청은 재시작 시 취소/중단되며 새 승인 없이 다시 실행하지 않습니다.

## 무엇이 분리되는가

| 경계 | 현재 동작 | 보장하지 않는 것 |
| --- | --- | --- |
| 승인 | 최소 자료·정책/요청 해시와 `execution`의 모형 코드 해시·버전·제한 종류를 함께 고정 | 해시는 서명이나 관리자 공격 방어가 아님 |
| 부모 서버 | 원본을 로컬에서 검증하고 승인 JSON만 stdio로 전달. 원본 DB/키/계정 파일은 자식에 전달하지 않음 | 부모 서버 자체가 OS 격리된 것은 아님 |
| 자식 실행 | 요청별 새 작업 폴더, 현재 Node 절대 경로, shell 비활성, 표준 입출력 파이프만 사용 | 임의 Codex 실행 파일/스크립트/사용자 질문을 실행하는 기능 아님 |
| 파일·명령 | Node 권한 모드로 추가 파일 읽기·쓰기, 자식/worker/addon/WASI/inspector 권한 미허용. entrypoint 코드 읽기는 런타임 예외 | Node의 모든 파일 접근 우회·OS ACL/악성 코드를 검증한 것이 아님 |
| 통신·모듈 | 고정 모형이 추가 모듈 로딩과 `getBuiltinModule`, `fetch`/`WebSocket` 진입점을 차단·자체 확인 | OS 네트워크 차단이나 악성 코드의 우회 불가능성 아님 |
| 결과 | 전체 통신 완료·자식 정상 종료 후 기존 엄격한 결과 스키마/출처/시점/수치 및 실행 바인딩 재대조 | 응답 도착만으로 승인하지 않음. 제안 자동 적용 없음 |

부모가 전달하는 환경변수는 `SystemRoot`/`WINDIR` 및 전용 작업 폴더를 가리키는 `TEMP`/`TMP`로 제한합니다. `NODE_OPTIONS`, 인증 정보, 사용자 PATH를 복사하지 않습니다. 이 Windows 실행 환경이 자동 추가한 기본 계정/경로 변수는 자식 시작 시 제거하고 알 수 없는 추가 변수는 실패 처리합니다. 환경변수 이름 검사도 OS 수준의 계정 격리를 대신하지 않습니다.

모형 시작 자체 검사에는 더미 `TEST_SECRET.json` 읽기, 더미 쓰기, Node 자식·worker 생성의 거절 확인이 있습니다. 실제 키 파일을 시험에 사용하지 않습니다. `net/http/https/http2/tls/dgram/dns/sqlite` 추가 로딩과 차단된 fetch도 확인합니다. 고정 모형 계산에는 파일·명령·통신 기능이 없습니다.

## 통신 모형의 범위

[공식 App Server 문서](https://learn.chatgpt.com/docs/app-server)를 참고하여 `initialize` → `initialized` → `thread/start` → `turn/start` → `item/completed` → `turn/completed`의 제한된 순서를 구현했습니다. 줄바꿈 JSON을 사용하고 wire의 `jsonrpc` 필드는 생략합니다. `turn/interrupt`도 정해진 시점에만 보냅니다. `approvalPolicy: never`와 읽기 전용 필드는 모형 계약이며 실제 권한 제한의 증거는 아닙니다.

고정 모형 식별자·메시지 순서·필드만 허용합니다. UTF-8 분할 수신은 합치되 잘못된 인코딩, 중복/틀린 ID, 알 수 없는 알림, 추가 필드, 서버의 명령/파일/인증 요청, 오류·미완성 종료는 거절합니다. 서버가 요구하는 클라이언트 작업은 실행하지 않습니다. 내부 `LOCAL_MOCK_*` JSON은 자체 자료 계약입니다.

**실제 App Server는 실행하지 않았습니다.** 전체 이벤트/확장 필드나 설치된 Codex 버전에 대한 호환성 검증이 아닙니다. 실제 연결은 이 엄격한 모형을 그대로 바꿔 끼우는 방식으로 활성화할 수 없습니다.

## 한도·취소·보관

| 항목 | 현재 제한 |
| --- | --- |
| 실행 | 요청당 1회, 동시 자식 1개, 자동 재시도/다른 모델 전환 0 |
| 시간 | 기존 승인 후 실행 예산 3초 유지. 취소/시간 초과 시 interrupt 시도 후 100ms 뒤 소유 자식 종료. 자식 자체 수명 타이머 3.5초 |
| 입력 | 자식 stdin 전체 160KiB, 내부 요청 텍스트 140KiB |
| 출력 | stdout 전체 256KiB, 줄/미완성 버퍼 192KiB, 최대 16줄. 최종 결과 기존 16KiB |
| 오류 | stderr 4KiB 초과 즉시 종료. 양이 작아도 stderr가 있으면 성공으로 수용하지 않음 |
| 메모리 | V8 old-space 64MiB. 총 RSS/OS 메모리 할당량이나 실시간 지연 보장은 아님 |
| 파일 | 모형 코드 64KiB 이하, 실행 루트 최대 100개 항목, 기존 요청 폴더 재사용/자동 삭제 없음 |

취소 이후 늦은 출력은 폐기합니다. 부모의 비정상 종료로 stdin이 닫히면 자식도 종료합니다. 재시작은 기존 미완료 상태를 중단 처리하며 재실행하지 않습니다. 이 시간 제한은 고정 모형용이며 향후 실제 모델의 실행 예산으로 검증한 값이 아닙니다.

`PORTFOLIO_WEB_ROOT/codex-analysis/executions/<요청 UUID>/`에 `worker.mjs`와 `receipt.json`만 저장합니다. receipt는 요청/코드/통신/출력 해시, 부모·자식 PID, 종료 상태의 보조 메타데이터입니다. 승인 JSON 전문과 통신 원문·stderr·인증 정보를 따로 기록하지 않습니다. 기존 승인/결과 DB 및 원본 보관 스냅샷은 부모의 별도 로컬 저장소에 남습니다.

receipt의 `COMPLETE`는 통신과 프로세스 완료를 뜻하며 최종 의미 검증은 `mock.sqlite`의 `VERIFIED_MOCK`를 확인해야 합니다. receipt는 서명된 감사 원장이나 전원 장애에 안전한 복구 근거가 아닙니다. 부모가 갑자기 종료되면 receipt가 STARTING 상태로 남을 수 있습니다. 한도 도달/손상 시 자동 삭제·수리하지 않습니다.

## 개발 검사

기존 의존성 설치 상태에서 아래 명령은 새 시험 폴더/임시 포트만 사용합니다. 사용자 서버·DB를 열거나 실제 Codex/계좌를 호출하지 않습니다.

```powershell
node work/verify-analysis-process.mjs
node work/run-analysis-process-handoff.mjs
node work/check-analysis-process.mjs
```

첫 명령은 타입/린트/형식·엔진/웹 빌드·명시된 관련 회귀·원본 정책·격리 Edge 시험을 실행하고 `work/analysis-process-verification/<시각>/report.json`에 남깁니다. `--focused`를 추가하면 타입·엔진 빌드·분리 실행 집중 검사만 합니다. 둘째는 전체 합성 이력 생성/계획/기록 CLI와 실제 웹 시작·승인·중복 실행·저장 종료·재시작을 확인합니다. 시험 가드는 부모의 외부 통신/자격증명 경로 접근을 거절하고 정해진 모형 자식 실행만 허용합니다. OS 방화벽 검사는 아닙니다.

셋째는 이번 변경 대상으로 명시한 파일, 기준 해시, 내부 파일 경로, 제한적 비밀값 패턴과 진행 항목을 점검합니다. 전체 저장소/Git 이력/사용자 파일 보안 감사가 아닙니다. 실행 결과와 실패 이력은 [PROGRESS · 공개 요약](PROJECT_STATUS.md)에 구분해 기록합니다. 핵심 구현은 [프로세스 실행기](../src/server/analysis-process.ts), [고정 모형](../src/server/analysis-process-worker.ts), [메시지 검증기](../src/server/analysis-rpc.ts), [집중 검사](../tests/analysis-process.test.ts)에 있습니다.

## 남은 필수 조건

[OS 격리 준비 안내](ANALYSIS_ISOLATION_READINESS.md)에 실제 환경의 읽기 전용 진단·후보 비교·권한 경계·더미 시험 조건을 추가했습니다. 준비 도구는 실제 Codex/OS 설정을 실행하지 않으며 항상 BLOCKED를 반환합니다. 아래 OS 격리 미완료 상태는 그대로입니다.

Node 24 권한 모델은 신뢰된 코드의 실수를 줄이는 기능이지 악성 코드 격리 수단이 아닙니다. 로컬 24.20.0 도움말에서 네트워크 권한 옵션은 확인되지 않았습니다. 참고한 [공식 24.x 권한 문서](https://r2.nodejs.org/docs/latest-v24.x/api/permissions.html)는 확인 당시 24.21.0이므로 로컬 버전과 구분합니다.

실제 에이전트의 OS 파일·명령·네트워크 격리와 우회 검사, 실제 Codex 인증/버전/전체 통신/구독 사용량·외부 모델/프롬프트 공격, 새 설치·다른 플랫폼·장기 동시 처리·실제 전원/디스크/링크 경합은 미검증입니다. 실제 시장 자료의 권리·비용·성과 검증도 별개입니다. OS 설정/설치·인증·자료 전송·모델 실행은 후속 범위를 명시적으로 확인한 뒤 진행하며, 현재 승인을 실제 연결에 재사용하지 않습니다. [연결 계획](CODEX_ANALYSIS_PLAN.md)을 따릅니다.
