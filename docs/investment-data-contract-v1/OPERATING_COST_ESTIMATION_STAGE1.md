# 운영비 추정·후보 경제성 연결 — 1단계

_원본 정책 보존 · 합성 자료 전용 · 2026-09-17_

직전 완료 20위험일의 합성 비용 이력을 후보 경제성 검사에 연결하는 개발용 기능이다. 실제 요금 청구·계좌 원장·확정 배분·수익성 예측을 지원하는 기능이 아니다. 사용자 화면과 기존 앱 시작 방법은 변경하지 않았다.

## 🎯 구현 범위

| 구성요소 | 이번에 제공하는 동작 |
| --- | --- |
| [완료 위험일 창](../../src/core/calendar.ts) | KST 09시 기준 현재 미완료일을 제외한 직전 20위험일. 시작 포함·끝 제외, 주말 포함 |
| [비용 이력 해석기](../../src/core/operating-cost.ts) | 선언된 TEST_ONLY 원화 정수 이력의 완전성·가용시각·중복·설정 결합을 검사하고 후보 운영비 계산 |
| [수량·경제성](../../src/core/risk.ts) | 거래 비용에 추정 운영비를 한 번 가산. 손절 가격 위험과 매수 현금 예약에는 가산하지 않음 |
| [승인](../../src/core/approval.ts) / [접수 재검사](../../src/core/submission.ts) | 비용과 근거 해시를 예측 입력·승인에 결합. 별도 현재 근거가 없거나 바뀌면 신규 접수 보류 |

원본 기준·위험 한도·상품 허용 범위·SOXL/SOXX 연구 후보·UI·DB 스키마는 변경하지 않았다. [원본 비용 수정 명세](OPERATING_COST_SPEC.md)의 미결정 OC-U01–08을 해소하거나 34개 전체 자료 수용시험을 완료한 것은 아니다.

## 🧮 계산과 경계

O는 창 안에 발생한 합성 운영비 합계, N은 창 안에서 완료했다고 선언한 고유 진입 의도 수다. N이 양수면 `ceil(O/N)`, N=0이면 `max(O, 승인된 남은 당일 예산 D)`를 쓴다. N=0이고 D가 `null`이면 보류한다. D=0과 미확인을 구분한다.

예를 들어 O=10원/N=3이면 후보 추정은 4원이다. 이를 실제 비용 4원씩 세 번 발생시키거나 계좌 자산에서 12원을 차감하지 않는다. 보고 기간의 확정 배분을 구현한 것도 아니다.

운영비는 경제성 총비용·예상 순손익에만 연결된다. 같은 수량·가격일 때 손절 위험, 거래 수수료와 현금 예약은 그대로다. 합성 예측기의 고정 gross/q05 선언값을 유지했으므로 **비용을 학습한 실제 예측분포**가 아니다. 수익 개선을 측정하거나 보장하지 않는다.

## 🔌 개발 입력과 사용법

이 단계에는 사용자용 비용 입력 화면·HTTP API·CLI importer가 없다. 명시 이력은 모듈의 `ApprovalContext.operatingHistory`와 `submissionReasons(state, order, quote, currentHistory)`에 별도로 전달하는 메모리 시험 경로다. 저장된 승인 snapshot에서 현재 자료를 복원하지 않는다.

계약명은 `OPERATING_COST_TEST_HISTORY_V1`이다. 정확한 타입과 필드 검사는 [operatingHistorySchema](../../src/core/operating-cost.ts), 실행 가능한 입력 예시는 [통합시험](../../tests/operating-integration.test.ts)의 `history()`를 참조한다.

| 입력 | 조건 |
| --- | --- |
| 용도 | `TEST_ONLY`, `SYNTHETIC_FIXTURE`, `liveEnabled=false` |
| 설정 | 현재 설정 전체 해시와 위험 epoch 일치 |
| coverage | 정확한 완료20위험일 창, `complete=true`, 확인 시각은 창 종료 이상·현재 이하 |
| costs | 고유 ID, `OPERATING`, `KRW`, 비음수 정수 문자열, 발생·이용 가능 시각 |
| closedIntents | 고유 진입 의도 ID, 동일한 양수 매수/매도 수량, `allOrdersTerminal=true`, 완료·이용 가능 시각 |
| dailyBudgetKrw | 원화 정수 문자열 또는 미확인 `null`. N=0의 null은 보류 |
| futureIncreaseKrw | 이 단계는 알려진 증가분 `"0"`만 허용. 미확인·비영 값은 보류 |

각 배열 최대 10,000행, 금액 최대 30자리, 식별자 최대 128자 등 입력 자원 제한이 있다. 투자 한도를 변경하는 수치가 아니라 기존 Decimal 40자리 계산과 입력 처리의 경계를 제한하는 계약이다. 합성 완료 의도는 **실제 부분 체결·프로그램 귀속·주문 최종 상태를 독립 대조한 증거가 아니다**. 실제 자료에 TEST_ONLY 표식을 붙여 사용하는 것을 승인하지 않는다.

동일 ID·동일 내용은 한 번 계산하고 순서 변경은 근거 해시를 바꾸지 않는다. 동일 ID의 내용 충돌, 미래 시각, 포함 자료보다 먼저 작성된 완전성 확인, 일부 기간 누락은 보류한다. 단순 재검사 시각은 해시에서 제외하되 위험일 창이 바뀌면 재검사에 반영한다.

입력을 생략하면 원본 합성 프로필의 명시된 무운영비 선언인 `SYNTHETIC_ZERO`를 사용한다. 실제 20일 이력을 관측했다고 채우는 대체 경로가 아니다. 비영·미분류 레거시 비용이나 비영 예약이 있으면 명시 합성 이력으로도 우회할 수 없다.

### 로컬 검사 재현

기존 [프로젝트 실행 환경](../../README.md)의 의존성이 설치된 프로젝트 루트에서 실행한다. 이번에 의존성 설치나 새 환경 설정을 추가하지 않았다.

```powershell
npm run build:engine
node --test --test-concurrency=1 dist/runtime/tests/operating-calendar.test.js dist/runtime/tests/operating-cost.test.js dist/runtime/tests/operating-integration.test.js dist/runtime/tests/submission.test.js dist/runtime/tests/learning-bridge.test.js
```

정상 조건은 빌드 종료 0, 시험 집계의 실패·취소 0이다. 자체 메모리/임시 합성 DB만 사용하며 사용자 장부를 지정하지 않는다. 실제 실행 결과와 실패 이력은 [진행 기록 · 공개 요약](../PROJECT_STATUS.md)에 구분해 남긴다. 실행 중인 사용자 서버는 재시작하지 않았다.

2026-09-17 위 핵심 시험은 80/80 통과했다. 첫 관련 회귀는 198/199로 `NETWORK-01`이 실패했고 당시 결과는 진행 기록에 보존한다. 같은 날 후속 [통신 검사 경계 보강](../NETWORK_TEST_BOUNDARIES.md)에서 부모 실행 계측·모의 엔진 의존성 검사·독립 분석 모형 시험을 분리한 뒤 핵심 80/80과 기존 관련 회귀 199/199가 통과했다. 제품 운영비 코드·원본 정책은 후속 작업에서 변경하지 않았다. 전체 제품 회귀나 OS 통신 격리를 완료한 결과는 아니다.

## ⚠️ 보류와 다음 단계

- `OPERATING_COST_UNKNOWN`: 형식·완전성·시각·비용 분류 등 확인 실패. 세부 코드도 함께 반환한다. 0원으로 대체하지 않는다.
- `OPERATING_COST_EVIDENCE_CHANGED`: 승인과 현재 증거가 다르거나 새 결합이 없는 구형 미접수 주문. 과거 snapshot을 수정하지 않고 접수를 보류한다. 기존 엔진에서는 거절 후 예약을 해제한다.
- `OPERATING_COST_ALLOCATION_UNSUPPORTED`: 확정 비용 배분이 없으므로 해당 학습 정답은 미확정이다.

기존 무비용 앱 실행은 계속 지원한다. 명시 이력 주문을 저장해도 일반 엔진에는 현재 이력 공급자가 없으므로 자동 접수하지 않는다. 기존 완료 결과의 읽기·기존 보유 보호를 새 승인으로 이주시키지 않으며 사용자 DB를 마이그레이션하지 않는다.

다음 과제는 비용 의무의 발생/지급/예약 ID 연결과 독립 장부 대조, 확정 보고 배분·학습 가용시각 계약이다. 외화 환산·환불·공유 구독 귀속·부분 이력·미래 증가분/D 중복·늦게 도착한 비용의 소급 의미는 미결정으로 남긴다. 실제 계좌·API·유료 AI·실주문·OS 격리·투자 성과는 이번에 검증하지 않는다.

2026-09-18 후속 [보조장부·시험 보고 배분 2단계](OPERATING_COST_SUBLEDGER_ALLOCATION_STAGE2.md)는 위 과제 중 별도 TEST_ONLY KRW 장부의 ID 대조, 명시 시험기간 배분·가용시각 검사를 제공한다. 이 문서의 1단계 실행 결과와 구분하며 실제 장부·학습 자동 연결이나 OC-U01–08의 해결을 뜻하지 않는다.
