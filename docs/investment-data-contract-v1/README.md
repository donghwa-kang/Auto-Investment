# 투자 자료 계약 v1

_원본 거래 기준을 실제 자료와 연결하기 위한 설계 명세 · 2026-09-17_

2026-09-21 후속 결정: [키움 전환·공급원 대조표](KIWOOM_SOURCE_PLAN.md)에 키움 우선 후보, D01–D22별 보완 출처·비용·미확인 주문 기능을 정리했다. 아래 작성 당시 토스 구현 설명과 `contract.json`은 보존하며 키움 연결·G1/G2 통과를 뜻하지 않는다.

후속 상태: [운영비 오프라인 연결 1단계](OPERATING_COST_ESTIMATION_STAGE1.md)에 완료 위험일·명시 합성 비용의 부분 구현과 검사 범위를 기록했다. 아래 설계 당시 상태·원본 참조와 전체 자료 수용 계획을 통과 상태로 바꾸지 않는다.

---

이 문서는 자료 가족 D01–D22의 필요 조건, 시점·품질, 현재 구현 경계와 수용시험을 정의합니다. 대상은 국내·미국 시장 탐색, 선택형 테마 조사, 향후 실자료 모의매매입니다. 현재 상태는 **설계 명세 / 신규 후속 실제 수집 HOLD**이며 API 연결·거래 규칙·위험 한도·모델·주문 경로를 변경하지 않습니다. 이 HOLD는 이번 신규 연동 범위에 적용하며 기존 승인 범위나 합성 앱 동작을 취소·변경하지 않습니다.

[공급원 등록부](SOURCE_REGISTER.md)는 S-001–S-015의 근거·제공 범위·권리 확인 상태를, [수용시험 계획](ACCEPTANCE_PLAN.md)은 AT-D01–AT-D22의 입력·기대 결과·증거를 담당합니다. 아래 시험 ID 연결은 시험 요구의 추적이지 통과 기록이 아닙니다. 프로젝트 실행 방법은 [루트 안내](../../README.md)를 따르며 이 명세에는 새 실행 명령이나 환경변수가 없습니다.

[운영비 수정 명세](OPERATING_COST_SPEC.md)는 비용·완료 위험일의 코드 차이와 후속 수정 범위를 다룹니다. [기계 판독 명세](contract.json)는 원본 핵심값 32개와 미실행 시험 ID를 대조하기 위한 파일이며 앱에서 로드하는 설정이 아닙니다. 전체 정책을 대체하지 않습니다.

## 📋 적용 범위와 현재 상태

| 구분 | 이 문서에서 확정하는 것 |
| --- | --- |
| 설계에만 확정 | 자료 가족, 원본 요구 추적, 상태 구분, 시험 요구 |
| 아직 HOLD | 신규 후속 실제 수집·장기 저장·공급자 응답 수용·거래 입력 승격 |
| 이번 범위 밖 | 키 읽기, 계좌 조회, 주문, 유료 AI, OS 권한 변경 |
| 완료 의미 | 명세와 미확정 사항의 정적 대조 완료 |
| 완료가 아닌 것 | 실제 데이터 정확성·전략 수익성·실거래 자격 증명 |

`필수`는 해당 거래 경로 승인 전에 필요하다는 뜻입니다. 문서 작성이나 승인된 일부 자료의 독립 수용시험에 모든 자료가 필요하다는 뜻은 아닙니다. `조건부`는 활성 모듈·시장·상품·등록 모델이 해당 입력을 요구할 때 적용합니다. `보조` 자료를 필수라고 바꾸거나 필수 자료를 보조라고 바꾸는 일은 이 문서의 권한 밖입니다.

실제 연결 범위는 [기존 자료 제공 범위 대조](../TOSS_DATA_CAPABILITY_AUDIT_20260914.md)와 [실시세 사전점검 코드](../../src/server/market-paper-check.ts)(24–98행)를 기준으로 구별합니다. 기존 토스 경로는 SOXL/SOXX 단발 시세 점검 후 `ABSTAIN`, 전략 미평가·모의 주문 0건입니다. [수신 변환 계약](../../src/core/source-ingest-schema.ts)(120–130행)은 `MOCK_CONTRACT/MOCK_RESPONSE`, [시장 품질 계약](../../src/core/market-quality-schema.ts)(117–130행)과 [학습 계약](../../src/core/learning-schema.ts)(77–86행)은 `TEST_ONLY`입니다. 자료의 표시만 바꾸어 이 경계를 통과시키지 않습니다.

## 📌 원본 우선순위와 해석 주의

기준 파일은 [공통 정책 v2.3](../../outputs/AI_TRADING_POLICY_v2.3.json), [공용 B/P v1.0](../../outputs/TRADING_STRATEGY_SPEC_v1.0.json), [테마 정책 v1.3](../../outputs/THEME_RESEARCH_POLICY_v1.3.json)입니다. 세부 의미는 [공통 가이드 v2.3](../../outputs/AI_TRADING_GUIDE_v2.3.md), [테마 가이드 v1.3](../../outputs/THEME_RESEARCH_GUIDE_v1.3.md)를 함께 대조합니다. 아래 행 번호는 이 명세 작성 시의 위치이며, 소비자는 파일 버전·내용 해시도 함께 결합해야 합니다.

- **연구 범위 정정:** [후속 사용자 연구 범위](../../profiles/research-scope-v1.json)(4–13행)는 단일종목 레버리지이면서 요구예탁금 3,000만원 이상인 상품을 사용자 제외 대상으로 정하고, SOXL/SOXX를 검증 후보에 포함합니다. 원본 공통 정책의 넓은 예탁금 제외 문구(85행), 테마 정책의 레버리지 `OBSERVE_ONLY`(61·114행)는 이 후속 연구 분류와 구분해 보존합니다. 후속 정정은 실거래 자격·상품·비용·예측·실행 검증의 면제가 아닙니다.
- **MARKET_SCAN은 일부 규칙이 이미 정의됨:** 공통 가이드 230행은 최근 완료 20일 거래대금 중앙값 상위 최대 100개/시장, 완료 봉 후보의 RVOL 내림차순·스프레드 오름차순·고정 ID 순, AI 정밀 분석 최대 5개를 정합니다. 이 순서를 임의 재설계하지 않습니다. 실제 자료 연결·버전 있는 실행 프로필은 미구현이고, 테마 상세 선정 프로필은 별도 미정입니다.
- **시간 한도 의미 보존:** 뉴스 300초는 기사 나이가 아니라 최근 수집 성공의 신선도입니다. 호가 2초를 현재가·공시·구성종목의 공통 TTL로 확대하지 않습니다. 회사의 최신 재무보고가 수개월 전이라는 사실과 조사 보고서의 30일 만료도 다릅니다.
- **비활성 입력:** 미사용 차트 연구 지표·테마·LLM·수급은 등록된 버전에서 `NOT_APPLICABLE`과 이유를 명시합니다. 필수 입력의 `UNKNOWN`을 이 상태로 바꾸지 않습니다. 뉴스 LLM이 없는 Q/QT도 안전 공시·이벤트·거래정지 검사는 끄지 못합니다(공통 정책 577행).
- **원본의 작성 당시 상태:** `runtime_implemented=false` 등 보존된 명세 상태와 현재 합성 구현을 혼동하지 않습니다. 원본 REST 1.2.15(공통 정책 348행), 모형 수신 계약 1.2.17은 각각 확인 당시 버전이지 현재 공급자 호환성의 증명이 아닙니다.

## ⚙️ 공통 관측 envelope 제안

다음 필드는 **향후 로컬 내부 계약 제안**입니다. 토스·DART·SEC 등의 실제 응답 필드나 이미 구현된 공통 스키마가 아닙니다. 공급자가 제공하지 않는 원천 정보를 로컬 값으로 위장하지 않습니다. 저장 위치·형식·크기·암호화·보관/삭제 기간도 권리 확인과 후속 설계 전에는 미정입니다.

| 내부 필드 묶음 | 목적 | 미확인 처리 |
| --- | --- | --- |
| `contract_version`, `family_id`, `observation_id` | 계약·가족·관측 식별 | 수용 불가 |
| `source_id`, `source_spec_version` | 등록 공급원·관측 명세 | `UNKNOWN` |
| `rights_status`, `rights_evidence_id` | 수집·보관 권리 근거 | `HOLD` |
| `instrument_id`, `issuer_id`, `market`, `venue`, `currency` | 거래종목·발행사 구별 | 필드별 `UNKNOWN` |
| `event_at`, `published_at` | 사건/봉 시각·발표 시각 | null + 이유 |
| `received_at`, `available_at` | 실제 수신·검증 후 가용 시각 | 없으면 수용 불가 |
| `effective_at`, `as_of` | 효력 시각·소비 판단 시각 | 해당 계약 검사 |
| `source_revision`, `source_revision_status` | 공급자 정정 식별 | null / `UNKNOWN` |
| `local_observation_version`, `supersedes_id`, `duplicate_of` | 로컬 관측·정정·중복 관계 | 원천 정정과 분리 |
| `source_document_id`, `source_url`, `payload_hash` | 허용된 원문 근거 | 누락 이유 보존 |
| `value`, `unit`, `period_start`, `period_end`, `basis` | 값·단위·기간·가격/회계 기준 | 0으로 채우지 않음 |
| `coverage`, `quality_status`, `reason_codes` | 범위·완전성·상충 | 보류 범위 표시 |
| `required_by`, `profile_hashes`, `policy_hashes` | 소비자·프로필·원본 결합 | 승인 미생성 |
| `last_success_at`, `expires_at`, `expiry_basis` | 수집 상태·적용 만료 | TTL 미정 표시 |
| `data_origin`, `purpose`, `readiness_status` | 합성/실제 관측·사용 범위 | 자동 승격 금지 |

시간 네 종류는 `event_at`(무슨 시점의 사건/봉인가), `published_at`(언제 발표됐는가), `received_at`(프로그램이 실제로 언제 받았는가), `available_at`(수신 후 검증·처리를 거쳐 언제 사용할 수 있었는가)입니다. 기업행동의 `effective_at`과 판단의 `as_of`는 별도입니다. 발표·사건 시각이 없으면 null과 원인을 남기고, 현재 받은 이력의 수신 시각을 과거로 소급하지 않습니다. 해당 자료가 요구하는 시간 순서와 `available_at <= as_of`를 적용하며, 예정 사건의 발생 시각이 미래라는 이유만으로 발표된 일정을 폐기하지 않습니다.

`source_revision=UNKNOWN`과 `local_observation_version`은 다른 개념입니다. 동일 논리 키·동일 원천 버전에 다른 값이 오거나 원천 정정 순서를 알 수 없으면 덮어쓰기 대신 상충/추가 관측을 보존합니다. 해시는 내용 일관성 검사이지 공급자 인증이나 원문의 진실성 증명이 아닙니다.

자료가 실제 요청으로 수신됐다는 사실, 형식이 맞다는 사실, 해당 전략이 사용할 수 있다는 판정은 각각 분리합니다. `REAL_OBSERVED` 같은 출처 표지를 장래 도입하더라도 그것만으로 `DATA_READY`가 되지 않습니다. 현재 실행 계약은 변경하지 않습니다.

## 📚 범위·식별·선정 자료 D01–D04

### D01 출처·권리·시점 — 필수

- **원본:** [공통 정책](../../outputs/AI_TRADING_POLICY_v2.3.json)(588–602행), [B/P](../../outputs/TRADING_STRATEGY_SPEC_v1.0.json)(19–32행), [공통 가이드](../../outputs/AI_TRADING_GUIDE_v2.3.md)(284행). 발표·수신·가용·정정과 당시 이용권을 분리하고 미래 자료·사후 정정을 과거에 덮어쓰지 않습니다.
- **공급·현재:** 모든 공급원에 공통 적용합니다. 권리 근거 후보는 [S-002·003·006·008·010·011](SOURCE_REGISTER.md)이며 이 ID가 권리 승인이라는 뜻은 아닙니다. 현재 [관측 변환기](../../src/core/source-ingest-normalize.ts)(25–49행)는 MOCK이며 발표/원천 정정 null과 로컬 버전을 분리합니다.
- **품질·미정:** 자료별 권리·공급 범위·장기 저장·파생물/외부 AI 재사용·삭제 의무는 공급원별 확인 전 `HOLD`입니다. 별도 일괄 TTL은 만들지 않습니다. 권리 미확인은 수신 후 처리만이 아니라 해당 새 수집 자체를 잠급니다.
- **수용·영향:** [AT-D01](ACCEPTANCE_PLAN.md): 미래 추가/변조 불변성, 시각 역전, 원천 정정 UNKNOWN, 권리 미확인 수집/전송 차단. 실패 관측은 격리하고 의존 진입만 보류하며 기존 보호를 해제하지 않습니다.

### D02 종목 식별·당시 모집단 — 필수

- **원본:** [공통 정책](../../outputs/AI_TRADING_POLICY_v2.3.json)(79–108·595행), [테마 가이드](../../outputs/THEME_RESEARCH_GUIDE_v1.3.md)(38·155행). 토스 지원 KR/US 주식·ETF, 발행사/상장종목/주식 종류와 당시 상장·폐지·코드 변경을 구별합니다.

- **품질·미정:** 해당 위험일·거래 세션 갱신과 변경 공지 반영이 필요합니다([공통 가이드](../../outputs/AI_TRADING_GUIDE_v2.3.md),294행). 과거 상장폐지/재상장·복수 상장 매핑 공급자와 보관 범위는 미선정 또는 미확인입니다. 시험용 `metadataMaxAgeMs`를 실자료 TTL로 승계하지 않습니다.
- **수용·영향:** [AT-D02](ACCEPTANCE_PLAN.md): 같은 심볼·다른 발행사, ISIN/거래소 충돌, 코드 변경/폐지/미래 편입. 불완전 모집단은 해당 선정 평가를 보류합니다. 현재 목록에서 사라졌다고 보유·미확정 주문 기록을 지우지 않습니다.

## ⚠️ HOLD 처리와 다음 승인 경계

권리/비용·인증 범위가 미확인인 공급원은 **새 수집 자체가 HOLD**입니다. 웹에 문서가 있다는 사실, API 키를 보유한 사실, 모형 응답이 통과한 사실은 수집·장기 저장·외부 AI 전송 허가가 아닙니다. 원문을 보관할 수 없는 경우 허용된 메타데이터/해시만으로 무엇을 재현할 수 있는지 한계도 기록해야 하며, 권리 제약을 우회해 원문을 수집하지 않습니다.

제한 수집에는 해당 수집·보관 목적의 권리와 비용·접근 조건을 먼저 확인합니다. 아직 사용하지 않는 외부 AI 전송·모델 학습 권리까지 한 번에 승인받아야 한다는 뜻은 아닙니다. 제한 수집 승인, 수집 후 품질 수용, 별도 AI 용도 승인은 독립된 단계입니다.

권리가 확인된 뒤에도 수신 성공, 형식 수용, 해당 시점의 사실/coverage 검증, 전략 자료 적격, 주문 승인은 별도 판정입니다. `UNKNOWN`, `FAILED`, `CONFLICT`, `NOT_APPLICABLE`을 구별하고 결측을 0·무사건·기존값 유지로 자동 복원하지 않습니다. 영향을 받지 않는 독립 자료 가족의 문서/오프라인 수용시험은 계속할 수 있습니다.

신규 진입 보류 범위는 `instrument`, `source`, `profile`, `market`, `portfolio` 중 실제 의존 범위와 이유를 남기는 설계를 제안합니다. 정확한 enum/저장 구현은 후속입니다. 범위가 불명확하면 보수적으로 보류하며 영향 없는 전체 프로그램을 무조건 종료하는 동작으로 대체하지 않습니다.

기존 보호·주문 대조는 신규 진입과 분리합니다. 단순 목록 편출·테마 만료·학습 실패 때문에 보호를 취소하지 않습니다. 동시에 유효한 가격·확정 잔여 수량·검증된 청산 프로필이 없는데 보호 유지를 이유로 임의 새 주문/정정을 보내서도 안 됩니다. 해당 경우 대조·알림·`EXIT_BLOCKED` 상태를 보존하며 청산 가능성을 보장하지 않습니다. 근거는 [공통 정책](../../outputs/AI_TRADING_POLICY_v2.3.json)(160–175·345·706행), [공통 가이드](../../outputs/AI_TRADING_GUIDE_v2.3.md)(303–314행), [테마 가이드](../../outputs/THEME_RESEARCH_GUIDE_v1.3.md)(85–92·171행)입니다.

후속 구현/수집 승인 전에 확정할 항목은 공급원별 수집·보관·재사용 권리와 비용, 실제 요청 대상/예산, 미정 TTL·coverage·상품/선정/벤치마크/예측/체결 프로필, 원시/정규화 자료 저장·복구 계약입니다. 시계·통합 뉴스·컨센서스·거시/실적 일정·전체 기업행동/종목 계보·업종/파생 노출 등 공급자가 미선정인 입력은 그대로 남깁니다.
