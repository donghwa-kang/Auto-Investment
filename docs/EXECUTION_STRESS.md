# 초기 비용·체결 스트레스 시험

_2026-09-21 · 오프라인 합성 PAPER 개발 시험. 수익성·실자료·실전 적합성 검증이 아닙니다._

## 📋 제공 범위

별도 실행에만 선택한 스트레스 조건을 연결하여 공용 판단·위험·체결·장부 경로를 검사합니다. 기본 웹 앱, 기존 실행 설정, 원본 정책과 합성 프로필은 바꾸지 않습니다. 뉴스 자동 청산, SOXL 고정 감가, 실계좌/API/유료 AI 연결은 없습니다.

이 단계는 [투자 재검토](INVESTMENT_CAPABILITY_REVIEW_20260917.md)의 A 자료 계약과 병행할 수 있는 초기 C/D 시험입니다. 실제 자료 수용과 현실 비용 교정, 미사용 구간 평가, 전진 모의는 여전히 별도 단계입니다. [운영비·학습 통합 보류](investment-data-contract-v1/OPERATING_COST_SUBLEDGER_ALLOCATION_STAGE2.md)도 유지합니다.

## ⚙️ 조건과 적용 계약

선택 옵션 `PortfolioPaperEngine(..., { executionStress })`는 [엄격한 스키마](../src/core/execution-stress.ts)를 사용합니다. `schemaVersion=OFFLINE_EXECUTION_STRESS_V1`, `purpose=TEST_ONLY`가 필요하며 미지 필드·소수·음수는 거절합니다. 아래 범위는 프로그램 입력 제한이며 투자 추천값이나 실측 최악 조건이 아닙니다.

| 필드              | 허용 정수 범위 | 의미                                         |
| ----------------- | -------------: | -------------------------------------------- |
| `latencyMs`       |        0–60000 | 의도 저장부터 체결까지의 최소 시간           |
| `cancelLatencyMs` |        0–60000 | 취소 요청부터 확정 가능 시각까지의 최소 간격 |
| `adverseTicks`    |          0–100 | ask 상승·bid 하락 각각에 더하는 틱 수        |
| `liquidityBps`    |        0–10000 | 표시 bid/ask 잔량의 잔존 비율                |

| 비교 조건   | 최소 체결 시간 ms | 취소 지연 ms | 양쪽 틱 악화 | 잔량 비율 bps |
| ----------- | ----------------: | -----------: | -----------: | ------------: |
| CONTROL     |                 0 |         2000 |            0 |         10000 |
| DELAY_ONLY  |               500 |         2000 |            0 |         10000 |
| SPREAD_ONLY |                 0 |         2000 |            2 |         10000 |
| ADVERSE     |               500 |         3000 |            2 |          5000 |
| EXTREME     |              2500 |         5000 |            5 |          1000 |

기존 `INTENT_SAVED` 접수와 후속 tick 체결은 유지합니다. `latencyMs`는 체결 가능 여부만 제한하고 취소 확정·보호 검사를 건너뛰게 하지 않습니다. 실측 통신 지연이나 거래소 도착시각 모형은 아닙니다. 관측 간격이 1초라면 500ms 차이를 식별하지 못할 수 있습니다. 기존 합성 프로필의 사용되지 않던 `execution.latencyMs`를 실측값으로 해석하거나 덮어쓰지 않습니다.

호가는 원본의 시각·출처·가용시각·정지 상태를 유지한 채 결정적으로 변환합니다. 기존 사전점검 호가도 같은 함수로 변환해 일치 여부를 확인하므로 임의 호가 변경이 허용되는 것은 아닙니다. 변환은 진입 심사·수량·시가평가·보호·체결 모두에 적용됩니다. 따라서 SPREAD_ONLY도 신호 이후 체결만 격리한 인과 실험은 아닙니다. 잔량은 소수 주를 버리고, bid가 0 이하가 되는 조건은 실패시킵니다.

체결은 여전히 매수 ask≤지정가, 매도 bid≥지정가일 때만 가능합니다. 불리한 가격을 지정가로 잘라 허위 체결하지 않습니다. 취소 확정 전에는 부분체결이 가능하고, 확정 시각부터 체결하지 않습니다. 미접수 의도는 기존처럼 로컬에서 즉시 취소하며 UNKNOWN은 증거 없이 해소하지 않습니다. 유효 호가가 없으면 취소 완료도 자동 확정하지 않고 예약·노출을 남기는 기존 보수적 동작을 유지합니다.

이 시간 기반 취소 확정 모형은 상태가 확정된 합성 주문에만 적용됩니다. SELL `UNKNOWN`/`CANCEL_UNKNOWN`은 저장된 `cancelFinalAt`이 지나도 확정 근거가 아닙니다. DEV-D01에서 포지션 청산 루프도 두 상태를 건너뛰도록 수정했습니다. 정책의 무진행 2초·대체 상한 2회나 스트레스 지연값을 바꾸지 않았습니다.

스프레드는 체결대금에 이미 포함됩니다. [기존 체결 처리](../src/core/simulator.ts)가 실제 체결대금의 수수료를 한 번 반영하며 별도 슬리피지 비용이나 감가 비용을 추가 차감하지 않습니다. [위험 계산](../src/core/risk.ts)의 예상 adverse 버퍼는 장부 지출과 다릅니다. 틱·수수료는 기존 TEST_ONLY 값이며 실제 종목별 틱표·세금·환전 비용 프로필은 아닙니다.

## 🔧 실행 방법

프로젝트 루트의 PowerShell에서 실행합니다. 기존 [실행 환경](../README.md#실행-환경)과 설치된 의존성을 사용하며 새 의존성이 없습니다.

```powershell
npm run build:engine
node dist/runtime/src/server/execution-stress-cli.js 5000000 KR
node dist/runtime/src/server/execution-stress-cli.js 1000000 US
```

인수는 1–5,000,000원의 정수와 `KR` 또는 `US`입니다. LOW·PILOT을 고정하고 미국 사례의 가상 달러 배정은 입력액의 40% 이내로 생성합니다. 계좌 환전은 없습니다. 다른 금액은 같은 명령의 첫 인수를 바꾸어 비교합니다.

정상 출력은 `OFFLINE_STRESS_SAMPLE_COMPLETE`와 새 `work/execution-stress-runs/run-*/report.json` 경로입니다. 매번 새 폴더를 만들며 기존 사용자 DB를 열지 않습니다. 잘못된 입력·LIVE 설정·실행 오류는 `OFFLINE_STRESS_SAMPLE_FAILED`, 종료 코드 1이며 자동 재시도·실 API fallback은 없습니다. 실패한 실행을 통과 보고서로 저장하지 않습니다.

샘플은 기존 합성 120세션 B 자료의 첫 프레임만 사용합니다. 이후 가격을 유지하는 100ms 간격 호가를 20초 동안 명시적으로 생성하고 10초에 청산을 요청합니다. 이는 실제 분봉 보간, 전체 시장 검색, 장기 전략 백테스트가 아닙니다. 고정 가격 때문에 지연만 바꾸면 손익이 같을 수 있으며, 지연에 가격 영향이 없다는 일반 결론을 낼 수 없습니다.

## 📊 보고서 해석과 복구 경계

보고서에는 입력·정책·실행·스트레스 해시, 판단 사유·승인 수량/비용, 최초 체결시각, 체결 수량, 수수료, 순자산 변화, 종료 거래 순손익, 통화별 가용 현금, 열린 계획 위험, 주문별 시계열과 최종 상태가 포함됩니다. 승인 수량과 실제 체결 수량을 구분합니다.

- `FLAT`: 보고 종료 시 잔여 보유와 미완료 주문이 없음. 수익성 통과가 아닙니다.
- `UNRESOLVED_EXPOSURE`: 미청산 보유 또는 미완료 주문이 있음. 실행 루프 종료와 청산 성공을 구분합니다.
- `closedTradeNetKrw`: 완료 거래만의 순손익. 미청산 손실을 대신하지 않으며 `equityChangeKrw`·잔여 수량과 함께 확인합니다.
- `performanceQualified=false`, `learningEligible=false`, `liveEnabled=false`: 결과의 허용 범위를 고정합니다.

스트레스 설정은 복사·동결한 뒤 manifest와 신규 승인 해시에 결합합니다. 일반 엔진 API로 별도 DB를 사용할 경우 같은 설정을 제공해야 재개할 수 있습니다. 설정 생략/변경 또는 기존 기본 DB에 스트레스 덧씌우기는 DB 쓰기 전에 거절됩니다. 정상 재개도 RECONCILING에서 시작하며 미체결 취소·대조를 우회하지 않습니다. CLI 자체는 메모리 DB로 실행하고 최종 JSON을 저장하므로 CLI 실행 도중 강제 종료의 복구 기능은 제공하지 않습니다.

학습 수집과 스트레스를 동시에 켜는 것을 거절합니다. 기존 장부·운영비 배분·학습 입력 계약에 자동으로 편입하지 않습니다. 현재 명시된 손실 제한은 계획 위험이며 갭·정지 시 실제 손실 상한을 보장하지 않습니다.

시간과 호가만 진행할 때는 매 tick마다 주문 전체, 기체결량, 잔여 수량, 예약·통화 지갑과 미확정 상태를 대조합니다. 새 임시 SQLite 재개 및 직접 생성한 자식 프로세스의 강제 종료/재시작에서도 이를 확인합니다. 사용자 DB·실행 서버·lease를 지우거나 수정하지 않습니다. 복구 시험의 lease 만료는 주입된 시험 시계로 진행하며 PC 전원 차단·실시간 20초 대기 시험은 아닙니다.

늦게 도착한 명시적 합성 체결 증거는 기존 `applyOrderEvent` 계약으로 한 번만 반영합니다. 부분 체결 후에는 알려진 수량과 매각 대금만 반영하고 나머지는 미확정으로 유지합니다. 다음 tick의 기존 TEST_ONLY 현금 결제와 근거 없는 주문 확정을 구별합니다. 취소가 확정된 경우에만 남은 수량의 대체를 허용하며, 전량 체결이면 재매도하지 않습니다. 이것은 실제 주문조회·체결내역·잔고 대조의 충분성 검증이 아닙니다. 해당 모형은 후속 DEV-D02 범위이며 아직 연결하지 않았습니다.

실제 호가 대기열·공유 잔량 소진·시장 충격·실측 지연 분포·다일 결제·SOXL 일일 재설정·실제 뉴스·수익성·OS 격리는 미검증입니다. 정적 통신 검사는 OS 차단이나 허용 패키지 내부 전체 감사를 대신하지 않습니다. 이번에는 화면이나 웹 입력을 추가하지 않았고 기존 서버를 재시작하지 않습니다.
