# 토스 시장 데이터 제공 범위 대조 — 2026-09-14

2026-09-14 공개 문서 및 현재 코드 기준. **토스의 데이터 제공 범위는 현재 수집기보다 넓지만, 전체 시장 자동매매에 필요한 자료가 모두 확보된 것은 아니다.** 이번 결과는 조사·연동 설계이며 실제 데이터 수용검증이나 새 매매 기능이 아니다.

공식 REST 명세는 이전 연결 시험의 1.2.15가 아니라 **1.2.17**이다. 현재 공개 명세의 경로 33개·연산 36개 중 시장 자료 관련 GET 연산 20개를 구조적으로 대조했다. 이 숫자는 새로 추가된 기능 수나 우리 프로그램의 구현 개수가 아니다. [공식 REST 명세](https://openapi.tossinvest.com/openapi-docs/latest/openapi.json).

2026-09-14 구현 후속: [오프라인 수신 형식 변환](TOSS_OFFLINE_INGEST.md)을 별도 MOCK_RESPONSE 계약·CLI로 추가했다. 종목/지표 봉 시각·페이지·상충·격리 저장을 모형으로 시험하며 실제 수집기·기존 TEST_ONLY 거래 경로는 바꾸지 않았다. 아래 표의 실제 연결 상태와 이력/권리/프로필 미확인은 유지한다. 아래 ‘구현 제안/다음 단계’는 최초 대조 당시 기록이며 해당 오프라인 변환 범위만 후속 구현한 것이다.

## 2. 연동 전 반드시 처리할 차이

### 봉 시각·수정주가·과거 이용 가능 시각

공식 필드에서 주식 `Candle.timestamp`의 1분봉은 **종료**, `MarketIndicatorCandle.timestamp`는 **시작**으로 설명한다. `before`는 경계를 포함하며 `nextBefore`를 다음 요청에 전달한다. `adjusted` 기본값은 true다. [REST 명세](https://openapi.tossinvest.com/openapi-docs/latest/openapi.json).

따라서 다음 변환 설계가 필요하다. 아래는 구현 제안이며 아직 실행 코드에 적용하지 않았다.

- 종목 봉과 지표 봉의 시간 변환을 분리한다. 1분봉을 대상으로 정규화하고 일봉은 별도 거래일 계약으로 다룬다. 원시 시각과 변환한 시작/끝 시각을 함께 보존한다.
- 페이지 경계 중복을 제거하되 내용이 다른 같은 봉을 덮어쓰지 않는다. 반복/역행 커서, 빈 페이지, 중간 실패, 요청 예산 소진은 ‘수집 완료’가 아니라 불완전 상태로 남긴다.
- 원본 정책의 원시 체결 가격·시점별 유효 분할 조정을 유지한다. 현재 수집기의 명시적 `adjusted=false`를 그대로 보존한다. 수정주가만으로 분할 당시의 공개·효력·정정 이력이 확보됐다고 처리하지 않는다.
- 수집 시각, 원천 시각, 자료를 실제 사용할 수 있었던 시각을 구별한다. 오늘 받은 과거 봉의 수신 시각을 과거로 소급하지 않는다. 공급자 정정 번호가 없다면 로컬 관측 버전과 구분하고 원천 정정 상태는 UNKNOWN으로 둔다.
- 과거 시점의 가용성 증거가 없는 일괄 이력은 ‘현재 수집한 과거 자료’로만 보관한다. 당시 알고 있던 정보로 재생하는 검증의 합격 자료로 자동 승격하지 않는다.

### 필요한 이력 길이는 아직 확보되지 않음

[원본 B/P 명세](../outputs/TRADING_STRATEGY_SPEC_v1.0.json)는 완료된 120세션·1분 원천 봉·별도 벤치마크를 요구한다. 예를 들어 미국 정규장을 매일 390분으로 단순 가정하면 **종목 하나만 46,800봉, 페이지당 200봉을 가득 받아도 최소 234페이지**다. 조기 종료·정지·장외 자료·중복·누락에 따른 실제 요청 수는 달라진다. 이는 계산 예시이지 실제 수신 가능 기간이나 수집 시간 측정값이 아니다.

공개 페이지네이션 설명만으로 120세션 또는 [원본 성과 검증](PHASE2_READINESS_AUDIT.md)의 목표 과거 36개월이 보장되지는 않는다. 가장 오래된 제공 일자, 상장폐지 종목 이력, 누락/정정 범위를 실제 제한 조회로 확인해야 한다. 현재 ACTIVE 목록은 과거 시점의 상장·상장폐지 모집단을 대신할 수 없다.

기존 [시장 품질 입력](../src/core/market-quality-schema.ts)과 [신호 재생 입력](../src/core/signal-replay-schema.ts)은 `purpose=TEST_ONLY`를 강제한다. 실제 자료를 이 표시로 바꿔 통과시키면 안 된다. 50,000행의 짧은 품질 창과 종목별 장기 이력 파일을 구분하고, 전체 이력을 한 창에 억지로 넣기 위해 상한을 늘리지 않는다.

### 수급·벤치마크·기업 조사

국내 투자자별 자료는 일별 거래량이며 잠정치/후속 갱신과 `updatedAt`이 있다. 종목 상세의 `leverageFactor`만으로 기초자산 종류나 사용자 제외 조건을 모두 판별할 수는 없다. [REST 명세](https://openapi.tossinvest.com/openapi-docs/latest/openapi.json).

후속 설계에서는 수급을 실시간 확정 기관 매수로 간주하지 않고, 잠정·확정 및 지연 정보를 구별한다. 미국 종목의 수급을 국내 자료나 거래량 증가만으로 추정해 채우지 않는다.

벤치마크는 데이터가 있다는 이유만으로 자동 선정하지 않는다. 원본의 거래량/VWAP 요구와 시장·업종 대응을 검증해야 하며, 거래량 0 또는 의미가 불명확한 지수를 ETF 대용으로 강제 사용하지 않는다. 뉴스·공시·분할/배당·ETF 구성종목/중복 노출·기업 실적 일정은 별도의 시점 및 이용권 계약이 남아 있다. AI가 부족한 사실을 추정해 거래 근거로 채우는 경로는 만들지 않는다.

### 전체 시장 수집량과 실시간 제약

공식 가이드상 REST 제한은 클라이언트×그룹별이며 변경 가능하다. 이번 표기값은 `STOCK_ALL` 1/s, `STOCK` 5/s, `MARKET_DATA` 15/s, `MARKET_DATA_CHART` 20/s, `MARKET_INFO` 3/s, `RANKING` 5/s, `STOCK_TRADING_TREND` 10/s다. 운영에서는 응답의 한도·잔여량·재시도 정보를 우선해야 한다. 웹소켓은 계정당 2연결·연결당 100구독이며 채널×종목으로 센다. 시세는 유실 가능하고 유실 감지 sequence를 제공하지 않는다고 안내한다. [공식 호출 제한·웹소켓 가이드](https://developers.tossinvest.com/docs).

이는 초당 최대치까지 계속 조회하라는 허가나 전체 종목 실시간 감시의 보장이 아니다. 한 연결에서 체결과 호가를 함께 쓰면 단순 계산상 50종목 분량이므로, 모든 종목을 무제한 구독하는 설계는 사용할 수 없다. 이번에는 웹소켓에 연결하지 않았으며 별도 AsyncAPI 전체 스키마의 호환성 검증도 하지 않았다.

제안 흐름은 **넓은 목록·가격 점검 → 명시된 후보 필터 → 제한된 후보의 상세 자료·이력 확보 → 검증된 자료만 전략 평가**다. 순위 상위만 쓰면 전체 시장 전수 검토와 다르므로, 수집 제외/보류된 종목과 조회 범위를 기록한다. 구독 변경·끊김 때는 관측 신뢰 상태를 낮추고 새 진입을 보류한다. 없는 틱을 재구성해 체결·슬리피지를 확정하지 않는다.

현재 목록 CLI의 잠금은 같은 작업 폴더끼리만 조정하고 시세 CLI와 토큰/호출 예산을 공유하지 않는다. 후속에는 단일 인증 소유자·그룹별 예산·재시도 상한을 설계해야 한다. 앱의 조회 경로 제한과 토큰 자체의 조회 전용 권한은 다르며, 새 경로에도 계좌/주문/환전 및 주문 이벤트 구독을 넣지 않는다.

## 3. 비용·저장 조건: 확인된 것과 남은 것

브라우저에서 선택된 **2026-08-12 약관**과 펼친 수수료 FAQ를 다시 읽었다. [공식 약관](https://corp.tossinvest.com/ko/terms/v2?id=752), [공식 API FAQ](https://corp.tossinvest.com/ko/open-api).

- 확인: 개인 본인 매매 목적의 시세 이용과 제3자 제공/배포·상업 이용 제한, 체결 시 위탁수수료, 기존 수수료 적용 및 향후 변경 가능성. 회사의 거래기록 10년 보존은 고객의 시세 저장 권한과 다르다.
- 확인: 종목 목록의 일일 로컬 캐시는 공식 명세에서 권장한다. 이를 모든 시세의 장기 보관·재배포 허가로 확대하지 않는다.
- 미확인: 본인에게 별도 조회·시세 이용료/유료 신청이 없는지, 누적 시세를 장기간 저장·반복 검증할 때의 보관·삭제·재사용 조건. 공개 수수료 설명을 ‘조회가 영구 무료’라는 확약으로 처리하지 않는다.

[기존 문의 초안과 확인 경로](TOSS_CATALOG.md)를 유지한다. 이번에는 문의를 전송하거나 약관에 동의하지 않았고 `TOSS_CATALOG_TERMS_CONFIRMED`도 변경하지 않았다. 실자료를 외부 AI나 저장소에 전송할 권리 역시 승인된 것으로 보지 않는다.

## 4. 바로 다음 구현 단위와 완료 조건

**다음은 네트워크 없는 ‘실자료용 수신 형식·변환·격리 저장’ 기반이다.** 문서 형식에 맞춰 직접 만든 모형 응답을 사용해 연결 오류를 먼저 검사한다. 모형 응답을 실제 수신 기록으로 표시하지 않는다. 이 계획은 실제 수집이나 거래 기준 변경 승인이 아니다.

1. 출처/형식/명세 버전, 원천 시각·수신 시각·가용성, 종목 식별/통화/원시 가격, 정정 및 필수 정보의 UNKNOWN을 표현한다. 합성 입력과 실자료 관측 컨테이너를 구분하고 기존 TEST_ONLY 계약은 보존한다.
2. 목록·상세·가격/호가·봉·달력 응답을 순수 변환기로 분리한다. 수량/가격 소수 문자열, 시각 누락, 잘못된 최신 값, 거래소 식별 차이, 종목 봉/지표 봉의 시각 차이를 검사한다. 미확인 정지·기업행동을 ‘없음’으로 채우지 않는다.
3. 가짜 페이지 전송기로 커서 중복/상충/반복/역행/중간 실패·호출 예산을 시험한다. 원본 응답 근거와 정규화 결과를 새 격리 경로에 연결하되 사용자 DB/원본 정책을 덮어쓰지 않는다. 실제 원문 저장 방식은 권리·민감정보 보관 조건이 확정되기 전 활성화하지 않는다.
