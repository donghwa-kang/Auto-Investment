# 다종목 로컬 모의매매 대시보드

페이퍼랩은 합성 국내 또는 미국 2종목의 기존 다종목 엔진을 웹으로 조작하는 TEST_ONLY 도구입니다. 전체 시장 검색·실제 뉴스/AI·SOXL/SOXX 거래·실계좌·실주문은 연결하지 않습니다. 토스증권의 밝은 여백·숫자 중심 배치·파란색 주요 버튼을 참고한 독립 디자인이며 공식 서비스나 제휴가 아닙니다. 외부 로고·이미지·글꼴을 가져오지 않습니다.

## 실행

프로젝트 루트, 기존 [실행 환경](../README.md#실행-환경)과 의존성 설치가 필요합니다.

```powershell
npm run build
npm run portfolio:web
```

서버 출력의 `http://127.0.0.1:4184/?view=portfolio`로 접속하고 출력에 표시된 일회용 코드 파일을 사용합니다. 기본 파일은 `data/portfolio-web/local-pairing.txt`입니다. 5분/1회 유효하며 키·코드는 URL이나 일반 서버 로그에 넣지 않습니다. Windows ACL 또는 디스크 암호화를 보장하는 기능은 아닙니다.

`PORTFOLIO_WEB_ROOT`(기본 `data/portfolio-web`)와 `PORTFOLIO_WEB_PORT`(기본 `4184`)는 선택 설정입니다. `.env`를 자동으로 읽지 않으며 PowerShell 프로세스 환경변수로 설정합니다. 예를 들어 ` $env:PORTFOLIO_WEB_ROOT = 'data/my-paper-web' ` 설정 후 실행할 수 있습니다. 사용자 API 키가 필요하지 않습니다. `TRADING_MODE=LIVE` 또는 `LIVE_ENABLED=true`면 시작을 거절합니다. 초기화·삭제 명령은 없습니다.

기존 `npm start`의 `data/paper.sqlite`·`data/local-pairing.txt`·`paper_session`과 분리합니다. 다종목 서버는 전용 폴더의 `legacy.sqlite`와 `portfolio_session`을 사용합니다. 단일 종목 실험 링크는 새 서버의 별도 legacy 실험이지 기존 사용자의 실행을 옮기는 기능이 아닙니다. 두 화면은 가상 자금도 공유하지 않습니다.

정상 확인: `/api/health`의 `mode=OFFLINE_ONLY`, `live=false`, 인증 전 `/api/portfolio`는 401. 준비 완료 후에도 재생 정지·신규 진입 중지 상태이며 주문/재생 위치는 0입니다.

## 기본 흐름

거래와 독립된 **Codex 분석 · 모형** 메뉴도 제공합니다. 고정 합성 예시 또는 [기록 전용 모의 실행](ANALYSIS_RECORDS.md)을 확인·승인한 뒤 모형 함수를 한 번 호출합니다. 실제 Codex/외부 전송은 없으며 웹 실험의 과거 기록을 소급 생성하지 않습니다. 전용 저장소는 `PORTFOLIO_WEB_ROOT/codex-analysis/mock.sqlite`, 원본 스냅샷은 그 옆 `sources/`입니다. 선택 설정 `PORTFOLIO_RECORDS_ROOT`는 기본 `data/paper-learning-runs`의 합성 기록 전용 폴더를 가리킵니다. [사용법·승인/복구·검증 한계](CODEX_ANALYSIS_MOCK.md)를 참고하세요.

현재 시작 경로는 [제한된 별도 모형 프로세스](ANALYSIS_MOCK_PROCESS.md)를 사용하며 위 폴더의 `executions/<UUID>/`에 고정 코드와 실행 메타데이터를 보관합니다. Windows·Node 24.20.0 또는 빌드/저장소/정책 확인 실패 시 분석만 비활성화합니다. 기존 함수/실제 Codex로 자동 전환하지 않으며 실행 중인 구버전 서버도 자동 교체하지 않습니다. 이 분리는 악성 코드용 OS 샌드박스가 아닙니다.

1. 새 모의 실험에서 총 가상 운용금(정수 원, 1~5,000,000), 그중 달러 배정 원화액(최대 40%), 기존 하/중/상·PILOT/STANDARD를 선택합니다. 초기 배정 후 해당 실행에서 자금·위험도를 바꾸거나 손실을 초기화하지 않습니다.
2. KR 또는 US의 **합성 2종목 B/P 시나리오**를 선택합니다. 기본 예측은 `MISSING_PROFILE`로 주문 보류입니다. 사용자가 선택할 때만 `TEST_ONLY` 합성 예측으로 모의 주문 경로를 시험합니다. 낮은 자금·한도에서 최소 1주가 불가능하면 승인하지 않습니다.
3. 시험용 가격·비용·체결·처리 순서·예정 청산의 합성 가정을 확인한 뒤 생성합니다. 120개 완료 세션 이력을 새 폴더에 생성하고 원본 정책·이력·신호를 worker에서 재검사합니다. 준비 중 HTTP 응답은 유지하며 자동 시작하지 않습니다.
4. 모의 거래 시작을 누르면 실제 1초당 **명령 1개**를 재생합니다. 가상 시각은 화면에 따로 표시하며 실제 오늘 시장이 아닙니다. 두 평가 시점 사이에는 노출이 없을 때만 시각을 건너뛰고, 노출 중 공백은 기존 엔진이 차단합니다.
5. 판단 근거에서 승인/보류·개별 조건·입력값·스냅샷을, 주문·보유에서 부분 체결·보호·귀속·남은 수량을 확인합니다. 화면에 아직 재생하지 않은 미래 신호나 가격을 공개하지 않습니다.

샘플 명령에는 각 시점의 예정 청산과 다음 평가 재개가 들어 있습니다. 이는 실제 시장의 매도 전략이나 투자 추천이 아닌 기존 시험 절차입니다. 사용자가 신규 진입을 중지하면 예정 재개가 이를 무시하지 않습니다. 새 실행마다 독립 자금이며 여러 실행의 잔고를 실제 계좌의 합계로 해석하지 않습니다.

## 중지·청산·복구

| 버튼/상태 | 실제 의미 |
| --- | --- |
| 신규 매수 중지 | 신규 진입 금지·기존 매수 취소 요청. 재생 중이면 남은 호가로 보호/청산 처리 계속 |
| 재생 정지 | 신규 진입 중지와 가상 시계 정지. **보유분 청산 아님, 보호 처리도 중지**. 확인 창 제공 |
| 보호 처리 계속 | 신규 진입은 막은 채 남은 합성 시나리오 재생. 복구 중 취소 결과를 처리하는 용도 |
| 장부 대조 | UNKNOWN/미체결 매수·불변식 대조. 실패는 자동 정상화하지 않으며 성공해도 시작하지 않음 |
| 명시적 매매 재개 | 대조·보호·예약·래치 검사 후 진입/재생 허용. 손실 래치를 초기화하지 않음 |
| 프로그램 보유분 청산 | 해당 실행의 BOT 보유분에 청산 의도 저장 후 남은 호가 재생. 확인 창 제공. 요청 ≠ 완료 |
| 재생 종료 | 입력 명령을 모두 처리했다는 뜻. **보유 0·미체결 0**인지 별도 표시. 잔여 노출이 있으면 자료 부족/미해결 |

브라우저 닫기·새로고침은 서버 재생을 중지하지 않습니다. 연결이 끊겨도 마지막 잔고를 현재 값이라고 표시하지 않고 조작을 차단합니다. 명령 응답이 유실되면 같은 요청 ID로 재확인하며 중복 자금 배정/주문을 하지 않습니다.

서버를 종료할 때는 터미널 Ctrl+C 또는 같은 서버의 단일 종목 화면에 있는 저장 후 엔진 종료를 사용합니다. 종료는 청산이 아닙니다. 정상 종료 시 신규 진입/재생 중지 의도를 저장하며 강제 종료·종료 저장 실패는 다음 열기에서 대조가 필요합니다.

서버 재시작 후 실행 기록 → 기존 기록 열기·복구 검사 → 필요 시 보호 처리 계속 → 재생 정지 → 장부 대조 → 명시적 재개 순서입니다. 복구 시 writer epoch를 새로 발급하고 대조 완료 epoch는 초기화하므로 중지 버튼을 눌러도 대조 절차를 우회하지 못합니다. 원래 HTTP 시작 요청 재전송도 자동 재개하지 않습니다.

## 저장·API 경계

`runs/<UUID>/`에 `request.json`, 원시 이력 3개, `replay.json`, `plan.json`, `paper.sqlite` 및 WAL/SHM을 기록합니다. 입력 파일은 최초 생성 때만 씁니다. 재생 명령·입력·정책 해시와 DB 체크포인트를 연결하고, 명령 ID·매매 상태·다음 재생 위치를 같은 SQLite 트랜잭션으로 저장합니다. 1개 활성 worker와 기존 DB writer lease를 사용합니다. 실행 중·잔여 보유/미체결이 있을 때 다른 실행을 열거나 새로 생성하지 않습니다. 최대 20개 실행이며 자동 정리·삭제는 없습니다.

인증된 `GET /api/portfolio`는 실행 목록·현재 상태를, `POST /api/portfolio`는 엄격한 `create/open/control` 계약을 제공합니다. POST에는 동일 Origin·Host·세션·CSRF가 필요합니다. 예시 ID는 실제 UUID로 대체합니다. 서버 생성 실행 ID만 허용하며 임의 파일 경로·시세·tick·실주문·설정 변경을 받지 않습니다. 모든 금액·위험 심사는 서버에서 수행합니다.

상태/입력 손상, 읽을 수 없는 실행, 중복 ID에 다른 입력, writer 충돌은 성공으로 표시하지 않습니다. 오류 화면에서 같은 실행을 다시 열어 검사할 수 있지만 UNKNOWN·손상 파일·원시 이력 생성 중단의 자동 수리 기능은 없습니다. 실패한 자료는 보존합니다. 새로고침/다른 실험 생성으로 오류 상태를 해제했다고 간주하지 마세요.

## 검사와 한계

```powershell
node work/verify-portfolio-web.mjs
```

현재 설치에서 타입·린트·형식·빌드, 명시적으로 열거한 관련 단위/통합/강제 종료 검사, 기존+새 웹 E2E, 원본 해시를 실행하고 `work/portfolio-web-verification/<시각>/report.json`에 명령/결과를 남깁니다. 실제 실행 결과와 실패 이력은 [PROGRESS · 공개 요약](PROJECT_STATUS.md)에 구분합니다. 시험 서버는 임시/격리 DB를 쓰고, 네트워크 시나리오는 로컬 요청 실패를 주입합니다. 실제 인터넷/거래소 장애 시험은 아닙니다.

실제 수익성·시장 수집·뉴스/테마 선정·SOXL/SOXX 실행·실제 체결/슬리피지·실시간 SLA·장기 운영·계좌 자격·실주문은 미검증/미구현입니다. 다일 보유·배당·기업행동 후 자동 대조/해제, 사용자 자료 업로드, CLI DB 마이그레이션, 실행 간 실제 계좌 통합도 없습니다. 실제 전원/디스크/OS ACL·백업 매체 복원·새 PC 설치·모든 브라우저·200% 텍스트 확대·스크린리더 전수 감사·전체 제품 회귀를 이 제한적 시험으로 보장하지 않습니다. 원본 위험 수치·전략 기준을 변경하지 않습니다.
