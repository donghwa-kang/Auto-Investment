# 운영비 첫 통합의 선택안과 인수 조건 — D5

2026-09-25 · DEV-D03 내부 결정 준비 기록 · **후속 U08-A/U06-A 승인, D6 부분 구현**

후속 결정: 직전 U08-A/U06-A 권장 조합에 대한 사용자의 “그렇게 진행해줘”를 이 첫 범위의 승인으로 기록한다. [D6 공통 장부](COST_OPERATING_LEDGER.md)에서 의무·예약·지급·원자 재생 및 최소 HOLD를 연결했다. 마감/최종 배분·손실 재판정은 후속이며 OC-U01/02/03/04/05/07은 미결정이다. 아래의 “현재/선택 전/미실행” 표기는 **D5 작성 당시 기록**으로 보존하며 최신 구현 상태는 D6와 PROGRESS를 따른다. 원본 정책 파일과 구형 계약은 변경하지 않는다.

이 문서는 OC-U08(첫 통합 범위)과 OC-U06(배분 확정·연속손실)의 선택 자료다. 현재 코드 동작, 원본의 필수 규칙, 새 제안을 구별한다. **문서 작성·검토 완료는 정책 채택이나 기능 구현 완료가 아니다.** 두 항목을 포함한 OC-U01~08은 아직 UNRESOLVED다. 원본 정책·제품 코드·시험·기존 실행/DB는 변경하지 않는다.

권장 조합은 **U08-A: 원화·새 합성 실행·1위험일부터 통합**과 **U06-A: 비용 미확정 청산 후 신규 진입 보류**다. 후자는 첫 청산 이후 그 위험일의 나머지 신규 진입까지 막을 수 있는 보수적인 선택이다. 수익성 우위를 입증한 제안이 아니다. API 키·실제 구독 비용은 이 결정 단계에 필요 없다.

## 🔒 선택과 무관하게 보존할 원본 규칙

아래는 새 제안이 아니라 [원본 v2.3](../outputs/AI_TRADING_GUIDE_v2.3.md)의 2~4절·8~9절·19절·21.3절 및 [운영비 명세](investment-data-contract-v1/OPERATING_COST_SPEC.md)의 제약이다.

- 발생 의무는 비용 ID로 한 번만 인식한다. 이용 가능해진 미지급 의무는 채무와 계좌 순자산 E에 반영하며, 보고 마감까지 비용 인식을 미루지 않는다. 지급은 현금·채무의 동시 감소이지 두 번째 비용이 아니다.
- 보고 배분은 기간 발생 비용 O를 설명용으로 귀속한다. 완료 거래 N>0이면 정수 나눗셈과 안정적인 거래 ID 순서의 나머지 배분으로 합계 O를 보존한다. N=0이면 O 전부 미배분으로 남고 계좌·기간 손익에서는 빠지지 않는다.
- 비용 차감 후 완료 거래가 2회 연속 손실이면 해당 위험일 신규 진입을 중지한다. 순손익 0은 연속손실을 초기화하지 않는다. 미확정을 0이나 승리로 바꾸지 않는다.
- 가격 위험 R0, 손절 거래비 C_stop, 운영비를 분리한다. 고정 운영비를 손절 위험에 다시 더하지 않는다. 기존 2배 초과 손실·보호 사고 중지와 재진입 제한을 배분 때문에 완화하지 않는다.
- 후보의 운영비 **추정**과 사후의 **확정 배분**은 다르다. 완료20위험일 창·N=0의 승인 D·미확인 자료 HOLD·월 지출 한도는 그대로다. 이번 1위험일 통합 제안을 추정창 축소로 해석하지 않는다.
- 발생 시각과 이용 가능 시각을 보존한다. 미래에 알게 된 비용으로 과거 판단을 다시 쓴 것처럼 만들지 않는다. 구형 정책 해시·실행·학습 자료는 원래 의미로 유지한다.
- 이전 기간에 중지되어야 했던 늦은 손실이 확인되면 현재 계좌도 검토 중지한다. OC-U07의 상세 귀속/재생이 미정이라는 이유로 이 원본 중지 원칙을 무효화하지 않는다. 날짜·모드·입력금 변경만으로 저장된 중지 사유를 없애지 않는다.

### U08-A를 고르면 승인할 구체적 경계

1. 기존 저장/비용 커널을 재사용하는 **새 명시 합성 계약**을 설계한다. 정책 원본 해시와 별도의 승인된 통합 계약 해시를 함께 남긴다. V1/V2/V3의 기존 의미를 자동 변경하지 않는다. 버전명·API 이름은 구현 때 정하며 현재 존재하는 것처럼 표시하지 않는다.
2. 통합 현금의 초기 원천은 하나다. 기존 보조장부의 전체 잔액을 합산하지 않고 비용 사건의 효과를 공통 장부에 한 번만 반영한다. 매매/운영비 예약 간 가용 현금 경쟁도 검사한다.
3. 비용 ID·채무·관련 예약 상계·현금 효과·위험/보류·감사 기록은 동일 writer/epoch/lease 및 단일 COMMIT 경계에서 저장한다. 같은 사건의 재수신은 무효과, 같은 ID의 다른 내용은 충돌 보류다. 별도 파일 저장 후 나중 합산은 확정 장부 경로로 쓰지 않는다.
4. 시험기간은 KST 09:00부터 다음 09:00 직전까지의 반열린 **1위험일**이다. 장 운영시간을 24시간으로 늘리거나 전략의 기존 최대 보유시간을 바꾸지 않는다. 시각 경계를 넘었다는 이유로 미해결 주문·노출·채무를 지우거나 자동 청산하지 않는다.
5. 완전한 합성 원자료와 독립 기대값을 갖춘 새 실행만 대상으로 한다. 실제 청구 내역·공유 구독 귀속·환불·정정·늦은 비용·외화·다일 이월은 이 단계에서 지원하지 않는다. 사전 입력이면 명시 거절/HOLD, 실행 중 지원 불가 사건이면 원시 근거와 기존 노출을 보존하고 신규 위험 확대·손익 확정을 보류한다. 지원 불가 사건을 조용히 버리지 않는다.
6. 실거래·새 지출·학습·모델 활성화·앱 자동 전환은 false로 유지한다. 실제 데이터로 확장하기 전에는 미지원 사건의 보존/복구 계약을 별도로 인수해야 한다.

**국내 원화부터 검증한다는 개발 순서일 뿐, 미국 시장이나 SOXL/SOXX를 최종 대상에서 제외하거나 레버리지 금지 범위를 바꾸는 선택이 아니다.** 현재 미국 합성 기능도 삭제하지 않는다.

청산 때 거래비는 알아도 그 위험일의 최종 운영비 O와 완료 거래 N은 아직 모를 수 있다. 최종 순손익에 따라 연속손실 횟수가 달라지므로 단순히 화면 손익만 나중 수정해서는 안 된다.

| 선택 | 미확정 청산 후 동작 | 이점 | 감수할 점 |

| **U06-A — 권장** | 해당 비용 적용 실행의 신규 진입·재진입을 보류하고, 최종 배분 이후 별도 최종 손익/연속손실을 재생 | 미확정 승리로 손실 횟수를 초기화하거나 추가 위험을 만드는 경로를 차단 | 첫 청산부터 마감까지 거래 기회 감소. 일일 배분이면 남은 위험일 내내 보류될 수 있음 |
| U06-B | 다른 가드가 허용하면 잠정 거래비 손익 기준으로 신규 진입을 계속하고 나중 재판정 | 더 많은 진입 기회 | 나중 비용 반영 시 이미 2회 손실 뒤 추가 거래한 상태일 수 있음. 원본 중지 규칙의 충족을 보장 못하므로 첫 구현에는 권장하지 않으며 별도 정책 변경 검토 필요 |
| U06-C | 증명된 운영비 상한 등으로 손익 부호가 확실한 경우만 먼저 판정, 불명확하면 보류 | A보다 덜 보수적일 가능성 | 상한·분모·귀속 완전성을 별도로 증명해야 함. 단순 평균/예산값을 확정 비용으로 간주할 수 없음 |

### U06-A의 제안 상태 계약

아래 상태명은 설명용이며 아직 제품 상수·API가 아니다. 현재 V3 실행에 소급 적용하지 않는다.

| 시점 | 금융 사실·보고 | 신규 진입/보호 | 손실 판정 |
| --- | --- | --- | --- |
| 의무 자료 이용 가능 | 공통 장부에 비용·채무와 예약 상계를 한 번 반영 | E/가용 현금·기존 한도에 즉시 반영 | 청산하지 않은 포지션을 완료 손실로 만들지 않음 |
| 청산됐으나 운영비 배분 미확정 | 거래비 손익은 보존, **최종 운영비 포함 손익은 null** | 비용 확정 대기 HOLD. 기존 포지션 보호·청산·유효 체결 인식·취소/결제 처리는 계속 허용 | 해당 행의 최종 카운터 적용 대기. 잠정 양수로 횟수 초기화 금지 |
| 마감 검증 통과 | 확정 배분과 원본 근거·버전·가용시각을 함께 저장. 계좌 E를 재차감하지 않음 | 비용 대기 사유만 해소 가능. 다른 HOLD/HALT를 지우거나 자동 재시작하지 않음 | 기준 체크포인트에서 **원래 청산 순서**로 최종 손익을 한 번 재생. 음수 +1, 양수 초기화, 0 유지 |
| 불완전/상충/마감 뒤 새 비용 | 기존 근거/결과를 덮어쓰지 않음 | 지원 범위 밖임을 표시하고 신규 진입·확정 보류 | OC-U05/U07 계약 없이는 자동 재배분·과거 중지 해제 금지 |

청산 순서는 신뢰된 청산 시각과 동시각 사건 순번으로 고정한다. 나머지 1원 배분에 쓰는 거래 ID 정렬과 다르다. 순서 근거가 없으면 보류하며 임의 정렬로 연속손실을 만들지 않는다. 이미 카운터에 반영한 손실에 최종 손실을 다시 더하지 않는다. 기존 판정 기록은 보존하고 새 비용 계약의 최종 판정과 분리한다.

기존에 발동한 손실/보호 중지는 유지한다. 운영비 확정 대기를 이유로 거래비만으로 확인되는 기존 2배 초과 손실·보호 사고 대응을 늦추지 않는다. **보고 배분 운영비를 C_stop이나 기존 2배 초과 손절 손실 검사에 다시 더하는 변경은 이 제안에 없다.** 계좌 E의 실제 운영비 손실 반영과 비용 차감 최종 손익의 연속손실 판정은 별도로 보존한다.

마감은 위험일 종료 시각 이후이므로 그 결과를 전날 이미 알았던 것처럼 기록하지 않는다. 원래 위험일의 결과·중지 근거와 실제 확정 가용시각을 함께 남긴다. 확정 결과 과거 위험일의 중지 조건 위반이 드러나면 현재의 검토 중지도 유지한다. U08-A에서는 다음 위험일 자동 재개·카운터 이월/초기화를 지원하지 않으며, 새 실행을 만드는 것이 미해결 위험의 리셋 수단이 되어서는 안 된다. 다일 전환은 U08-B의 별도 인수 대상이다.

### 마감은 시간 경과나 `complete=true` 선언만으로 확정하지 않음

- `기간 끝 ≤ finalizedAt ≤ availableAt`과 전체 원자료의 조회 기준을 검증한다. 거래/비용의 누락 없음 근거, 정책·실행·자료 해시, 중복/상충과 합계를 독립 재생한다. 현재 fixture의 `complete=true`를 실제 공급자의 완전성 증거로 승격하지 않는다.
- 대상 기간에 걸친 거래는 수량 0이고 관련 주문이 모두 최종 상태여야 한다. 열린 거래·UNKNOWN·기간 걸침은 빼고 나머지만 성공 처리하지 않는다. U08-A에서는 전체 마감을 보류한다.
- 기간 말 이전 예약의 변환/해제가 모두 대조되어야 한다. 확정되지 않은 예약을 편의상 발생 비용으로 바꾸지 않는다.
- **발생액이 확인된 미지급 채무는 지급 전에도 비용 배분할 수 있다.** 모든 지급/결제를 기다려야 비용이 확정되는 것은 아니다. 이후 지급은 같은 비용을 재배분하거나 연속손실을 재적용하지 않는다.
- 환불·정정·외화·늦은 자료 등 이번 범위 밖 근거가 있으면 확정하지 않는다. 합성 원자료를 갖춘 마감 검증이 실제 공급원 누락·지연 해결을 입증하지는 않는다.

## 🧮 금액·판정 대조 예시

실제 청구나 수익성 결과가 아닌 설명용 정수 사례다. 이 표의 산술과 아래의 **미구현 통합 인수 시험**은 구별한다.

| 사례 | 기대 결과 | 막아야 할 오류 |
| --- | --- | --- |
| 초기 현금 1,000원, 의무 50원 인식→지급 | 인식 직후 현금 1,000/채무 50/E 950, 지급 뒤 현금 950/채무 0/E 950 | E를 900으로 이중 차감하거나 두 초기 현금을 합쳐 2,000으로 시작 |
| 운영비 O=10, 완료 N=3, ID a,b,c | a=4, b=3, c=3, 합계10 | 후보 추정 올림값 4를 모두 배분해12로 인식 |
| 이미 보유한 2거래가 거래비 차감 뒤 각각 +2, 최종 O=6/N=2 | 각 운영비3, 최종 -1/-1. 최초 횟수0이면 최종 연속손실2 | 잠정 +2를 확정 승리로 간주, 나중 2를 기존 2에 다시 더함 |
| 완료 거래0, 운영비10 | 거래별 배분0/미배분10. 계좌 E에는10 반영 | 가짜 완료 손실을 만들거나 무거래 비용을 숨김 |

세 번째 사례의 2거래는 첫 청산 전에 이미 보유한 거래들이다. U06-A의 신규 진입 HOLD를 뚫고 두 번째 거래를 새로 열었다는 가정이 아니다. 최종 결과가 불리하게 바뀌어도 실제로 하지 않은 주문·중지를 과거 이력에 합성하지 않는다.

승인 예시: **“U08-A와 U06-A로 진행해. 첫 청산 후 비용 확정까지 신규 진입이 보류될 수 있다는 점도 동의해.”** 이 문장은 복사 가능한 선택 예시이며 현재 승인 기록이 아니다. 일반적인 문서 검토 요청이나 무응답을 위 선택의 승인으로 바꾸지 않는다.

선택 후 다음 한 작업은 **새 합성 KRW 공통 장부의 운영비 의무·예약·지급 연결과 원자 저장/재생 검증**이다. 먼저 OI-01~03 및 필요한 미지원/레거시 경계를 인수한다. OI-04~10과 확정 손실 판정은 후속 연결 전까지 미완료/HOLD로 둔다. 새 조건이 필요하면 승인된 범위와 대조한 뒤 요청한다.

후속 승인 시 U06/U08의 **이 첫 범위에 한정한 결정**을 별도 기록한다. 원본 파일이나 기존 미결정 목록의 역사를 덮어쓰지 않으며, 범위 밖 세부사항까지 전부 해결됐다고 표시하지 않는다. 실제 API 키·이용료·자료 저장 허용은 실자료 단계에서 별도로 요청한다.

이번 D5의 실행 검사·문서 표시·원본/제품 보존 근거와 진행률은 [PROGRESS · 공개 요약](PROJECT_STATUS.md)를 따른다. `markdown-mermaid-writing` 방식에 따라 현재 사실·제안 선택·미실행 인수 조건을 분리했다. 설계 문서 작성은 자동매매의 안전성이나 수익성 인증이 아니다.
