# 1차 검증 보고서

대상: Windows 로컬 오프라인 합성 모의매매 앱. 원본 정책·실계좌·유료 AI·실주문을 변경/연결하지 않았다.

이 문서는 최초 1차 검증 당시의 기록이다. 이후 사용자 요청에 따른 SOXL 후보 범위 정정은 [별도 문서](PHASE2_SCOPE_20260911.md)를 따른다. 아래 과거 '감시 전용' 설명과 108개 전체 검사 결과를 후속 변경의 현재 정책/새 실행 결과로 혼동하지 않는다.

## 실행 증거

최종 검사는 report.json (로컬 비공개 기록: `work/phase1-verification/report.json`)에 명령·종료 코드·시간·원본 파일별 SHA-256 보존 결과를 기록한다. 해당 파일에 실패가 있다면 이 문서의 기능 설명만으로 검증 완료라고 판단하지 않는다. 브라우저 세부 결과는 browser-report.json (로컬 비공개 기록: `test-results/browser-report.json`)에 있다.

최종 실행: 2026-09-11, Windows x64 / Node.js 24.20.0 / npm 11.19.0. 마지막 코드 변경 후 아래 통합 명령 전체를 다시 실행했다.

| 실제 실행 | 결과와 범위 |
| --- | --- |
| `npm ci --ignore-scripts --no-fund` | 잠금 파일 기준 재설치 성공. 외부 데이터·금융·AI가 아니라 개발 의존성 설치 |
| `npm run verify` | 하위 검사 7개 명령 모두 종료 코드 0 |
| `npm run typecheck` / `npm run lint` / `npm run format:check` | 각각 성공. 런타임·수익성 검증과 별개 |
| `npm test` | 실제 구현 단위·통합 108개 통과, 실패·건너뜀 0. 약 131초 |
| `npm run build` | 서버 TypeScript 컴파일 및 Vite 웹 빌드 성공 |
| `npm run test:e2e` | Edge 브라우저 E2E 2개 통과, 실패 0. 데스크톱·모바일 PNG 직접 확인 |
| `npm run verify:originals` | 구현 시작 전 보존 대상 outputs/work 파일 37개 모두 SHA-256 일치 |
| `pwsh -NoProfile -File work/validate_policy_v2_3.ps1` | 기존 정책 정적 검사 248/248, 실패 0. 별도 결과 (로컬 비공개 기록: `work/phase1-verification/legacy-policy-result.json`) |
| `npm start` 및 `SHUTDOWN-01` | 실제 시작·health·로그인·초기 STOPPED/미배정/LIVE=false 확인. 자식 CLI의 인증된 종료는 종료 코드 0, 저장 장부·감사 확인 |

새 README/정책 대응표/이 보고서는 내부 링크 실재와 Markdown 변환을 검사하고 브라우저 렌더링 PNG를 직접 확인했다. 문서 검사 기록 (로컬 비공개 기록: `work/phase1-verification/document-check.json`)은 이번 새 문서만 대상으로 한다. GitHub 표시 또는 이전에 차단된 정책 문서의 화면을 검증했다는 뜻은 아니다. 제한적 민감정보 패턴 검색에서 이번 소스·시험·프로필·문서의 해당 패턴을 찾지 못했으며, 전체 비밀값/OS/Git 기록 감사는 수행하지 않았다.

이번 구현 중 실제로 찾고 수정한 문제:

- 즉석 TypeScript 실행기의 Windows 샌드박스 사용자 정보 조회 실패 → 사전 컴파일한 JS 실행으로 전환.
- 자료 준비 중 writer 임대 만료 → 거래/화면 처리와 독립된 주기적 임대 갱신.
- 선택 필드 undefined의 JSON 직렬화와 감사 해시 불일치 → 일관된 정규 직렬화.
- 위험도 하향의 취소 미확정 단계와 적용 완료 단계를 별도 검증.
- UI 검사에서 같은 한도 금액이 두 곳에 나타나는 선택자 충돌 → 해당 검사의 대상을 명확화.
- 의도 저장 후 어댑터 접수 전에 입력 변조/기한을 재검사하고, 여러 합성 초를 진행할 때도 tick마다 별도 커밋하도록 보강.
- 일부 tick만 처리된 명령의 재시도에서 원래 요청한 진행 초를 바꾸지 못하도록 최초 명령 의도도 별도 저장.
- 시험 도구의 PTY Ctrl+C 전달 실패 → 인증된 저장 후 종료 경로를 추가하고 실제 CLI 자식 프로세스의 종료 코드 0과 `cleanShutdown=true`를 검사.
- 조사 예시의 상태와 주문 권한을 분리하고 실제 검토가 없으면 검토 시각을 null로 표시. SOXL은 감시 전용이며 연구 예시 노출을 주문 허가로 사용하지 않음.

## 검사 구분

실제 구현 시험: 자금/위험/경제성·시점/지표/B/P·DB 트랜잭션/소유권/감사·부분 체결/취소/청산·강제 종료/복구·웹 인증/보안·재현성. 시험 ID와 원본 요구의 연결은 [정책 대응표](POLICY_TRACEABILITY.md)에 있다.

별도 브라우저 시험: 1440px 데스크톱에서 입력→시험 자금 배정→B 모의 주문→보호→귀속 청산→각 화면→새로고침, 390px 모바일, 잘못된 자금/기본 예측 보류/연결 끊김 표시. 생성된 데스크톱 주문·모바일 현황 PNG를 직접 확인했다. 기존 정책 문서의 차단된 file:// 미리보기를 다시 열거나 우회한 것이 아니라 이번 localhost 앱을 검사한 것이다.

이전 정책 산식/고정 스키마 검사와 실제 거래 엔진 검사를 구분한다. 테스트가 종료 코드 0이어도 실제 전략 수익성이나 실거래 운영 승격 조건을 충족한 것은 아니다.

합성 원천 자료는 `src/core/fixture.ts`의 고정 규칙으로 만든 121개 세션(과거 120개와 현재 1개), 가상 종목·벤치마크의 1분봉이다. 실제 주가나 뉴스 데이터는 다운로드하지 않았다. 별도 [TEST_ONLY 가정](POLICY_TRACEABILITY.md#시험-전용-가정)을 사용하며 기본 예측 제공기는 자료 없음으로 주문을 보류한다.

동시 후보 검사는 `RESERVE-02`에서 실제 엔진 결정 함수를 서로 다른 두 후보로 호출하고 메모리 SQLite 트랜잭션을 통해 첫 예약 후 두 번째 후보를 거절하는지 확인한다. 단일 프로세스에서 직렬화하는 검사이며, 복수 DB 연결의 writer 소유권 검사는 별도다. UI가 다종목 전체 시장을 탐색하거나 다중 프로세스 후보 부하를 검증했다는 뜻은 아니다. 외부 호출 검사는 전송 함수 감시와 구현 소스의 전송 경로 점검 범위이며 OS 방화벽 격리 검증은 아니다.

## 성능 측정

최종 빌드 후 `node scripts/benchmark.mjs`를 실행했다. 원시 결과 (로컬 비공개 기록: `work/phase1-verification/performance.json`): 파일 SQLite WAL / synchronous=FULL, 생성 원천 94,380개 1분봉, 초기 판단의 완료 입력 93,690개, 121개 합성 세션, 한 PC의 100회 tick 명령 측정이다.

- 초기 자료 준비 약 7.97초.
- tick 명령 평균 6.84ms, p95 12.75ms, 최대 21.23ms. 의도·상태 DB 커밋을 포함하지만 실제 네트워크 지연은 없음.
- 측정 종료 시 부모 프로세스 RSS 278,200,320바이트. 최고 메모리나 worker를 포함한 전체 사용량 측정은 아님.
- 종료 시 모의 BOT 보유 4주가 남았음을 기록하며, 강제로 평가손익을 확정하거나 전량 청산 결과로 바꾸지 않음.

콜드 자료 준비를 worker로 분리하고 버전별 집계 캐시를 사용한다. 후속 다종목 구현에서는 후보 수·자료 크기별 메모리/지연·큐 적체와 캐시 무효화를 별도로 측정해야 한다. 이 수치는 실시간 SLA·실거래 처리량·투자 성과 보증이 아니다.

## 미검증·제약

- 실제 시장 자료 백테스트·OOS·봉인/부트스트랩 성과·60일 전향 모의·예측 보정·AI 추가 가치·실제 기관 수급/기업 실사.
- 계좌 자격·증권사 인증/주문/조건주문/OCO/실체결·실시간 장애 복구·환전·세금 산출.
- 하드웨어 전원 차단·실제 디스크 포화·사용자 백업 매체 복원·OS ACL 격리·대규모 장기 가동·다중 사용자 보안.
- UNKNOWN의 증거 기반 해소, 위험/보호 사고 래치 해제 승인 UI, 실제 전체 계좌 청산은 제공하지 않는다.
- 실제 다종목/두 시장 동시 scanner와 순위/상관행렬의 통합 성능은 검사하지 않았다. 첫 앱의 진입 경로는 합성 종목 1개다.

이 항목들은 성공값으로 채우거나 원본 검증 플래그를 true로 바꾸지 않는다. 프로그램의 한계와 다음 승인 단계에서 해야 할 일을 명시한 것이다.
