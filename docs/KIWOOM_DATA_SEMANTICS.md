# 키움 데이터 의미와 수집 조건 확인 기록

_2026-09-21 · 공개 근거 대조 및 오프라인 보완 · 외부 확인은 미완료_

## 📋 결정과 범위

문서에 적힌 **문자열 형식**, 금융 데이터의 **실제 의미**, 사용자의 **이용 권한**을 분리한다. 확인된 형식만 변환하고 시간대·봉 경계·가격 보정이 불명확하면 거래 입력으로 승인하지 않는다. [오프라인 어댑터](KIWOOM_OFFLINE_INGEST.md)의 정상 결과도 `MOCK_FORMAT_PARSED_SEMANTICS_HOLD`다.

대안은 추정으로 정규화하기, 형식 검사도 중지하기, 형식 검사를 계속하되 의미 판정을 보류하기다. 마지막 방식을 유지한다. 개발을 계속할 수 있지만 실제 과거 자료 재생과 거래 적격 판정은 아직 할 수 없다. 원본 전략·위험 수치나 실수집/주문 승인 범위를 바꾸는 결정이 아니다.

공개 명세·공식 예제·서비스 소개만 읽었다. 계좌·API 키·금융 자료 API·인증·실주문·유료 AI는 사용하지 않았다. SDK 설치나 공식 예제 실행도 하지 않았다. 로컬 시험 값은 자체 합성 자료다.

## 📚 확인된 사실과 남은 의미

기준은 공식 저장소의 고정 커밋 `953e5dbff123f437ab4d11a78a95191a685eb51f`다. 명세 바이트의 SHA-256 `42a7b3912c9d9588c83bdc2db7779c8d2e038703a2b5562e54ef46ae905cba79`가 이전 확인값과 일치했다. 조회일은 문서 개정일이나 서버 호환성 보증일이 아니다.[^1]

| 항목 | 이번에 재확인한 범위 | 미확인 및 처리 |
| --- | --- | --- |
| KR/US 분봉 시각 | `cntr_tm`은 `YYYYMMDDHHmmss`[^1] | 시간대, 봉 시작/끝, 확정 시각, 세션 포함 범위 미확인. `eventAt=null` |
| 분봉 초 정렬 | 위 형식에 초 자리가 있음[^1] | 항상00초라는 근거 미확보. 유효한37초를 형식 오류로 단정하지 않음 |
| KR 호가 시각 | `bid_req_base_tm` 설명과 예시의 날짜/시간 형태가 상충[^1] | 형식 정밀도만 기록. 수신일·자정·시간대 보충 금지 |
| US 호가 시각 | `dt` 날짜와 `bid_tm` 분 단위 표시[^1] | 초 정밀도·시간대 미확인. 원본2초 신선도 승인 불가 |
| 부호와 단위 | KR 가격은 원·부호 포함, KR 거래량/호가 잔량은 주. US 호가는 USD·부호 포함/잔량 주[^1] | 부호가 상승/하락을 뜻하는지까지 확정하지 않음. 절댓값은 모형 숫자 변환일 뿐 |
| KR 수정주가 | `upd_stkpc_tp`의0/1 선택은 있으나 해당 설명은 값만 나열[^1][^2] | 0의 상세 의미·기업행동 조정 범위·과거 정정 미확인 |
| US 수정/환율 옵션 | 요청의 수정주가·환율 옵션 모두0 미적용/1 적용으로 설명[^1][^3] | 응답 수정비율 의미·거래량 조정·당시 가격 재현을 증명하지 않음 |
| US 분봉 거래량 | `usa06011.trde_qty` 설명에서 단위를 확정하지 못함[^1] | 별도 호가 TR의 주 단위를 옮겨 쓰지 않음. `US_VOLUME_UNIT_UNVERIFIED` 유지 |

공식 예제4개도 필드 명칭/요청 값을 대조하는 데만 사용했다. 공식 예제의 기본 환율 옵션과 이 프로젝트의 명시값은 다를 수 있다. 예제 기본값을 가져와 기존 요청의0을1로 바꾸지 않았다. 예제 코드가 동작한다는 사실만으로 시간대·수정 의미가 확정되는 것은 아니다.[^2][^3][^4][^5]

사용자가 전달한 공식 API 안내 URL도 추가 확인했다. 이번 웹 도구로 읽은 기본 화면에는 KR/US 자료 카테고리와 토큰 발급 규격이 있었으며, 개별4개 TR의 의미 대조는 위 고정 명세와 공식 예제로 수행했다. 안내 사이트를 전달받은 것을 저장/요금 확인 답변이나 약관 동의로 해석하지 않는다.[^11]

## 🔧 이번 코드 보완과 검증 범위

[변환 코드](../src/core/kiwoom-ingest.ts)의 시각 검사는 원래 날짜·시각 형식만 확인하는 경계다. 그런데 분봉에 `endsWith("00")`를 추가 적용해 형식과 봉 정렬 의미를 혼합하고 있었다. 초가37인 KR/US 합성 반례로 기존 동작을 재현하고, 유효한 초 값은 원형대로 보존하도록 수정했다. 60초·존재하지 않는 날짜·잘못된 시/분은 여전히 오류다.

관측에 추가한 `sourceTimePrecision`은 문자열이 표현하는 최소 단위다. 아래 표는 브로커 시계의 정확도나 시세 지연 측정값이 아니다.

| 모형 필드 형태 | 보고 값 | 여전히 승인하지 않는 것 |
| --- | --- | --- |
| 유효한 KR/US 분봉 날짜+초 | `SECOND` | 시간대·봉 정렬·완료 여부 |
| 유효한 KR 호가6자리 시각 | `SECOND` | 실제 날짜·시간대 |
| 유효한 KR 호가8자리 날짜 | `DAY` | 자정으로의 보충 |
| 유효한 US 호가 날짜+분 | `MINUTE` | 초 보충·2초 신선도 |
| 잘못된 날짜/시각 또는 행 | `null` | 어떠한 시각 적격성도 없음 |

항상 `eventAt=null`이며 `realDataReady`, `strategyReady`, `paperOrdersEnabled`, `liveEnabled`는 false다. 초 정렬 추정을 없앤 것이 거래 위험 기준 완화는 아니다. 미국 DST 전환과 겹칠 수 있는 형태도 임의로 뉴욕 시각으로 해석하지 않는 반례를 추가했다. DST 변환기를 구현·검증한 것은 아니다.

추가 필드는 오프라인 보고서의 호환 가능한 확장이며 보고서 버전은 유지했다. 원래 JSON 전체의 해시는 새 필드를 포함하므로 이전 버전 보고서와 달라진다. 기존 파일/해시를 다시 쓰는 마이그레이션은 하지 않았다. UI·수집기·전략·학습 연결도 추가하지 않았다.

검사 명령은 프로젝트 루트에서 실행한다. 실제 실행 결과는 [진행 기록 · 공개 요약](PROJECT_STATUS.md)의 이 단계에 남긴다.

```powershell
npm run build:engine
node --test --test-concurrency=1 dist/runtime/tests/kiwoom-ingest.test.js
npm run verify:originals
```

## 🔐 이용 조건과 요청 예산

공식 소개는 HTS와 같은 매매 수수료 적용을 안내하지만, 이것을 사용자에게 적용되는 조회·저장 요금이0원이라는 근거로 쓰지 않는다. 이용안내는 신청 과정에서 약관을 확인하도록 안내한다. 공개 약관 목록을 확인했지만 이번 도구 조회에서는 해당 REST 서비스의 적용 약관 본문·개인 저장 허용 범위를 확정하지 못했다.[^6][^7][^8]

조회한 소개의 호출 제한은 KR 조회 초당5회, US 조회 일반5회/한국시간09–10시3회, 모의는 각 TR 초당1회다. 실시간 세션당200종목 안내도 있다. 계좌/토큰 단위와 추가 제한을 함께 적용해야 하며, 이 수치를 실제 호출 설정이나 승인으로 반영하지 않았다. 실행 전 최신 조건을 다시 확인해야 한다.[^6]

공식 소프트웨어 라이선스와 시장 데이터의 저장·이용권은 별개다. 공식 SDK/예제를 복사·설치·배포하지 않았고, API 필드 사실을 근거로 자체 코드를 보완했다.[^9] 모의 서버 시세도 실제 시장 값과 같다고 전제하지 않는다.[^10]

기존 [G1/G2 절차](investment-data-contract-v1/SOURCE_REGISTER.md)와 [자료 수용시험](investment-data-contract-v1/ACCEPTANCE_PLAN.md)을 유지한다. G1 전에 실제 표본을 요구하지 않는다. 첫 제한 수집의 시각 의미가 미확인이라도 권리·비용·범위가 별도 승인되면 격리된 진단 자료로 다룰 수 있지만, G2나 전략 입력으로 승격할 수는 없다. 사용하지 않는 외부 AI 전송·학습·재배포 권한을 첫 로컬 수집의 필수 조건으로 확대하지 않는다.

### 공급자 문의 초안 — 아직 전송하지 않음

아래 내용을 키움의 공식 문의 채널에서 확인할 수 있다. 키·토큰·계좌번호·주민번호는 답변 전달 자료에서 제외한다.

```text

최우선 호가를 제한적으로 조회하고, 로컬 저장·재생·백테스트하려 합니다.
외부 AI 전송·재배포·타인 계좌 운용은 이번 목적에 포함하지 않습니다.

1. 이 목적의 수신·로컬 보관·분석 허용 범위, 보관/삭제 조건 및
   별도 조회/시세/저장 요금과 적용 약관/공지 링크를 알려주세요.
2. ka10080/usa06011의 cntr_tm은 어떤 시간대이며 봉 시작, 봉 종료,
   마지막 체결 중 무엇입니까? 진행 중인 봉의 포함/확정·정정 기준과
   정규장/장전후 구분, 과거 제공 범위는 무엇입니까?
3. ka10004의 bid_req_base_tm은 날짜입니까, 시각입니까?
   usa20101의 dt/bid_tm 시간대와 초 단위 원천 시각을 제공하는
   읽기 TR 또는 WebSocket 필드가 있는지 알려주세요.
4. KR 가격/US 호가의 +/- 부호 의미, 수정주가 옵션과 응답 수정비율의
   기업행동별 적용 방식, 거래량 조정 여부를 알려주세요.

```

### 답변을 받은 뒤의 수용 조건

문의 답변만으로 실제 수집을 자동 실행하지 않는다. 적용 서비스/환경·TR·답변일·공식 원문 위치·유효 범위를 대조하고, 미답변 항목은 보류한다. 승인할 대상·기간·보관/삭제·총 호출/속도·최대 비용을 사용자와 별도로 정한다. 약관상 허용 여부와 프로그램 실행 승인은 서로 다르다.

필드 의미를 코드에 반영할 때는 의미별로 정상/반례를 추가한다. 시간대는 DST·거래일 경계, 봉은 시작/종료·미완료, 가격은 분할/정정·원시/조정 분리, 거래량은 단위·봉별/누적을 검증한다. 실제 표본 수용은 그 다음 별도 G2 시험이다.

## 📊 개선안 진행률과 다음 단계

이 단계는 공식 대조, 오프라인 보완, 문서/검증, 외부 확인의4항목으로 추적한다. 앞3개를 마쳐도 마지막이 미완료이면3/4=75%이며100%로 표시하지 않는다. 최신 실제 수치는 [PROGRESS.md · 공개 요약](PROJECT_STATUS.md)를 따른다.

누적 등록 작업 비율에는 이전 설계·문서·모형 시험도 포함되므로 전체 개선 로드맵 A–F의 완료율이나 실전 준비도가 아니다. A–F의 실자료·비용·다일 모의·독립 성과·AI/운용 종료 조건은 별도로 남는다. 이번 단위 테스트를 통과해도 실제 자료 수용/수익성·실계좌 적합성은 미검증이다.

다음 외부 의존 작업은 위 문의에 대한 근거 확보다. 답변 전에도 별도 승인 범위에서 주문 없는 수집기의 호출 예산·중단/재개 모형 같은 독립적인 오프라인 개발은 가능하다. 지금의 “진행”을 실제 연결·유료 이용·금융 약관 동의로 해석하지 않는다.
