# 실제 분석 연결 전 OS 격리 준비도 진단

현재 제공하는 것은 **읽기 전용 환경 조사와 연결 준비 진단**입니다. 환경 진단 CLI는 Codex를 실행하지 않으며 결과는 항상 `BLOCKED`입니다. 별도 개발 점검에서 설치된 Codex의 버전·도움말을 확인했지만, OS 격리 설정·실제 분석 연결은 하지 않았습니다. 모형의 승인을 실제 연결에 재사용할 수 없습니다. [기존 고정 모형 프로세스](ANALYSIS_MOCK_PROCESS.md)와 거래 엔진은 변경하지 않았습니다.

이후 [로컬 스키마 대조·더미 검사 도구](ANALYSIS_DUMMY_LAB.md)를 추가했습니다. 설치 버전의 읽기 제한 필드 차이를 보존하고 제한 없는 더미 파일 양성 대조/노출 감지를 시험합니다. 실제 OS 실행 어댑터·부모 전체 격리·인증/모델은 아직 없습니다. 후속 [부모 격리 결정·변경 명세](ANALYSIS_OUTER_BOUNDARY.md)는 LPAC 기반 오프라인 실험을 우선 후보로 정했으며 다음은 OS 변경 없는 실행기/명세 준비 구현입니다. 설정 분리·실제 Codex 기동은 미검증입니다. 아래 후보/계획/실행 범위는 각 작성 당시 기록입니다.

## 실행과 정상 확인

Windows, 기존 [Node/npm 설치 조건](../README.md#실행-환경)이 필요합니다. 새 패키지나 키·로그인은 필요 없습니다. 프로젝트 루트에서 실행합니다.

```powershell
npm run build:engine
node dist/runtime/src/server/analysis-isolation-cli.js
```

출력의 `reportPath`에 새 `work/analysis-isolation-reports/probe-.../report.json`이 생성됩니다. 기존 보고서를 덮어쓰거나 삭제하지 않습니다. 별도 인자·임의 실행 명령·업로드 경로는 받지 않습니다. 웹 메뉴와 연결된 기능은 아닙니다.

| 결과 | 의미 |
| --- | --- |
| 종료 코드 2, `status=BLOCKED` | 환경 자료 수집/검증 완료. 실제 연결은 허용하지 않음. 일부 조회가 UNKNOWN이어도 이 상태가 정상 결과 |
| 종료 코드 1 | 실행 불가·잘못된 인자/경로·시간 초과·오류 출력·형식 거절. 실제 연결 차단. 실행 전 실패는 보고서가 없을 수 있음 |
| `realCodexEnabled=false` | 이 도구에는 실제 모델 실행/승격 경로가 없음 |
| `osIsolationVerified=false` | 환경 정보일 뿐 실제 접근 차단 시험을 수행하지 않음 |

CLI는 기본 Windows PowerShell을 `-NoProfile -NonInteractive -File`로 호출합니다. 관리자 승격·ExecutionPolicy 변경/우회·설치는 하지 않습니다. 실행 정책/관리 정책으로 스크립트가 차단되면 우회하지 말고 그 결과를 미검증으로 남깁니다. 20초/출력 버퍼 32KiB 한도와 최종 JSON 16KiB 검증을 적용하며 stdout 전문이나 예외/인증값을 오류 보고서에 복사하지 않습니다.

검사 환경은 새 빈 cwd/TEMP/TMP와 SystemRoot/WINDIR만 명시 전달했습니다. 기존 홈·Codex 환경·키·토큰을 넘기거나 `CODEX_HOME`을 바꾸지 않았습니다. 각 정상 호출에도 **홈 경로를 찾지 못해 PATH 별칭을 생성하지 못했다는 경고**가 있었습니다. 해당 경고를 보존한 채 도움말 내용만 수용했고, 경고를 없애려고 홈 경로/인증/설정을 제공하지 않았습니다. 이는 파일·통신을 OS에서 추적하거나 차단한 시험이 아닙니다.

중간 실패도 보존합니다. 첫 검사는 이 경고 때문에 중단했습니다. 다음 검사에서 문서형 `sandbox windows --help`를 호출한 것은 잘못된 가정이었습니다. 로컬 구문상 `windows --help`는 실행 대상 인자로 해석될 수 있으며 실제 출력은 `Could not find home directory`, 종료 코드 1입니다. 이를 정상 도움말·접근 차단 통과로 계산하지 않습니다. 해당 호출은 최종 검사기에서 제거했습니다. 초기 보고서의 `sandboxPayloadIssued=false` 등은 의도를 기록한 잘못된 단정이므로 실행 부재의 증거로 사용하지 않습니다. 정정·관측 범위 (로컬 비공개 기록: `work/codex-cli-contract/assessment.json`)를 함께 확인하세요. OS 전체 프로세스/파일/네트워크 추적은 하지 않았으므로 내부 부작용이 전혀 없었다고 보장하지 않습니다.

재현 보조 스크립트 inspect-codex-cli.mjs (로컬 비공개 기록: `work/inspect-codex-cli.mjs`)는 이 PC에서 확인한 파일 경로/해시에 고정돼 있습니다. 임의 인자를 받지 않고 버전이 바뀌면 재검토를 요구합니다. 각 호출은 shell 없이 숨김 창·stdin 차단·10초/64KiB 한도로 수행합니다. 범용 설치 도구나 제품 런타임이 아니며 다른 PC에서 경로를 추측해 바꾸지 않습니다.

### 다음 단계의 명령 계약과 선행 조건

아래는 **실행하지 않은 인자 설계**입니다. 프로필·실험 폴더·허용 도구는 아직 생성/확정하지 않았으므로 복사 실행 명령을 제공하지 않습니다.

```text
executable: 확인 후 해시를 고정한 codex.exe
argv: ["sandbox", "--permission-profile", <검증된 전용 프로필명>,
       "--cd", <새 더미 시험 폴더의 절대 경로>,
       "--include-managed-config", "--", <고정 더미 도구의 절대 경로>, <고정 인자>]
```

정확한 실행 배열을 만들기 전에 이 버전의 스키마/권한 설정 계약, 설정을 읽는 범위, 관리 정책 우선순위, elevated 구현 선택 및 약한 모드 대체 금지, 허용 읽기/통신 범위를 확인해야 합니다. 위 `--` 구분과 옵션 조합의 실제 파싱도 아직 시험하지 않았습니다. 현재 사용자 설정이나 실행 중 앱의 sandbox-state를 가져다 재사용하지 않습니다. 도움말만으로 전체 App Server를 감싸는 격리 명령이 확정된 것은 아닙니다.

따라서 다음 개발 단위는 **버전별 스키마 대조와 전용 더미 검사 도구 준비**입니다. OS 사용자/ACL/방화벽 변경이 필요하면 정확한 대상·영향·복구 절차를 먼저 제시하고 승인받습니다. 실제 모델·인증·거래 자료는 계속 제외하며, 실제 OS 더미 시험도 아래 수용 기준과 별도 실행 범위를 충족해야 합니다.

## 방식 선정

현재 **Codex 네이티브 elevated 방식의 실효 경계를 우선 조사하는 것**을 설계 방향으로 정했습니다. 설치/설정 결정이나 Home에서 해당 버전의 모든 기능이 검증됐다는 뜻은 아닙니다.

| 방식 | 판단과 이유 |
| --- | --- |
| Microsoft Windows Sandbox | 공식 지원 목록에서 Home은 제외되므로 현재 후보에서 제외. 우회 설치나 Windows 구매/업그레이드는 하지 않음 |
| Codex 네이티브 elevated | 별도 낮은 권한 사용자·파일 권한·방화벽·로컬 정책을 사용하는 공식 방식. 실제 버전/구성/전체 접근 경계 확인이 필요 |
| Codex 네이티브 unelevated | 공식 문서상 네트워크 제한이 더 약함. 이번 프로젝트의 자동 대체 경로로 채택하지 않음 |
| WSL2 또는 별도 VM | 대안. 실행 파일만으로 준비됐다고 판단하지 않음. 기존 배포판·호스트 마운트·interop·통신 경계를 먼저 조사하고 별도 설치 승인이 필요 |

두 Windows Sandbox는 이름이 비슷하지만 같은 기능이 아닙니다. Microsoft VM형 제품의 Home 미지원이 Codex 네이티브 방식도 불가능하다는 뜻은 아닙니다. 근거는 [Microsoft Windows Sandbox](https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/)와 [OpenAI Windows 샌드박스](https://learn.chatgpt.com/docs/windows/windows-sandbox)입니다. 실제 채택은 아래 시험 통과 이후에만 확정합니다.

WSL의 자동 마운트를 끄는 것만으로 호스트 접근을 막았다고 판단하지 않습니다. 수동 마운트와 Windows 실행 연동을 따로 검토해야 합니다. 전역 `.wslconfig` 변경/WSL 전체 종료는 기존 배포판에 영향을 줄 수 있으므로 준비 과정에서 하지 않습니다. [Microsoft WSL 설정](https://learn.microsoft.com/en-us/windows/wsl/wsl-config).

## 적용해야 할 권한 경계

다음은 후속 구현의 설계 조건이며 아직 실제 OS에 적용하지 않았습니다.

1. **거래 호스트:** 장부·증권 관련 정보·원본 정책은 거래 측에 남습니다. 사용자 승인 시 만든 최소 JSON만 분석 경계를 넘어갑니다. 프로젝트/사용자 홈 전체를 분석 작업 폴더로 쓰지 않습니다.
2. **분석 제어 프로세스:** 전용 자료와 고정 실행 파일만 사용합니다. App Server 자체의 파일/API 접근과 모델이 요청한 도구/자식 프로세스의 접근을 따로 시험합니다. 도구 명령 하나의 제한을 전체 서버의 OS 격리로 확대해석하지 않습니다.
3. **입출력:** 승인 입력은 읽기 전용, 결과는 크기 제한된 통신 채널로 호스트가 검증 후 저장합니다. 필요 없는 파일·셸·브라우저·앱·MCP·플러그인·후크는 제공하지 않습니다. 실행 코드/권한/전송 범위가 바뀌면 새 승인입니다.
4. **통신:** 오프라인 시험은 모델 서비스도 호출하지 않습니다. 실제 연결 시 필요한 인증/모델 서비스 통신과 모델이 실행하는 도구의 통신을 구분합니다. 명령 통신 차단만으로 웹 검색·앱·MCP가 차단됐다고 판단하지 않습니다. 허용 목적지/리다이렉트/DNS/IPv4·IPv6/로컬 접근은 실제 버전에 맞춰 별도 확정합니다.
5. **중단:** 승인 취소·기한/사용량 초과·권한 확인 실패·부모 종료 시 소유 실행을 멈추고 늦은 결과를 폐기합니다. 조회 불가·시험 누락·설정 변경·더 약한 방식으로의 전환은 연결 차단입니다. 매매 엔진은 독립적으로 유지합니다.

공식 App Server의 `readOnly`는 접근 범위를 지정하지 않으면 광범위한 읽기 접근이 기본입니다. 이름만 보고 승인 자료 외 파일 읽기가 막힌 것으로 처리하지 않습니다. 또한 `externalSandbox`는 외부 격리가 이미 적용됐다는 전제의 모드이지 격리를 만들어주는 옵션이 아니므로 지금은 사용하지 않습니다. [App Server 문서](https://learn.chatgpt.com/docs/app-server).

명령용 네트워크 정책과 검색·앱·MCP의 경계가 다르다는 점은 [공식 설정 참조](https://learn.chatgpt.com/docs/config-file/config-reference)에 근거합니다. 실제 Codex 로그인 토큰을 추출/공유하거나 증권 키를 분석 환경에 복사하지 않습니다. 서비스 인증 주체와 모델/도구에 노출되는 자료의 분리도 후속 필수 조건입니다.

## 더미 검증 절차와 합격 조건

아래는 **준비된 시험 명세이지 이번에 실행한 OS 시험 결과가 아닙니다.** OS 설정과 시험 실행에 대한 별도 승인 뒤 적용합니다. 실제 키·사용자 장부 대신 새 시험 전용 폴더·가상 정책·작위적인 canary 값만 사용합니다.

| 검사 | 통과에 필요한 증거 |
| --- | --- |
| 허용 입력 읽기 | 같은 런타임/샌드박스에서 승인된 더미 입력의 정확한 해시를 읽을 수 있음 |
| 비허용 파일 읽기 | 존재/정상 읽기를 호스트에서 먼저 확인한 더미 비밀 파일을 분석 부모 API·도구·자식 모두 읽지 못함. 파일 없음은 차단 증거가 아님 |
| 장부·정책 쓰기 | 시험 복사본 수정·생성·삭제·이름 변경 거절 및 전후 해시 동일. 실제 사용자 파일은 시험 대상 아님 |
| 경로 우회 | 상위/절대 경로·junction·symlink·hardlink·교체 경합·공유 경로의 시험 표본을 접근 거절. 준비 실패는 SKIPPED/미검증 |
| 명령·하위 실행 | 허용한 고정 시험 도구 외 셸/자식·권한 상승·정책 변경 시도 거절. 시험 대상은 더미 명령이며 호스트 설정 변경 명령은 실행하지 않음 |
| 통신 | 소유한 시험 수신기의 양성 대조 후 제한된 실행의 TCP/UDP/DNS/HTTP·IPv4/IPv6 및 로컬 경로를 확인. 단순 연결 거절/시간 초과를 방화벽 차단 성공으로 처리하지 않음 |
| 비명령 도구 | 검색·브라우저·MCP·앱·후크·파일 API 등 각 진입점이 비활성 또는 동등한 경계로 제한됨을 확인 |
| 인증·환경 | 실제 인증 없이 더미 환경/canary로 불필요한 변수/파일/핸들이 전달되지 않음을 확인. 실제 인증 경계는 이후 별도 검사 |
| 수명·복구 | 소유 부모/자식 강제 종료·취소·재시작에서 잔류 실행/추가 전송/자동 재실행 없음. 기존 위험관리의 독립성 확인 |
| 증거 무효화 | 실행 파일/OS·권한 설정/자료·시험 도구 해시와 시각/결과를 결합. 변조·누락·버전 변경·수동 성공값은 통과로 수용하지 않음 |

양성 대조 실패, 포트 미준비, 기능 부재, 시험 중단은 격리 통과가 아닙니다. 일부 통과를 전체 통과로 올리지 않습니다. 네트워크 시험용 대상은 별도 승인된 소유 수신기만 사용하며 거래 API·외부 서비스·사용자 서버를 시험 대상으로 사용하지 않습니다. 검사자가 만든 성공 JSON을 신뢰하는 범용 `READY` 입력 기능은 제공하지 않습니다.

## 승인과 다음 실행 범위

이번에 수행하지 않은 항목은 다음처럼 나누어 승인받습니다.

- **버전/도움말 확인 완료:** 위 별도 검사로 설치 버전과 문서의 명령 규격 차이를 확인했습니다. 실효 설정/스키마 대조와 더미 검사 도구 준비가 다음 단계이며 임의 `setupStart`·기능 설치로 확대하지 않습니다.
- **필요한 경우 설정 승인:** 해당 버전이 요구하는 로컬 사용자/그룹·파일 ACL·방화벽·로그온 권한 등 정확한 변경 목록/대상/복구 영향을 먼저 제시. 관리자 UAC는 사용자가 승인하며 보안 기능을 전역 해제하지 않습니다. 기존 Codex 작업에 영향을 줄 수 있어 임의 설정 재사용/수정은 금지합니다.
- **실제 OS 더미 시험 승인:** 새 시험 공간·소유 실행/수신기만 대상으로 위 양성/음성 검사를 수행. 실제 모델·실자료·인증·계좌는 제외합니다.
- **실제 분석 연결 승인:** 앞 단계 통과 후 구독 인증·전송 자료·사용량/시간 제한을 별도로 확인합니다. 이번 진단/모형 승인은 여기에 효력이 없습니다.

현재는 실행 가능한 OS 변경 스크립트나 샌드박스 설정 파일을 생성하지 않았습니다. 버전은 확인했지만 정확한 실효 권한/설정 영향을 모르는 상태에서 로컬 계정 이름·방화벽 규칙을 임의로 만들어 승인받지 않습니다. 소프트웨어 설치·Windows 업그레이드 구매·기존 WSL 종료도 하지 않습니다.
