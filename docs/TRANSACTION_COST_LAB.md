2026-09-23. 개발자용 **오프라인 TEST_ONLY 계산 모듈**이다. D03-01 비용 계약과 D03-02의 독립적인 수량 검사를 제공한다. 웹 앱·주문 승인·체결·원장·학습에는 아직 연결하지 않는다. 실제 요율·API·모의계좌·실계좌·수익성 검증이 아니다.

[개발 가이드](DEVELOPMENT_EXECUTION_GUIDE_v1.md)의 D03-03/04와 [운영비 명세](investment-data-contract-v1/OPERATING_COST_SPEC.md)의 OC-U01~08은 미완료다. 기존 정책·합성 프로필·과거 DB·데모 동작·G1/G2/LIVE 잠금은 유지한다. 이 문서의 달러 1 등 요율은 실제 증권사 조건이 아닌 시험 반례다.

## 사용 방법과 정상 결과

기존 설치가 된 프로젝트 루트에서 PowerShell로 실행한다. 새 패키지 설치·키·인증·서버 시작이 필요하지 않다. 런타임 요구 조건과 설치법은 [README](../README.md)를 따른다.

```powershell
npm run build:engine
node --test --test-concurrency=1 dist/runtime/tests/transaction-cost.test.js dist/runtime/tests/cost-aware-sizing.test.js
```

검사 요약의 `fail 0`, `cancelled 0`, `skipped 0`을 확인한다. TypeScript 원본을 직접 실행하지 않고 `.js` import를 해석할 수 있도록 먼저 빌드한다. 성공한 테스트 수·실행 환경·실패 기록은 [PROGRESS · 공개 요약](PROJECT_STATUS.md)에 기록한다.

주요 구현은 [비용 계산](../src/core/transaction-cost.ts)의 `evaluateCostPlan`, [수량 검사](../src/core/cost-aware-sizing.ts)의 `evaluateCostSizing`이다. 복사 가능한 합성 입력은 [테스트 도우미](../tests/transaction-cost-helpers.ts)에 있다. 새 사용자 화면·일반 거래 명령·실제 공급자 어댑터는 제공하지 않는다.

| 결과 | 뜻 | 허용되지 않는 해석 |
| --- | --- | --- |
| 비용 `OK` | 명시한 합성 과금 그룹의 비용 계산 | 실제 체결·요율·청구가 검증됨 |
| `RESEARCH_CANDIDATE` | 지원하는 합성 시나리오의 정수 수량이 비용·위험·경제성 검사 통과 | 주문 승인, 전체 B/P 신호·뉴스·상품 자격 검증 |
| `HOLD` / `ABSTAIN` | 잘못되거나 부족한 근거, 한도 위반 또는 미지원 문맥 | 비용 0으로 대체하거나 자동 재주문 |

수량 결과는 항상 `orderSubmissionAllowed=false`, `learningAllowed=false`, `liveEnabled=false`이다. 성공과 보류 모두 전달받은 State·현금·주문·예약·입력을 변경하지 않는다. 내부 검증된 State 스냅샷을 전제로 하며, 이 함수 자체를 외부 State 수신 API로 사용하지 않는다.

## 비용 계약

`SYNTHETIC_TRANSACTION_COST_V1`은 `purpose=TEST_ONLY`, `provenance=SYNTHETIC_FIXTURE`, `liveEnabled=false`만 받는다. 확인된 실제 요율처럼 표시한 입력도 현재 계산기의 지원 범위 밖이므로 거절한다. 향후 실제 요율은 출처·적용 계좌/상품·검증 절차를 갖춘 별도 계약이 필요하다.

- 시장 KR/US, 상품 EQUITY/ETF/LEVERAGED_ETF, 통화 KRW/USD, 프로필 ID/버전·해시를 고정한다. 현재 KR/KRW, US/USD 조합만 지원한다.
- 사건 시각은 `[effectiveFrom, effectiveTo)` 안이어야 하고 `asOf` 이후면 안 된다. 프로필 `availableAt`도 `asOf` 이전 또는 같아야 한다. 과거 사건의 사후 비용 계산과 당시 의사결정 가능성을 혼동하지 않는다.
- BUY/SELL 각각 COMMISSION/TAX/EXCHANGE를 명시한다. 비용이 없어도 0 규칙을 넣으며 누락을 0원으로 가정하지 않는다. FX 규칙·환전 그룹은 별도다.
- 과금 단위는 ORDER/FILL/DAY/FX다. **집계가 완료되었다고 선언한 합성 그룹**에 계산할 뿐, 브로커 체결을 수집하거나 그 완결성·주문 귀속·위험일 경계를 입증하지 않는다. DAY 그룹의 경계·합산은 호출자가 명시적으로 준비해야 한다.
- 같은 단위·side·그룹 ID의 동일 입력은 계산에서 한 번만 사용하고 변경된 입력은 보류한다. 다른 과금 단위의 합계 수량/명목금액이 다르거나 필요한 단위가 빠져도 보류한다. 실제 이벤트 중복/취소·정정/일별 장부 대조를 대신하지 않는다.
- NOTIONAL은 명시 통화의 금액에 bps를 곱하고, SHARES는 주당 명시 통화 금액을 곱한다. 구간은 **누진 MARGINAL**만 지원한다. 구간 도달 시 전체 거래에 새 요율을 적용하는 방식은 지원하지 않는다.

각 규칙·그룹의 계산 순서는 다음과 같다.

```text
raw = max(minimum, fixed + 각 구간의 기준량 × 구간 요율 합계)
amount = raw / quantum을 UP·DOWN·HALF_EVEN으로 정수화 × quantum
total = 각 그룹·규칙의 amount 합계
```

최소액 적용 뒤 반올림하므로, DOWN과 최소액이 단위에 맞지 않는 합성 입력에서는 최종액이 최소액보다 작아질 수 있다. 실제 제공자 청구 순서라는 뜻이 아니다. 거래량·금액 모두 0인 그룹에는 고정액/최소액을 붙이지 않는다. 취소 자체의 별도 요금·리베이트/환불·상한 수수료는 지원하지 않는다.

Decimal 정밀도 40자리 안에서 계산하도록 입력 금액은 정수부 9자리·소수부 6자리, 규칙 최대16·구간 최대16·그룹 최대2,000·그룹 수량 최대1,000,000으로 제한한다. 이는 계산 자원/정밀도 경계이지 투자 정책 한도가 아니다. 형식 오류·음수·NaN·미지원 필드는 보류한다.

## 수량 검사와 비용 분리

이 모듈은 **포지션이 없고 미종료 주문이 없는 내부 합성 스냅샷**에서만 후보를 비교한다. 기존 보유 위험은 이전 비용 모델로 산출되므로 새 비용과 조용히 혼합하지 않는다. DAY 과금은 기존 일별 거래 누계가 필요하여 수량 검사에서는 보류한다. 별도 비용 계산기의 DAY 지원과 구별한다.

원본의 `guards`, `caps`, `remainingRisk`, `economic`, `resolveOperatingCost`를 재사용하고 B/P의 ATR 보호 거리 및 진입 프리미엄을 그대로 적용한다. 새 숫자 한도나 수익성 기준을 원본에 추가하지 않았다. 전체 신호/이벤트 자료 검증 또는 실전 상품 자격 판정은 아니다.

명시 실행 모형은 **편도당 한 주문, 매 주식 1주씩 분할 체결**이다. 주문 단위 비용은 한 번, 체결 단위 비용은 수량만큼 계산한다. 최소 체결 수수료를 보수적으로 비교하기 위한 고정 시나리오이며 모든 체결 경로·호가 깊이·지연·취소/대체의 최악 비용 상한을 증명하지 않는다.

1. 매수 ask는 틱 올림, 보호 stop은 틱 내림한다. 보호 거리·프리미엄·스프레드·신선도 등 원본 조건 위반은 보류한다.
2. 현금·종목/총 노출·최우선 호가 참여율·직전 분 거래량 참여율로 정수 상한을 만든다.
3. 상한부터 1주까지 열거하며 각 수량의 진입·손절·기대 청산·하위 시나리오 청산 요금을 각각 계산한다. 비선형 비용을 선형 비례로 축약하거나 단조성을 전제로 이분 탐색하지 않는다.
4. 기존 위험 예산·수수료 포함 현금/노출·외화 비중·경제성 조건을 모두 만족하는 가장 큰 수량만 `RESEARCH_CANDIDATE`로 반환한다. 가능한 수량이 없으면 이유별 거절 횟수와 `ABSTAIN`을 반환한다.

탐색 상한이 1,000주를 넘으면 잘라서 승인하지 않고 `SYNTHETIC_SEARCH_LIMIT`로 보류한다. 이 계산 자원 제한을 실제 유니버스/거래 한도로 승격하지 않는다.

| 항목 | 계산/처리 |
| --- | --- |
| 손절 위험 | `(틱 반영 진입가 − 보호가) × q × FX + C_stop`, KRW 올림 |
| `C_stop` | 진입 요금 + 불리한 틱을 반영한 손절 청산 요금 + 해당 틱 이동 손실; 운영비 제외 |
| 경제성 비용 | 기대 청산 시나리오 왕복 거래비 + 운영비 추정 한 번 |
| 하위 순손익 | `(q05Exit − 진입가) × q × FX − 해당 청산의 왕복 거래비 − 운영비 추정` |
| 틱 민감도 | `q × tick`, 비율은 `(q × tick)/(q × 진입가) × 10,000`; 예산125,000원을 분모로 쓰지 않음 |
| 스프레드 | ask 진입가격에 이미 포함됨; 진단값을 손실 비용에 재가산하지 않음 |
| 기존 USD 현금 | FX는 KRW 가치/위험 합산에만 사용; 거래마다 환전 비용 자동 부과 안 함 |

기대 청산가·`q05Exit`는 사용자가 아니라 개발 시험이 주입한 **수량과 무관한 합성 가격 시나리오**다. 각각 불리한 틱 이동 후 가격에서 SELL 요금을 다시 계산한다. `netQ05Krw`는 원본 `economic`에 전달하는 시험용 순손익이며 실제 시장의 다섯 번째 백분위수·검증된 예측 모델이 아니다. 운영비를 `C_stop`에 중복 가산하지 않고 기존 명시 이력/미확인 보류 계약을 사용한다. 추정값을 실제 지급·배분·학습 라벨로 기록하지 않는다.

요청·State·프로필·원본 정책·운영비 근거 해시를 결과에 묶지만, 이것은 계산 출처 추적이다. 스냅샷 승인·접수 재검사·영속 체결 기록과의 연결은 D03-03에서 별도 구현해야 한다.

## 검증 범위와 남은 작업

[비용 테스트](../tests/transaction-cost.test.ts)와 [수량 테스트](../tests/cost-aware-sizing.test.ts)는 비례/최소/구간·통화·과금 단위·반올림·시점·중복/상충·잘못된 입력, 위험/현금/노출/정수/ATR/틱/스프레드/경제성 경계와 입력 불변을 확인한다. 명시 USD 1 최소액에 의한 거절과 더 낮은 합성 비용에서 통과하는 양성 대조가 있다. SOXL 등 레버리지 ETF를 유형만으로 일괄 금지하지 않지만 실제 자격·상품 적격성은 별도 확인 대상이다.

아직 하지 않은 것:

- D03-03: 새 비용 계약을 공용 승인·접수·체결·예약·원장·보고·학습·재시작에 연결, 부분 체결·취소/대체·사후 정정·누계 DAY 비용의 대조.
- D03-04: 앱–운영비 보조장부–학습의 다일/혼합 통화 통합. 기존 운영비 학습 보류 조건은 삭제하지 않는다.
- 실제 요율 확인, 외부 자료/API/계좌 연결, 브로커 모의·실주문, 시장 수익성, 웹 UI/E2E, 새 설치 및 실제 OS 격리.

OC-U01~08의 남은 결정은 짧은 이력 처리, 공유 구독의 증분 비용, 외화 비용 환산 시각/출처/반올림, 미래 증가분과 예산 중복, 환불·정정 버전, 보고 마감과 손실 래치, 늦은 비용의 가용성/귀속, 기존 단일 세션과 다일 원장의 통합 범위다. 이번 구현은 이 결정을 대신하지 않는다.

후속 [비용 체결·예약·복구 실험실](COST_EXECUTION_LAB.md)에서 개별 합성 체결의 비용 차액·예약·취소/대체·보고/학습 보류 근거·새 SQLite 재생을 별도로 구현했다. 1주씩 체결 시나리오의 수량 검사와 달리, 그 원장의 비용 예약은 최대 구간 요율로 다양한 체결 분할을 덮는다. 기존 수량 계산의 지원 의미나 공용 엔진은 바꾸지 않았다. D03-03/04 통합은 여전히 미완료다.

다음 작업은 공용 엔진과의 비용 연결 범위를 확정하고, 위 안내의 OC-U01~08 선택지·영향 중 필요한 정책 결정을 받는 것이다. 제안은 미승인 초안이며 자동 적용하지 않는다. 정책 승인이 필요한 부분은 보류하면서 독립적인 오프라인 검증은 진행할 수 있다. 지금은 App Key를 발급할 필요가 없다.
