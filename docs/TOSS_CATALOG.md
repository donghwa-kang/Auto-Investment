# 토스 종목 목록 수집 준비

국내·미국 후보 목록을 만들기 위한 **실험적 독립 CLI**다. 구현과 모형 통신 시험만 수행했으며, 실제 목록 조회는 이용 조건·비용 미확인으로 보류했다. 기본 웹 앱의 합성 모의매매나 SOXL/SOXX 시세 점검 명령을 바꾸지 않는다.

## 범위와 공식 계약

2026-09-12 확인한 [토스 공식 API 명세](https://openapi.tossinvest.com/openapi-docs/latest/openapi.json)의 `GET /api/v1/stocks/all`을 사용한다. KOSPI, KOSDAQ, NYSE, NASDAQ, AMEX, KR_ETC, US_ETC를 각각 조회한다. `status=ACTIVE`를 명시하고 상품 종류·보통주 필터는 생략한다. SOXL/SOXX만 조회하는 명령이 아니다.

이 범위는 **토스가 제공하는 활성 종목 카탈로그**다. 모든 거래소의 모든 상품·계좌별 거래 자격·장중 거래정지 여부를 보장하지 않는다. 공식 설명은 일 배치 자료의 저빈도 조회·캐시를 권장하며 페이지네이션은 명세에 없다. [공식 가이드](https://developers.tossinvest.com/)의 STOCK_ALL 제한은 초당 1회이며 운영 중 바뀔 수 있다.

당일 성공 결과를 캐시로 재사용한다. 같은 작업 폴더에서는 프로세스 간 잠금과 영속 시도 기록으로 **KST 실행 시작일당 최대 1회 수집 시도**를 제한한다. 시도 1회는 인증 최대 1회와 7개 시장 조회를 뜻하며 HTTP 요청 총 1회라는 뜻이 아니다. 자동 갱신·스케줄러는 없고 명령 실행 시에만 동작한다. 시장별 응답은 하나의 원자적 동일 시점 스냅샷이 아니다.

## 키 없이 캐시만 확인하기

기존 의존성이 설치된 프로젝트 루트의 PowerShell에서 실행한다.

```powershell
npm run build:engine
npm run catalog:cached
```

이 명령은 키·토큰·확인 플래그를 사용하지 않고 파일을 생성하거나 외부 통신을 하지 않는다. PAPER/BACKTEST 모드·실거래 비활성·원본 정책 검사는 유지한다. 현재 작업 폴더에는 실제 목록 캐시가 없어 직접 실행 결과는 `CATALOG_CACHE_MISSING` / 종료 코드 1이었다. 아래의 실제 조회 예시와 구분한다.

### 일일 캐시·재시도 규칙

- `catalog:fetch`는 기존 조회/이용 조건 확인 게이트를 먼저 검사한다. 당일 정상 캐시가 있으면 키 파일을 읽거나 재인증하지 않고 같은 결과 경로를 반환한다. 플래그 없이 확인만 하려면 `catalog:cached`를 사용한다.
- 최초 시도는 키 읽기·인증 전에 STARTED 상태를 영속 기록한다. 잘못된 키, 인증/HTTP 실패, 부분 수신, 품질 불완전, 저장 실패도 당일 자동 재시도를 허용하지 않는다. 정상 빈 목록 7개는 빈 캐시로 재사용할 수 있다.
- 저장 파일의 크기·UTF-8·스키마·정책/연구 범위·해시·7개 시장·요청/수신 순서·집계 수치를 검사한다. 저장된 분류/승인은 신뢰하지 않고 현재 분류기로 재계산해 비교한다. 손상되거나 변경된 당일 캐시는 거절하며 자동 재조회로 대체하지 않는다.
- 날짜 기준은 **로컬 호출 예산용 KST**이지 토스 갱신 시각이나 한국/미국 거래일이 아니다. 자정을 넘긴 수집도 시작일에 귀속하므로 다음 날 캐시로 자동 승격하지 않는다. 다음 시작일에는 새 명령 실행이 필요하며, 순차 실행 사이에도 최소 1.1초 대기한다. 날짜 경계는 24시간 간격 보장이 아니다.
- 동시 수집은 `daily-fetch.lock`으로 거절한다. 강제 종료 후 남은 잠금은 다음 날에도 자동 해제하지 않는다. 잠금/시도 기록을 지워 강제로 재호출하지 말고, 해당 CLI 종료 여부·실제 요청 결과·기존 기록을 먼저 대조해야 한다. 자동 복구/강제 새로고침 명령은 제공하지 않는다.
- 잠금은 **같은 작업 폴더의 이 CLI끼리**만 조정한다. 다른 복사본·PC·프로그램 및 별도 `market:check`와 같은 키를 동시에 사용하지 않는다. 토큰 무효화나 계정 전체 호출 예산을 통합 관리하는 기능은 아니다.

## 실행 전 확인

사용자가 다음을 확인하기 전에는 실제 키를 사용하지 않는다.

1. 본인 API 이용 조건에서 개인용 조회·로컬 저장을 허용하는지, 보관 제한이 있는지 확인한다. 재배포 권한으로 확대하지 않는다.
2. API/시세 정보의 별도 이용료·신청 비용을 확인한다. 공개 명세에서 무료라고 확정하지 못했다.
3. 본인 키·허용 IP를 준비한다. 새 토큰 발급은 같은 키의 기존 토큰을 무효화할 수 있으므로 다른 프로그램 사용 여부를 확인한다.

2026-09-12 사용자는 이용 조건·비용을 아직 확인하지 않았다고 답했다. 이번에는 실제 키 읽기·토큰 발급·인증된 목록 조회를 하지 않았다. 아래는 **확인 이후의 사용 절차**이며 지금 실행하라는 의미가 아니다.

### 후속 공식 약관 확인 (2026-09-12)

공식 홈페이지의 접힌 FAQ와 [오픈 API 서비스 이용 약관](https://corp.tossinvest.com/ko/terms/v2?id=752)을 브라우저에서 읽었다. 약관 목록과 본문의 선택 버전은 2026-08-12다. 고객별 계약·신청 화면은 확인하지 않았으며 약관에 대신 동의하지 않았다.

- 제5조: 개인 본인의 매매 목적으로 시세를 이용하고 제3자 제공·배포·상업적 활용을 제한한다. 키도 제3자에게 대여·위임·양도·누설하지 않아야 한다.
- 제10조: 매매가 성립했을 때의 위탁수수료와 요율 게시를 규정한다. [소개 페이지 FAQ](https://corp.tossinvest.com/ko/open-api)의 수수료 답변도 기존 적용 수수료 유지와 추후 변경 가능성을 설명한다. 이를 조회·저장 비용이 반드시 0원이라는 명시적 확인으로 처리하지 않는다.
- 제13조의 10년 보존은 **회사**의 거래기록 보존 규정이다. 고객의 종목 정보 로컬 저장 허가·보관 기간으로 승계하지 않는다.

후속 대조에서 [공식 종목 목록 명세](https://openapi.tossinvest.com/openapi-docs/latest/openapi.json)의 `GET /api/v1/stocks/all` 설명이 하루 1회 조회 후 **로컬 캐싱을 직접 권장**함을 확인했다. 따라서 종목 목록의 로컬 캐시까지 모두 미확인으로 묶었던 앞선 설명은 정정한다. 이 권장은 종목 목록의 효율적인 사용 근거이며, 모든 시세의 장기 보관·과거 DB 구축·제3자 제공 허가로 확대하지 않는다.

[공식 매매 수수료표](https://corp.tossinvest.com/ko/business?tab=commission), [업무수수료표](https://corp.tossinvest.com/ko/business?tab=businessFee), 투자정보서비스 안내 및 고객센터의 API 제목 검색도 확인했다. 열람한 수수료표에서는 별도 API 조회 요금 항목을 찾지 못했고 FAQ 제목 검색은 결과가 없었다. **별도 요금 공시를 찾지 못했다는 사실과 무료라는 공식 확약은 다르다.** 조회 비용 확약, 고객별 신청 조건, 시세 장기 보관 범위는 남은 확인 사항이다. 확인 플래그는 변경하지 않았으며 고객센터와 실제 상담한 것은 아니다.

다음 질문을 토스 고객센터에 확인하면 실제 조회 수용검증의 남은 조건을 판단할 수 있다. 아래 문안은 초안이며 전송하지 않았다.

> 개인용 개발·모의검증을 위해 실주문 없이 Open API를 사용하려고 합니다. 종목 목록의 로컬 캐싱 권장은 공식 문서에서 확인했습니다. (1) 조회만 할 때 별도 API/시세 이용료나 유료 신청이 있나요? (2) 목록의 일상적인 캐시를 넘어 시세를 제 PC에 누적 저장해 장기간 반복 검증할 경우 보관 기간·삭제·재사용 조건이 있나요? 외부 배포·상업적 제공은 하지 않을 예정입니다.

### 확인 후 실행 예시

기존 의존성이 설치된 프로젝트 루트의 PowerShell에서 실행한다. 기본 설치 환경은 [README](../README.md)를 따른다. `.env` 자동 로딩은 없다.

```powershell
npm run build:engine
$env:TRADING_MODE = 'PAPER'
$env:LIVE_ENABLED = 'false'
$env:TOSS_CATALOG_READ_ONLY = 'true'
# 이용 조건·비용을 본인이 확인한 이후에만 설정
$env:TOSS_CATALOG_TERMS_CONFIRMED = 'true'
$env:TOSS_CREDENTIAL_FILE = 'C:\secure-local\toss-credentials.txt'
npm run catalog:fetch
```

키 경로는 본인이 준비한 로컬 파일로 대체한다. 형식은 [기존 시세 안내](TOSS_MARKET_CHECK.md)의 CLIENT_ID/CLIENT_SECRET 형식을 사용한다. 실제 값을 문서·예제 설정·브라우저에 넣지 않는다. 확인 플래그는 본인 확인 선언이지 이용권이나 조회 전용 토큰을 발급하는 기능이 아니다.

| 변수 | 기본값·필수 조건 | 비밀 여부 |
| --- | --- | --- |
| `TRADING_MODE` | 미설정 시 PAPER. 기존 PAPER/BACKTEST 경계 사용, LIVE 거절 | 아니오 |
| `LIVE_ENABLED` | 미설정 또는 false. true 거절 | 아니오 |
| `TOSS_CATALOG_READ_ONLY` | 정확히 true 필수. 미설정/false 거절 | 아니오 |
| `TOSS_CATALOG_TERMS_CONFIRMED` | 정확히 true 필수. 미확인 상태에서 설정 금지 | 아니오 |
| `TOSS_CREDENTIAL_FILE` | 로컬 키 경로 필수. 직접 URL/UNC/장치 경로 거절 | 경로만 설정; 내용은 비밀 |

모드·확인·인자·원본 정책 해시 검사는 키 파일 읽기 전에 수행한다. [.env.example](../.env.example)의 목록 조회 플래그 예시는 false다.

## 결과 읽기

실제 수집 시도에서 보고서가 반환되면 `data/toss-catalogs/시각-UUID.json`을 새로 만든다. 당일 캐시 재사용은 기존 보고서를 읽으며 새 보고서를 만들지 않는다. 같은 디렉터리의 `daily-state.json`만 임시 파일 저장·동기화 후 교체하고 자신이 만든 실행 잠금만 정상 종료 시 제거한다. 기존 보고서·합성 DB·일회용 로그인 코드는 수정하지 않는다. 오래된 보고서의 자동 삭제/보관 기간 정책과 웹 화면 연결은 없다. 목록 캐시를 장기 시세 DB 허가로 확대하지 않는다.

| 결과 | 의미 |
| --- | --- |
| `CATALOG_SCOPES_RECEIVED` | 7개 요청 범위 모두 수신. 품질·거래 준비 성공은 아님 |
| `CATALOG_INCOMPLETE` | 인증 또는 일부 요청 실패. 이전에 받은 시장만 보존 |
| `CATALOG_CACHE_REUSED` | 당일 성공 캐시 재검사 완료. 이번 실행의 키 읽기·통신 0회 |
| `CATALOG_CACHE_MISSING` / `CATALOG_CACHE_STALE` | 캐시 없음 / KST 시작일이 이전 날짜. 자동 조회하지 않음 |
| `CATALOG_CACHE_INVALID` | 캐시 상태·내용·시각·정책·해시 또는 재분류 불일치. 재조회로 숨기지 않음 |
| `CATALOG_DAILY_ATTEMPT_ALREADY_USED` | 당일 실패 또는 완료 여부가 불확실한 시도 존재. 추가 인증/조회 거절 |
| `CATALOG_CACHE_LOCKED_OR_UNWRITABLE` | 실행 잠금 존재 또는 잠금 생성 불가. 다른 실행/파일 권한 확인 필요 |
| `RECEIVED` / `RECEIVED_EMPTY` | 자료 수신 / 정상 응답의 빈 목록 |
| `FAILED` / `NOT_ATTEMPTED` | 해당 단계 실패 / 앞선 실패로 시도하지 않음 |
| `allScopesReceived` | 모든 요청 범위 수신 여부. 거래소 전체 종목 포함 보장 아님 |
| `dataQualityComplete` | 모두 수신하고 잘못된 행·ID 상충·심볼 충돌이 없다는 제한적 의미 |
| `metadataReady=false` | 통화·상품 구조·시점 등 보강 필요. 모의 주문에도 연결하지 않음 |
| 종료 코드 0 / 1 / 2 | 요청 범위·구조 검사 완료 / 시작·저장 등 실패 / 수집 또는 행 품질 불완전 |

목록 API만으로 필요한 사실이 확보되지 않아 정상 수신이어도 검토 후보 승인 수는 0이다. SOXL이나 레버리지를 금지해서가 아니라 미확인 정보를 채우지 않기 때문이다. 실패·결측 때 이전의 좋은 자료를 자동으로 최신 자료 대신 사용하지 않는다.

## 자료 계약·분류

- 결과는 `TOSS_CATALOG_SNAPSHOT_V1` / `REAL_REFERENCE_SNAPSHOT`이다. [오프라인 카탈로그](OFFLINE_CATALOG.md)의 TEST_ONLY 입력에 넣으면 거절한다. 시험은 통신을 가짜로 대체하고 출력도 임시 시험 폴더에 격리했다.
- `symbol`, `name`, `securityType`, `isCommonShare`, `isinCode`를 검증·정규화한다. 잘못된 행은 인덱스·일반 사유만 기록한다. 확장 필드는 버리고 새로운 상품 코드의 문자열은 보존하되 종류는 UNKNOWN이다.
- 키는 `시장 구분:ISIN`이다. ISIN은 형식만 검사하고 체크섬·외부 대조·재상장 계보는 미검증이므로 `SOURCE_ISIN_UNVERIFIED`로 표시한다. 시장 구분을 체결 거래소로 바꾸거나 같은 심볼의 다른 시장 종목을 합치지 않는다.
- 완전 중복은 합치고, 같은 ID의 다른 내용은 임의 최신값 선택 없이 확인 대기한다. 같은 시장의 심볼을 다른 ISIN이 주장하면 모두 충돌 처리한다. 분류 해시는 입력 순서·완전 중복 수와 독립적이다.
- STOCK/FOREIGN_STOCK은 STOCK, ETF/FOREIGN_ETF는 ETF로 정규화한다. ETN/신주인수권은 범위 밖 사유를 남긴다. DR/REIT/기금은 별도 프로필 없이 주식에 편입하지 않는다. 원천 종류는 보존한다.
- 기존 공통 사실 분류 함수와 연구 범위를 재사용한다. 3천만 원 이상 예탁금 단일종목 레버리지 제외와 지수형 레버리지 SOXL의 연구 범위는 변경하지 않았다.
- 목록 포함을 `brokerSupported=true`로 기록하되 계좌 자격으로 취급하지 않는다. 통화·체결 거래소·거래정지 여부·기초자산·레버리지·예탁금은 UNKNOWN/null이다. 심볼·이름으로 추정하지 않는다.
- 원천 갱신·효력 시각·정정 번호는 null이다. 로컬 요청/수신 시각으로 대체하지 않는다. `historicalUniverseReady=false`, `freshForTrading=false`이므로 과거 모집단이나 최신 거래 자료로 승인하지 않는다.

## 호출·저장 안전 경계

고정 HTTPS 호스트의 인증 POST 1회와 목록 GET 최대 7회만 가능하다. 계좌 헤더·계좌/잔고/주문/취소/환전 메서드·임의 URL 입력은 없다. 한 클라이언트는 재사용·동시 실행을 거절한다. 목록 응답 종료 후 다음 요청까지 최소 1.1초 간격이며 실패·429·토큰 만료 때 자동 재시도/재인증 없이 중단한다.

요청당 15초, 인증 응답 64 KiB, 목록 응답 4 MiB, 실행 전체 50,000행, 로컬 분류 보고서 64 MiB·일일 상태 8 KiB 상한은 자원 제한이며 투자 기준이 아니다. 리디렉션을 따르지 않고 JSON/UTF-8/자료 계약을 검사한다. 목록 응답 해시·정규화 자료·분류 해시, 상태 코드·제한된 숫자형 호출 제한 헤더만 보존한다. 원본 전체·오류 본문·인증 응답·키·토큰·계좌 정보는 저장하지 않는다.

토큰은 메모리에서만 쓰고 종료 시 참조를 지우지만 물리적 소거 보장은 아니다. 키 파일·결과의 OS ACL/동기화/백업은 별도 확인이 필요하며 `mode: 0o600`은 Windows ACL 보장이 아니다. 앱 경로 제한은 토큰 자체의 조회 전용 권한이나 OS 네트워크 격리가 아니다. 직접 UNC 거절도 연결 지점/심볼릭 링크 전수 차단을 뜻하지 않는다.

캐시 해시는 손상/계약 위반 검사용이지 토스가 발급한 전자서명이 아니다. 로컬 파일을 자유롭게 조작할 권한이 있는 공격자의 원천 자료 위조·과거 상태 복원을 차단한다고 보장하지 않는다. 상태 파일 동기화/교체 및 실제 자식 프로세스 종료는 시험했으나 전원 차단 내구성·디스크 고장·모든 Windows 재분석 지점/ACL은 미검증이다. 저장 불확실 시 자동 복구보다 보류를 우선한다.

## 검증·남은 단계

재현 가능한 격리 검사:

```powershell
npm run build:engine
node --test --test-concurrency=1 dist/runtime/tests/toss-catalog-cache.test.js dist/runtime/tests/toss-catalog.test.js dist/runtime/tests/catalog-fetch-cli.test.js dist/runtime/tests/catalog.test.js dist/runtime/tests/catalog-cli.test.js dist/runtime/tests/core.test.js dist/runtime/tests/research-scope.test.js dist/runtime/tests/market-data.test.js
```

가짜 자격증명·통신·임시 출력만 사용한다. 실제 자식 CLI의 정상/부분 실패 저장·종료 코드, 시작 거절, 실제 15초 abort 신호를 검사한다. 실제 서버의 타임아웃·호출 제한 시험은 아니다. 실행 증거 (로컬 비공개 기록: `work/toss-catalog-verification`)에 타입·린트·형식·빌드·집중 검사·원본 해시·문서 확인을 기록한다. 최초 자식 CLI 시험의 Windows import 경로 오류는 파일 URL 변환으로 수정하고 재실행했다.

목록 수집 최초 검사는 신규 24개와 관련 기존 115개, 총 139개가 통과했다. 일일 캐시 추가 후에는 신규 16개와 기존 139개, 총 155개를 재실행해 모두 통과했다. 실제 자식 CLI의 당일 키 미읽기 재사용·통신 없는 점검·두 프로세스 경합·소유 자식 강제 종료 후 잠금 보존을 포함한다. 타입·린트·형식·엔진/웹 빌드 통과, 원본 37개 해시 일치 및 기존 TEST_ONLY 판단 해시 유지도 확인했다. 캐시 검증 증거 (로컬 비공개 기록: `work/toss-cache-verification`)는 기존 검사/실패 로그와 분리했다.

전체 제품 회귀·브라우저 E2E·새 설치·실제 수집·이용 권리·투자 성과는 미검증이다. 사용자 실험을 건드리지 않도록 서버 종료/로그인 코드 생성 시험도 실행하지 않았다.

다음은 이용 조건·비용 확인 후 제한된 실제 조회로 계약을 검증하는 것이다. 이후 상품 구조·통화·시점, 가격 이력·유동성·뉴스 및 선정 프로필을 순서대로 보강한다. 목록 수집만으로 전체 시장 자동매매가 완성되지는 않는다.
