## 📋 제공 범위

기존 다종목 화면에 **비용 코어 시험** 메뉴를 추가했다. 기존 모의 투자 엔진·저장 기록을 전환하는 기능이 아니다. 새 단일 KRW 실행만 [신호·비용 브리지와 시간 감시](COST_SIGNAL_BRIDGE.md)에 연결한다. 실제 시세·계좌·브로커 주문·외부 AI·자동 학습은 호출하지 않는다.

가상 초기금은 5,000,000원, 종목은 `REPLAY-KR-B`, 위험 설정은 기존 합성 fixture를 사용한다. 기존 120세션 합성 이력과 B/P 심사를 거친 한 신호를 선택한다. 시험용 별도 비용 근거는 매수/매도 각각 주문 단위 1bp·최소10원, 세금/거래소 비용0원이다. **실제 증권사 요율이 아니다.** 원본 정책·기존 프로필은 변경하지 않는다.

가격 공급은 처음 네 번 매수 호가21,400원/매도 호가21,399원, 이후22,000원이라는 고정 경로다. 엔진은 이 경로에서 부분 체결·기존 목표가·예약·결제를 처리한다. 이 상승 경로의 손익은 산술 검사일 뿐 투자 성과가 아니다. UI에서 가상 자금·가격·비용·전략을 변경하거나 기존 DB를 이관할 수 없다.

## ▶️ 실행과 사용

프로젝트 루트에서 기존 [실행 환경](../README.md#실행-환경)을 사용한다. 새 의존성이나 API 키는 필요하지 않다.

```powershell
npm run build
npm run portfolio:web
```

1. 서버 출력 주소를 열고 로컬 일회용 코드로 연결한다. 기본 주소는 `http://127.0.0.1:4184/?view=portfolio&lab=cost`이며 서버 실행 중에만 열린다.
2. **비용 코어 시험**에서 합성 입력 동의를 확인하고 **새 비용 시험 생성**을 누른다. 기존 합성 이력을 검증하므로 수십 초 이상 걸릴 수 있다.
3. `IDLE`과 원화 장부가 나타나도 자동 시작하지 않는다. **비용 시험 시작**을 누르면 서버 작업기에서 합성 호가와 시간 감시를 처리한다.
4. 원화 현금/가용현금/예약금/미수/미지급, 잔여 주식·주문 상태·미결제 체결·비용을 확인한다. 모든 금액은 검증된 코어 보고서의 문자열이며 화면은 금융 계산을 하지 않는다.
5. 중지·단절 시험은 아래 의미를 확인하고 사용한다. 브라우저 닫기·새로고침·메뉴 이동은 서버 정지가 아니다.

이미 실행 중인 구버전 서버는 자동 교체하지 않는다. 기존 실행의 보유·미체결을 확인하고 사용자가 정상 종료한 뒤 새 빌드로 실행해야 새 메뉴/API를 사용할 수 있다. 이번 개발 검증은 임시 저장소·임의 로컬 포트만 사용하며 사용자의 상주 서버를 재시작하지 않는다.

| 조작/상태 | 정확한 의미 |
| --- | --- |
| 시작/같은 실행 재개 | 같은 서버 작업기에서 감시·합성 공급 시작. 신규 승인이나 HOLD 해제 아님 |
| 실행 중지 | 확인 후 체결 루프와 시간 감시 정지. 청산·취소·예약 반환 아님 |
| 합성 입력 끊기 | 호가 생성만 중지. 시간 감시는 계속되며 단절/기한 경고를 기록 |
| 합성 입력 다시 공급 | 새 합성 호가 공급. 이전 HOLD는 유지 |
| `STOPPED` | 실행기가 멈춤. 보유·미체결·미결제는 따로 확인 |
| 루프 `HOLD` / 경고 목록 | 저장된 검토 필요 사유. RUNNING과 동시에 존재할 수 있음 |
| `FAULT` / 작업기 응답 지연 | 실행·저장·통신 상태 확인 필요. 마지막 수신 값으로 현재 보호를 보장하지 않음 |

이 탭에는 수동 청산·HOLD 해제·대조 승인 버튼이 없다. 기존 자동 목표/손절/시간 청산 코어는 사용하지만, 중지로 청산을 가장하거나 보호 범위를 임의 확대하지 않는다. 미확정 주문은 상태 그대로 표시하며 타임아웃을 체결/취소 확정으로 바꾸지 않는다.

## 🔐 저장·요청·재시작 경계

전용 경로는 `PORTFOLIO_WEB_ROOT/cost-runs/<UUID>/request.json`과 `cost.sqlite` 및 WAL/SHM이다. 기본 루트는 `data/portfolio-web`이다. 기존 `runs/`와 금융 자금을 공유하지 않는다. `request.json`은 최초에만 생성하고 금융 사건은 기존 V3 Store의 원자 커밋·멱등성·재생 검사를 통한다. 앱 제어 의도는 같은 SQLite 연결의 `cost_web_controls`에 append-only로 기록하지만 **금융 원장의 일부나 실행 완료 영수증은 아니다.**

인증된 `GET/POST /api/cost-lab`을 사용한다. 기존 loopback Host·Origin·세션·CSRF·8KB 본문 제한을 그대로 적용한다. 요청 스키마는 `create/open/control`만 허용하며 임의 경로·시세·금액·실주문 플래그는 받지 않는다. 새 실행20개, 실행당 제어100개, 동시 제어 대기8개, 합성 호가32개로 제한한다. 제어의 마지막 한 칸은 STOP 전용으로 남겨 시작/입력 전환이 중지 슬롯을 소진하지 못하게 한다. 기존 코어의 명령/사건/감시 상한도 유지한다. 자동 삭제는 없다.

- 생성 UUID를 재전송해도 같은 실행을 반환한다. 제어는 UUID·전체 요청 해시·`expectedControl`로 중복/상충·늦은 명령을 구분한다. 오래된 START 재전송은 STOPPED를 재개하지 않는다.
- 브라우저는 **발송 전** 전체 요청을 해당 Origin의 `localStorage`에 기록한다. 응답 유실/5xx 시 새 명령을 막고 같은 요청 재확인만 허용한다. 새로고침 후에도 보존된다. 저장소 접근 실패·다른 보류 요청은 발송을 차단한다. 이 저장소는 비밀키 보관소나 OS 전원 장애 원자성 보장이 아니다.
- 서버 재시작 또는 worker 다시 열기는 **기록 검사 전용**이다. 새 writer lease와 기존 Store 재생 검사로 금융 보고를 읽지만 시계/실행을 자동 복구하지 않는다. 원래 제어 요청을 확인해도 재실행하지 않는다. 검사 과정의 lease 메타데이터 쓰기까지 없는 파일 읽기 전용 모드는 아니다.
- 저장된 실행이 전부 검사되지 않았거나 보유/미체결/미결제/HOLD/읽기 오류가 남으면 새 실행을 차단한다. 오류 자료나 DB를 삭제해서 정상화하지 않는다. 이 단계에는 복구 대조 승인 기능이 없어 미완료 실행의 콜드 재개는 지원하지 않는다.

시간은 최초 START에서 고정 합성 시작 시각에 단조 경과 시간을 매핑한다. 같은 프로세스에서 중지한 시간도 재개 때 포함한다. 시각을 샘플링한 한 처리 구간에서 시간 점검 후 새 합성 호가를 제공하며 과거/실제 호가를 현재 시각으로 바꾸지 않는다. 늦은 콜백은 한 번만 처리하고 놓친 가상 틱을 몰아서 생성하지 않는다. 이는 실시장 수신 시계 계약이 아니다.

## 📊 보고와 학습 권한

화면은 `CostReservationStore.read()`로 재생 검증한 상태에서 기존 `buildCostOutcomeReport`를 사용한다. UI용 별도 손익 계산기·금융 DB는 만들지 않았다. 기존 금융 사건이 바뀌거나 감시 사유가 기록되면 같은 상태의 보고서를 다시 만들고 HTTP 조회는 캐시만 읽는다.

보고·학습 보류 자료는 같은 `financialBasisHash`를 참조한다. `learningEvidence.status=HOLD`, `learningAllowed=false`, `orderSubmissionAllowed=false`, `liveEnabled=false`다. 운영비 포함 최종 손익·학습 라벨은 만들어내지 않는다. 보고 해시와 보류 사유를 화면에서 확인할 수 있지만 기존 학습 데이터셋/Codex 분석에 자동 전달하지 않는다.

## ✅ 검사와 남은 한계

```powershell
npm run build
node --test --test-concurrency=1 dist/runtime/tests/cost-web.test.js
npx --no-install playwright test tests/browser/cost-lab.spec.ts
```

실제 실행 개수·실패 이력·관련 회귀·사용 런타임은 [PROGRESS · 공개 요약](PROJECT_STATUS.md)의 S5 기록을 따른다. 자동 시험은 임시 DB를 쓰며 Playwright는 로컬 Edge로 화면을 확인한다. 기존 설치 환경의 검사이지 새 PC 설치나 모든 브라우저 검증이 아니다.

HTTP/UI와 비용 작업기는 별도 Node worker를 사용한다. 그러나 비용 타이머·금융 기록·보고 재생은 같은 worker의 동기 경로다. 장부가 커지거나 CPU/디스크가 느리면 호가·시간 점검·중지도 지연될 수 있으며 기존2초 경고가 발생할 수 있다. 작업기 소식이5초 없으면 마지막 상태임을 표시하고 제어를 막는다. 이것은 OS 독립 안전장치·2초 내 보호·실시간 성능 보장이 아니다.

다종목/USD 비용 코어 전환, 임의 전략·위험도 선택, 전원/OOM·물리 디스크/절전·장기 상주, 실제 브로커 대사/취소/청산, 실자료 백테스트·수익성·AI 기여도, 운영비 배분·정정 정책·콜드 재개 승인·자동 학습은 이번 범위 밖이다. S5 하위 완료가 D03 전체나 실전 준비 완료를 뜻하지 않는다.
