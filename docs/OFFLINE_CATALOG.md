# 오프라인 종목 후보 카탈로그

2026-09-12 구현. 국내·미국 종목 메타데이터를 같은 형식으로 받아 검토 후보·제외·확인 대기로 분류하는 독립 로컬 CLI다. 전체 시장 설계의 첫 구현 단위이며 **실제 전체 시장을 수집하는 스캐너, 추천 순위, 매수·매도 프로그램이 아니다.** 웹 화면과 합성 매매 엔진에도 아직 연결하지 않았다.

별도 [토스 목록 수집 경로](TOSS_CATALOG.md)를 후속 추가했다. 현재 문서의 입력은 여전히 TEST_ONLY이며 실자료 스냅샷을 받지 않는다. 두 경로는 사실 분류만 공유하고 원천 시점·시험 가정을 섞지 않는다.

## 실행과 정상 결과

기존 프로젝트 의존성이 설치된 Windows/Node 24 환경에서 프로젝트 루트 기준으로 실행한다. 공통 설치 방법은 [README](../README.md)를 따른다. 새 패키지나 API 키는 필요 없다.

```powershell
npm run build:engine
npm run catalog:check -- fixtures/catalog-v1.json
```

정상 종료 코드는 0이다. `OFFLINE_CATALOG_COMPLETE`, `purpose=TEST_ONLY`, `stage=METADATA_CLASSIFICATION_ONLY`, `strategyEvaluated=false`, `ordersEnabled=false`와 결과 파일 경로를 출력한다. 검토 후보는 자료 분류의 결과이지 거래 허용이 아니다.

[샘플 JSON](../fixtures/catalog-v1.json)은 실제 회사 조사나 현재 시장 자료가 아니다. SOXL/SOXX 심볼도 분류 경로 시험을 위한 것이며 거래소 `TEST-US`와 브로커 지원 여부·시각·예탁금 값 등은 합성 시험 입력이다. 실제 상품 자격과 최신 규제를 증명하지 않는다.

| 샘플 결과 | 건수 | 의미 |
| --- | ---: | --- |
| 검토 후보 | 3 | SOXL·SOXX·가상 국내 주식의 메타데이터 검사 통과 |
| 제외 | 2 | 사용자 제외 단일종목 레버리지 예시·거래정지 예시 |
| 확인 대기 | 2 | 요구 예탁금 누락·자료 만료 예시 |
| 미래 자료 | 1 | 기준 시점 후보 목록에는 종목 자체를 포함하지 않음 |

입력 8개 중 기준 시점 결과 항목은 7개다. 결과는 `data/catalog-checks/시각-고유ID.json`에 매번 새 파일로 저장한다. 기존 결과·입력 파일·SQLite 실험을 덮어쓰지 않는다. 결과 JSON의 `items`에서 상태와 사유 코드를, `reasonDescriptions`에서 한국어 설명을 확인한다.

알 수 없는 모드/LIVE 설정, 인자 누락·초과, 읽기/JSON/스키마 오류, 원본 정책 불일치는 종료 코드 1로 실패한다. 분류 결과에 제외나 확인 대기가 있다는 이유만으로 명령 실행 실패가 되지는 않는다. 오류 시 원문 입력·OS 오류·파일 경로를 표준 오류로 노출하지 않는다.

## 입력 계약

실행 스키마는 [catalog-schema.ts](../src/core/catalog-schema.ts)다. 모든 키는 필수이며 추가 키는 거절한다. 정보가 불명확할 때는 아래의 명시적 null/UNKNOWN을 사용한다. 키 자체 누락이나 잘못된 형식은 파일 전체를 거절하며 일부 행을 조용히 버리지 않는다.

| 범위·필드 | 계약 | 처리 |
| --- | --- | --- |
| `schemaVersion`, `purpose` | `OFFLINE_CATALOG_V1`, `TEST_ONLY` 고정 | 실제 자료용 모드를 허위로 제공하지 않음 |
| `sourceId` | 1~64자 식별자 | 하나의 자료 공급 계약/네임스페이스. 출처 인증 자체는 미구현 |
| `asOf` | 시간대가 있는 ISO 8601 시각 | 이 시점까지 이용 가능하고 효력이 있는 자료만 판단 |
| `metadataMaxAgeMs` | 명시적 양의 안전 정수 | 메타데이터 신선도의 합성 가정. 샘플 24시간을 실거래 값으로 승계하지 않음 |
| `records` | 최대 50,000행, 빈 배열 허용 | 자원 상한이며 감시 목록 100개와 별개 |
| `instrumentId`, `market` | ID 1~64자, KR/US/UNKNOWN | `market:instrumentId`로 그룹화. ID는 심볼 재사용에도 안정적이어야 하며 같은 시장에서 종목별 고유해야 함 |
| `symbol`, `venue` | 심볼 1~32자, 거래소 식별자 또는 null | 공백 제거·대문자화. 심볼만으로 다른 시장/거래소 종목을 합치지 않음 |
| `currency` | KRW/USD/UNKNOWN | KR·KRW, US·USD의 현 계약을 대조; 불일치는 확인 대기 |
| `kind`, `underlying` | STOCK/ETF/OTHER/UNKNOWN, SINGLE_STOCK/INDEX/UNKNOWN | 자료의 분류를 사용. 심볼 이름으로 상품 구조를 추정하지 않음 |
| `leveraged`, `requiredDepositKrw` | boolean/null, 0 이상 안전 정수/null | 기존 사용자 범위 분류 함수를 재사용 |
| `listingStatus` | LISTED/HALTED/DELISTED/UNKNOWN | 정지·폐지 자료는 신규 검토 대상에서 제외; UNKNOWN은 확인 대기 |
| `brokerSupported` | boolean/null | 공급 자료의 상품 지원 여부일 뿐 실제 계좌의 매수 자격이 아님 |
| `revision` | 종목별 단조 증가하는 양의 안전 정수 | 같은 자료 공급 계약의 정정/상태 변경 번호. 외부 공급원이 이를 보장하는지는 후속 확인 대상 |
| `observedAt`, `receivedAt`, `availableAt` | 관측 ≤ 수신 ≤ 이용 가능 | 신선도는 관측 시각 기준; 미래 이용 가능 자료는 판단에서 제외 |
| `effectiveAt` | 효력 시작 시각 | 알려져 있어도 미래 효력이면 아직 적용하지 않음 |

식별자는 영문·숫자·점·밑줄·하이픈만 허용한다. `instrumentId`와 `sourceId`는 양끝 공백만 제거하고 대소문자를 보존한다. 시장/종류 등 열거형은 명세의 대문자를 그대로 사용한다. 동일 기업의 다른 상장/주식 종류에는 별도 종목 ID가 필요하다. 다중 공급원 ID 자동 매칭, 코드 변경·재상장 계보의 외부 사실 확인은 아직 제공하지 않는다.

시각은 UTC로 정규화하며 밀리초보다 작은 소수부는 거절한다. 작은 미래 시각을 절삭해서 과거에 포함하지 않는다. 비교는 시각 값으로 수행한다. `availableAt`·`effectiveAt`이 `asOf`와 정확히 같으면 포함하고, `asOf-observedAt`이 명시된 유효기간과 같으면 신선도 검사에 포함한다.

## 분류와 정정의 우선순위

1. 엄격한 전체 입력 검증을 먼저 수행한다. 유효하지 않은 미래 행도 형식 검사 실패를 일으킬 수 있다.
2. 기준 시점에 아직 이용할 수 없거나 효력이 없는 행은 판단에서 제외한다. 미래 자료만 있는 종목을 과거 후보로 드러내지 않는다.
3. 시장+종목 ID별로 당시 사용 가능한 가장 높은 revision을 선택한다. 모든 정규화 필드가 같은 중복은 합치고, 최신 동일 revision에 다른 내용이 있으면 상충으로 보류한다. 결측/만료된 최신 행을 이전의 좋은 행으로 대체하지 않는다.
4. 선택된 최신 자료의 시장+거래소+심볼이 다른 ID와 겹치면 관련 항목 모두 확인 대기로 둔다. 상충 버전의 심볼 주장도 충돌 검사에 포함한다. 서로 다른 거래소의 실제 중복 노출까지 해소한 것은 아니다.
5. 시장·거래소·통화·종류·기초자산·레버리지·지원·상장 상태의 결측, 통화 불일치, 보통주 속성 모순, 자료 만료를 확인 대기로 처리한다. 단일종목 레버리지의 요구 예탁금 누락도 확인 대기다.
6. 확인 대기 사유가 없고 사용자 제외 상품, 비지원 상품군, 정지·폐지 또는 브로커 미지원이면 제외한다. 확인 대기와 제외 사유가 겹치면 모든 사유를 보존하되 최종 상태는 확인 대기다. 어느 경우도 검토 후보로 통과하지 않는다.
7. 나머지만 메타데이터 검토 후보로 표시한다. 결과의 ID 정렬은 재현용이며 투자 순위가 아니다.

기존 [연구 범위 정정](../profiles/research-scope-v1.json)에 따라 3천만 원 이상 요구 예탁금의 단일종목 레버리지를 제외하며, 지수형 레버리지라는 이유만으로 SOXL을 제외하지 않는다. 실제 예탁금 사실 확인이나 계좌 조회는 이번 기능에 없다. SOXL의 별도 상품/비용/예측/체결 검증도 면제하지 않는다.

결과의 `decisionHash`에는 당시 항목·설정·원본 정책 해시·연구 범위 해시가 결합된다. `inputHash`는 정규화한 전체 입력(순서 포함)의 감사용 해시다. 유효한 미래 자료/중복/입력 순서를 바꾸면 입력 해시나 진단 개수는 바뀔 수 있지만, 과거 판단 항목이 같으면 판단 해시는 같다. 출처 인증이나 전자서명은 아니다.

## 구현 경계와 후속 작업

- [catalog.ts](../src/core/catalog.ts)는 정규화된 자료를 분류하는 함수이며 계좌·시세·웹·주문 모듈에 연결하지 않았다.
- [catalog-file.ts](../src/server/catalog-file.ts)는 일반 로컬 파일을 최대 16 MiB까지 읽고 UTF-8/BOM을 처리한다. URL·직접 UNC/장치 경로를 거절한다. 이는 OS 네트워크 격리나 재분석 지점/네트워크 드라이브의 전수 차단 보장이 아니다. 신뢰하는 로컬 시험 파일만 사용한다.
- [catalog-check-cli.ts](../src/server/catalog-check-cli.ts)는 모드/정책 확인과 파일 입출력만 담당한다. 키를 읽거나 시세 API를 호출하지 않는다. 파일 `0600` 요청은 Windows ACL 보호 검증을 뜻하지 않는다.
- 가격·120세션 이력·20세션 거래대금·호가 차이 필터는 이 메타데이터 단계에서 평가하지 않는다. `pendingChecks`에 남기며, 원본 수치를 변경/완화한 것이 아니다.
- 시장별 100개 감시 목록과 AI 5개 후보를 선정하는 식, 뉴스·테마 조사, 상품별 프로필, B/P·수량·통화·포트폴리오 위험 검사는 후속 단계다. 100개보다 많은 메타데이터 후보가 나와도 모두 거래 대상으로 승인하는 것이 아니다.
- 전체 시장 범위의 실제 수집·현재 모집단 완전성·과거 생존편향·자료 이용권·실시간 갱신은 미검증이다. SOXL/SOXX의 단일 종목 모드는 계획으로 유지한다.

## 검사 범위

```powershell
npm run build:engine
node --test --test-concurrency=1 dist/runtime/tests/catalog.test.js dist/runtime/tests/catalog-cli.test.js dist/runtime/tests/core.test.js dist/runtime/tests/research-scope.test.js
npm run typecheck
npm run lint
npm run format:check
node node_modules/prettier/bin/prettier.cjs --check fixtures/catalog-v1.json
npm run build
npm run verify:originals
```

새 카탈로그 시험은 순수 분류 검사와 독립 임시 폴더의 실제 CLI 자식 프로세스 검사다. 입력/기존 보고서 보존, LIVE 거절, 잘못된 자료, 미래·신선도 경계, 중복·상충, 의미 없는 순위 생성 방지를 포함한다. 자식 프로세스는 임시 폴더의 정책 복사본과 결과만 사용하며 임시 증거 폴더를 자동 삭제하지 않는다.

실제 실행 결과와 샘플 관찰은 검증 산출물 (로컬 비공개 기록: `work/catalog-verification`)에 보존한다. 전체 제품 회귀 및 웹 E2E를 실행한 것으로 표시하지 않는다. 특히 기존 종료 시험은 공용 연결 코드 파일을 생성하므로 실행 중 사용자 실험에 영향을 주지 않도록 이번 관련 시험 목록에 포함하지 않았다. 의존성 변경은 없고 새 설치 환경의 npm ci 재현은 이번에 수행하지 않았다.
