### 후속 결정: 단일 종목 모드의 첫 후보 (2026-09-12)

사용자 제안에 따라 **SOXL·SOXX를 향후 단일 종목 지정 모드의 첫 구현·검증 후보**로 기록한다. 아직 해당 모드를 구현하거나 두 종목의 자동 거래를 활성화한 것은 아니다.

- 공통 B/P 평가기, 자금·통화·위험·청산·복구 기준은 재사용하고 각 상품의 데이터·벤치마크·비용·예측·체결 프로필과 검증 증거는 구분한다. 한 상품의 시험 통과를 다른 상품에 자동 승계하지 않는다.
- 지정한 종목이라도 필수 설정이나 거래 조건이 부족하면 보류한다. 후보 등록은 수익성 확인·매수 추천·실계좌 자격·주문 승인이 아니다.
- 전체 시장·테마·혼합 운용 범위와 다음 전체 시장 후보 기반 작업은 유지한다. 이번 결정만으로 개발 순서를 단일 종목 모드 우선으로 바꾸거나 전체 시장을 두 종목으로 제한하지 않는다.
- 적용 범위는 계획 문서다. 원본 정책, 연구 범위 JSON, 현재 시세 CLI의 고정 시험 목록, 실행 중인 합성 엔진/DB를 변경하지 않는다.

### 미정 값은 다음처럼 처리

- 운용금·위험도 선택: 런타임 사용자 입력이다. 원본 JSON을 채우는 것이 아니다.
- 실제 비용·지표 정밀도·예측/체결·선정 프로필: 필요한 사용 경로에 앞서 정의해야 한다. 합성 값을 실제 값으로 승계하지 않는다.
- 검증 기록의 빈 목록·미검증 플래그: 실제 시험 결과가 생길 때 별도 증거로 쌓는다. 문서 작성으로 합격 처리하지 않는다.
- 비활성 반대 검토/추가 차트 연구의 null: 사용하지 않는 동안 의도적 미설정이다.
- 실계좌 자격·청산 API 계약: 실거래 승인 범위 밖이다. 모의 준비를 핑계로 조회하거나 실주문을 시험하지 않는다.

중첩 null/빈 배열의 JSON Pointer 목록은 검사 결과에 자동 수록한다. 이 목록의 길이는 결함 수가 아니다. 빈 객체·false·UNVALIDATED 등 모든 미확정 표현을 자동 판독한 목록도 아니다.

세부 구현 순서는 의존성에 따라 일부 겹칠 수 있지만 단계를 끝냈다고 후속 완료 조건을 면제하지 않는다. 2단계는 수집·분류 기반 구현이지 “좋은 종목을 뽑아 수익 낼 기준이 검증됨”이 아니다.

원본 검증 문턱의 주요 예: 목표 과거 36개월, 봉인 구간 6개월, 프로필별 표본 외 청산 거래 200건 이상/거래일 120일 이상, 봉인 청산 50건 이상, PF 1.2 이상, 스프레드·슬리피지 2배 스트레스, 정방향 모의 60거래일 이상/청산 50건 이상. 이는 필요 조건의 일부이며 숫자만 채우면 합격하는 충분 조건이 아니다. 원본 전체 조건 및 위험도별 검증이 우선한다. 이번에 이 성과 검사를 수행하지 않았다.

## 실제 수행한 검사와 과거 근거

이번 실행 명령은 프로젝트 루트 기준이다. 네트워크, 제품 엔진, 사용자 DB를 사용하지 않는다.

```powershell
node --check work/check-phase2-readiness.mjs
node work/check-phase2-readiness.mjs
npm run verify:originals
```

별도 로컬 문서 검사기는 설치된 Markdown 변환기와 headless Edge로 README/이 문서/PROGRESS의 내부 경로 및 렌더링을 점검한다. 이 환경 전용 변환기 경로는 빠른 시작 의존성으로 추가하지 않는다. 검증 산출물 폴더 (로컬 비공개 기록: `work/phase2-readiness`)의 `document-check.json`에 대상과 결과를 기록한다. 외부 요청은 차단하고 실제 GitHub 표시나 기존 미완료 정책 문서 시각 검토를 대신하지 않는다.

과거 근거와 이번 실행을 구분한다.

- [1차 검증 보고](PHASE1_VERIFICATION.md): 당시 전체 108개 단위/통합 및 2개 E2E, 별도 정책 정적 248개. 이번에 재실행하지 않았다.
- [시세 연결 안내](TOSS_MARKET_CHECK.md): 당시 집중 85개와 CLI 시작 거절 4개 및 짧은 실제 시세 수신. 이번에 토큰 발급·API 호출·85개 재실행을 하지 않았다.
- 사용자 합성 실험 기록 (로컬 비공개 기록: `work/phase1-verification/user-trial-20260911.json`): 당시 합성 매수/청산·장부 대조. 현재 실행 중 상태를 새로 확인한 것은 아니며 실시장 성과가 아니다.

검사 로그 존재는 현재 제품 전체 회귀 성공을 뜻하지 않는다. 이번 신규 검사 결과는 인벤토리·원본 보존·문서 정합성으로 한정한다. 보안 전수 감사·네트워크 장애·실시간 장기 운영·투자 성과·실계좌 자격은 미검증이다. 원본 위험 숫자·전략 수치 및 실제 서버/계좌 상태를 수정하지 않았다.
