# Codex 분석 · 로컬 모형 연결

합성 자료를 사용해 **요청 → 자료 확인 → 승인 → 모형 실행 → 결과 검증** 절차를 시험합니다. 실제 Codex/GPT가 분석하는 기능이 아닙니다. 이번 단계의 결과로 매수·매도·정책 변경·모델 교체를 하지 않습니다.

## 현재 제공 범위

다종목 화면의 `Codex 분석 · 모형` 메뉴, 해시 결합 승인, 전용 SQLite 기록, 결정적 로컬 모형 함수, 구조화된 결과 검증을 제공합니다. 실제 거래 엔진의 반대 심사(SHADOW/GATED)나 학습 모델에 연결하지 않습니다. 원본 LLM 주문/정책 편집 금지·검증 문턱과 실거래 잠금을 유지합니다.

새 웹 시작 경로에서는 [제한된 별도 모형 프로세스](ANALYSIS_MOCK_PROCESS.md)를 사용합니다. 승인에 실행 코드 해시/버전도 결합합니다. Windows·Node 24.20.0 조건이 맞지 않으면 분석만 비활성화하며 기존 함수로 자동 전환하지 않습니다. 아래 자료·승인·결과 계약은 유지되고 기존 함수형 모형은 호환 시험용으로 남습니다.

기존 `SYNTHETIC_REVIEW_FIXTURE_V1`은 TEST_KR_A, 2026-09-10 00:00~01:00 UTC, 판단 4·승인 판단 1·확정 청산 0의 작위적인 예시입니다. 후속 [모의 기록 연결](ANALYSIS_RECORDS.md)은 명시적으로 기록한 합성 엔진 실행을 읽기 전용 대조하고 선택 기간의 최소 자료/통화별 집계를 제공합니다. 사용자 임의 파일·자유 질문·뉴스 업로드·실거래 DB·실제 외부 전송은 지원하지 않습니다.

## 실행과 정상 확인

프로젝트 루트에서 기존 [Node/npm 환경과 설치](../README.md#실행-환경)를 사용합니다. 의존성이 없을 때만 `npm ci --ignore-scripts`가 필요합니다. 새로운 라이브러리·키·외부 로그인은 필요 없습니다. 기록 루트의 선택 설정은 [기록 연결 안내](ANALYSIS_RECORDS.md#저장설정검증-경계)를 참고하세요.

```powershell
npm run build
npm run portfolio:web
```

1. `http://127.0.0.1:4184/?view=portfolio`에 접속하고 서버 출력에 안내된 로컬 코드 파일로 로그인합니다. 토스/OpenAI 키를 입력하지 않습니다.
2. **Codex 분석 · 모형** → **합성 자료로 분석 요청 만들기**를 누릅니다. 모의 자금 배정·매매 시작은 필요 없습니다. 이때 호출 수는 0입니다.
3. `전달 예정 자료 전체 보기 (JSON)`를 펼칩니다. 자료와 정책/요청 해시, 전달 대상, 금지 권한, 한도를 확인하고 두 동의를 체크합니다. 버튼만 열었다고 실제 내용을 이해했음을 기술적으로 보장하지는 않습니다.
4. **이 자료의 모형 전달 승인**을 누릅니다. 아직 호출 수는 0입니다. **승인된 모형 1회 실행**을 별도로 눌러야 로컬 모형이 실행됩니다.
5. 정상 결과는 **모형 결과 검증 통과**, 모형 호출 1·외부 호출 0·추가 AI 토큰 0입니다. 이는 자료 일치/형식 검사 결과이지 투자 판단 능력이나 수익성 평가가 아닙니다.

실행 중인 구버전 서버는 자동 교체하지 않습니다. 기존 보유/미체결을 확인하고 [저장·종료 안내](PORTFOLIO_WEB.md#중지청산복구)를 따른 뒤 다시 빌드/시작하세요. 기본 주소 충돌 시 [전용 루트/포트 설정](PORTFOLIO_WEB.md#실행)을 이용할 수 있습니다. 이번 작업은 사용자 서버를 재시작하지 않았습니다.

## 승인·실행·복구 계약

| 단계/상태 | 동작 |
| --- | --- |
| AWAITING_APPROVAL | 고정 자료·ID·생성/만료 시점·정책 해시·모형/파서/프롬프트 버전·권한·한도에 요청 해시를 결합. 승인 전 실행 불가 |
| APPROVED | 두 명시 동의와 정확한 요청 해시 필요. 요청 생성 후 5분 안에 승인과 실행 시작 모두 필요. 자료 수정 API 없음 |
| RUNNING | 먼저 호출 1회를 원자적으로 기록하고 실행. 요청당 1회·3초·재시도 0. 한 번에 활성 요청 1개 |
| VERIFIED_MOCK | 엄격한 스키마·요청 ID/해시·자료 해시·기준 시점·생성 시점·출처/관측 시각·세 수치를 대조. 제안 코드 두 종류만 허용 |
| REJECTED / FAILED / TIMED_OUT | 부적합 결과·모형 오류·시간 초과. 자동 재시도/다른 모델 또는 API 키 전환 없음. 같은 실행 요청은 저장 상태 조회만 수행 |
| CANCELLED / EXPIRED | 실행 전 취소/만료는 호출 0. 실행 중 취소는 결과 폐기, 이미 시작한 모형 호출 1은 남김. 이미 보낸 자료/사용량을 되돌리는 기능은 아님 |
| INTERRUPTED | 비정상 종료 후 실행 중 기록은 중단으로 복구. 승인 대기/승인 완료도 취소 처리하며 자동 재개하지 않음. 다시 하려면 새 요청과 새 승인이 필요 |

브라우저 새로고침은 승인/호출 수를 초기화하지 않습니다. 응답 유실 시 **분석 동일 요청 재확인**은 동일 ID/내용을 재사용합니다. 수신 지연 시 화면 승인을 차단합니다. 승인은 이 합성 모형 요청 전용이며 향후 실제 외부 전송 허가로 재사용할 수 없습니다.

기록 전용 요청은 위 검사에 더해 선택 기간의 통화별 집계·근거 목록을 정확히 대조하고 승인/실행/결과 반영 직전에 보관 스냅샷을 재검증합니다. 최신 원본이나 다른 기간으로 변경하려면 새 요청과 새 승인이 필요합니다. 자세한 범위/한도는 [기록 연결 계약](ANALYSIS_RECORDS.md)을 따릅니다.

호출 카운트는 실행 예약을 커밋한 횟수입니다. 커밋 직후 프로세스가 죽으면 실제 함수 시작 여부를 확정할 수 없으므로 1회로 보수적으로 남깁니다. 저장소 오류 시 호출 수는 0으로 오인하지 않도록 미확인(null) 처리합니다.

## 저장·안전 경계

기본 전용 파일은 `data/portfolio-web/codex-analysis/mock.sqlite`입니다. `PORTFOLIO_WEB_ROOT`를 지정하면 그 폴더 아래에 생성됩니다. 거래/학습 DB와 분리되어 있으며 초기 상태에는 분석 요청이 없습니다. 기존 실행 폴더에 추가되는 별도 파일이고 기존 거래 DB를 이관하지 않습니다.

- 전용 SQLite application ID·버전, 엄격한 입력/저장 스키마, 상태 해시·사건 해시 연결·최종 상태 연결을 검사합니다. 상태와 사건을 같은 트랜잭션에 커밋합니다.
- 단일 프로세스 소유권과 PID 생존 검사로 동시 writer를 막습니다. 비정상 종료 후 죽은 소유자만 교체합니다. PID 재사용/권한 오류로 생존 여부를 확정할 수 없으면 보류합니다. 자동 강제 소유권 탈취 기능은 없습니다.
- 최대 요청 100개·사건 500개·상태 본문 4MiB·기존 DB 8MiB·HTTP 입력 8KiB·모형 출력 16KiB입니다. 초과 시 보류하고 오래된 기록을 자동 삭제하지 않습니다. 운영 장기 보관/아카이브는 미구현입니다.
- 허용 목록으로 구성한 자료만 전달합니다. 기존 순수 모형 함수에는 네트워크·파일·명령·계좌·모델 SDK 호출이 없습니다. 새 별도 프로세스는 승인 JSON만 stdin으로 받고 시작 시 더미 파일/명령 접근 등의 거절을 자체 검사합니다. 이 제한 검사는 실제 키를 읽지 않으며 모형 계산과 구분합니다. 시험 주입점은 코드 수준이고 HTTP로 실행 코드를 교체할 수 없습니다.
- 결과 원문은 16KiB 이하일 때만 보존하며, 구조화된 검증 결과와 결과 해시를 별도로 저장합니다. 큰 출력은 원문 저장 없이 거절합니다. 실행 예외의 임의 본문/스택은 반환하지 않고 오류 코드만 남깁니다.
- 인증된 로컬 세션·정확한 Host/Origin·POST CSRF·JSON/크기 제한을 적용합니다. UI는 React 텍스트로 렌더링하며 모델 HTML/코드를 실행하지 않습니다.
- 분석 오류는 이 기능만 보류합니다. 거래 장부 쓰기 경로를 전달하지 않으며 기존 예측 누락 진입 차단과 보유 위험관리를 대신하지 않습니다.

해시는 변조 탐지/연결 확인 수단이지 서명·외부 출처 진위 인증이 아닙니다. 같은 PC의 관리자/파일 소유자가 DB·사건·해시를 일관되게 다시 쓰는 공격, 링크 경합/하드링크/OS ACL 전수·디스크 암호화는 해결했다고 주장하지 않습니다. 권한 false 값 자체도 OS 샌드박스가 아닙니다. 현재 고정 모형의 프로세스 분리·Node/모듈/API 제한은 실제 에이전트의 OS 파일/명령/네트워크 격리를 대신하지 않습니다.

## 로컬 API

기본 URL은 `http://127.0.0.1:4184`입니다. `GET /api/codex-analysis`는 인증 후 전체 요청 목록과 모형 호출 수를 반환하고, `POST /api/codex-analysis`는 `create/create-record/approve/run/cancel`을 받습니다. 기록 선택용 `/api/codex-records`는 [별도 안내](ANALYSIS_RECORDS.md#로컬-api와-검사)를 따릅니다. POST는 같은 Origin, 로그인 쿠키, 세션에서 받은 `x-csrf-token`과 `Content-Type: application/json`이 필요합니다. 입력 계약은 [스키마](../src/core/codex-analysis-schema.ts), 처리/검증은 [서비스](../src/server/codex-analysis-service.ts)와 [검증기](../src/core/codex-analysis.ts)에 있습니다.

아래는 합성 요청 생성 본문입니다. 새 요청은 새 UUID를 생성하고, 응답 유실 재확인은 같은 UUID를 사용합니다.

```json
{
  "type": "create",
  "id": "8f976e25-05bf-4e38-a2fa-7406a7137e01",
  "dataset": "SYNTHETIC_REVIEW_FIXTURE_V1"
}
```

정상 HTTP 200 응답은 `mode=MOCK_ONLY`, `jobs`의 새 항목 `state=AWAITING_APPROVAL`, `mockCalls=0`, `externalCalls=0`, `automaticApplication=false`를 포함합니다. 다음 요청에는 이 응답의 `request.id`와 `requestHash`를 그대로 사용합니다. 인증 전 401, Host/Origin/CSRF 거절 403, 스키마/상태/승인 충돌 409, 분석 미제공/저장·정책 장애 503입니다. 오류는 `{ "error": "ANALYSIS_APPROVAL_REQUIRED" }` 같은 코드 형태이며 임의 예외 본문을 반환하지 않습니다. 승인 체크가 있어도 거래 API 호출 권한을 새로 부여하지 않습니다.

## 개발 검증

기존 설치 상태의 프로젝트 루트에서 실행합니다. 아래 시험은 새 임시 DB/서버만 사용하며 사용자 실행을 열지 않습니다.

```powershell
npm run typecheck
npm run lint
npm run format:check
npm run build
node --test --test-concurrency=1 dist/runtime/tests/codex-analysis.test.js dist/runtime/tests/codex-analysis-http.test.js
npm run test:e2e -- tests/browser/codex-analysis.spec.ts
npm run verify:originals
```

개별 자동 검사는 미승인 0·해시 불일치·임의 필드/자료·시점/숫자/출처/출력·중복·취소·만료·3초 watchdog·실패·자식 비정상 종료·저장 변조·동시 소유·한도·통신/자격증명 경로 가드·HTTP 인증·기존 위험관리 격리를 다룹니다. 브라우저는 이 PC의 headless Microsoft Edge 대상이며 사용자 클릭 대행이 아니라 격리 시험입니다. 실제 결과와 초기 실패/수정 이력은 [PROGRESS · 공개 요약](PROJECT_STATUS.md)에 기록합니다.

## 미검증·다음 작업

실제 Codex 로그인/구독 사용량·공식 프로토콜 호환성·모델 성능/문장 진실성/프롬프트 주입 대응·실자료 권리/비용·실제 거래 기록 최소 추출·계좌/실주문·수익성·새 PC 설치·OS/실제 전원/디스크 고장·장기 처리 성능/동시 브라우저 전체는 미검증입니다. 모형 사용량 0은 실제 Codex 비용이 항상 0이라는 뜻이 아니며 구독비 배분 규칙도 정하지 않았습니다.

초기 설계와 후속 작업에서 OpenAI Docs 스킬로 [공식 App Server 인터페이스](https://learn.chatgpt.com/docs/app-server)를 확인했습니다. 자체 `LOCAL_MOCK_*`는 내부 자료 계약이며, 후속 [프로세스 통신 모형](ANALYSIS_MOCK_PROCESS.md)은 공식 문서의 제한된 줄바꿈 JSON 순서만 구현합니다. 실제 설치된 App Server의 전체 호환 시험이 아닙니다. 실제 에이전트 OS 격리·인증/통신 검증은 남아 있으며, [연결 계획](CODEX_ANALYSIS_PLAN.md)에 따라 실제 연결/전송은 별도 명시 승인 후 진행합니다.
