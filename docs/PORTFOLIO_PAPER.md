# 오프라인 다종목 통합 모의매매

`portfolio:run`은 TEST_ONLY 다종목 차트 신호를 공용 위험/경제성 심사, 통화별 가상 자금, SQLite 모의 주문·체결에 연결하는 독립 CLI입니다. 웹 앱·실계좌·실시간 시세·AI 서비스에는 연결하지 않습니다. 실제 투자 선정식이나 수익성 검증 프로그램이 아닙니다.

후속 [기록 전용 실행](PAPER_LEARNING_BRIDGE.md)의 `portfolio:record`는 같은 엔진/계획에 명시적 학습 기록을 켜고 새 DB에 실행합니다. `portfolio:run`과 기존 웹은 자동 활성화하지 않으며, 기록 없는 과거 DB를 소급 변환하지 않습니다.

## 실행

프로젝트 루트, README의 기존 설치 환경에서 실행합니다. 새 설치나 외부 서비스가 추가되지 않았습니다. PowerShell 예시입니다.

```powershell
npm run build:engine
if ($LASTEXITCODE -ne 0) { throw '엔진 빌드 실패' }
$replaySample = node dist/runtime/src/server/signal-replay-sample-cli.js | ConvertFrom-Json
if ($LASTEXITCODE -ne 0) { throw '신호 시험 입력 생성 실패' }
$portfolioSample = node dist/runtime/src/server/portfolio-sample-cli.js $replaySample.manifestPath | ConvertFrom-Json
if ($LASTEXITCODE -ne 0) { throw '모의매매 시험 입력 생성 실패' }
npm run portfolio:run -- $portfolioSample.planPath
```

이미 생성한 신호 재생 매니페스트가 있다면 `npm run portfolio:sample -- <매니페스트 경로>`로 마지막 두 단계를 시작할 수 있습니다. `<매니페스트 경로>`는 `replay:sample`의 실제 `manifestPath` 출력으로 대체합니다. 예측 설정이 TEST_ONLY인 기본 KR 샘플은 두 종목·두 판단 시점과 이후 명시적 고정 호가를 사용합니다. 매수 승인 2건, 모의 주문 4건(매수 2·매도 2), 잔여 보유/미체결 0건이 기대 결과입니다. 고정 가격의 왕복 수수료 때문에 손익은 음수이며 수익성 결과로 해석하지 않습니다.

입력 복사본은 `data/portfolio-paper-inputs/sample-…/`, 실행마다 새 DB와 보고서는 `data/portfolio-paper-runs/run-…/`에 생성됩니다. 기존 파일을 덮어쓰지 않습니다. 정상 출력의 `databasePath`와 `reportPath`를 확인하세요. `OFFLINE_PORTFOLIO_COMPLETE`는 **주어진 명령 처리가 끝났다는 뜻**이며 `openPositions`·`pendingOrders`가 0인지 별도 확인해야 합니다.

종료 코드 1/`PORTFOLIO_RUN_FAILED`는 성공이 아닙니다. DB 생성 뒤 실패했다면 가능한 경우 같은 폴더에 `failure.json`과 마지막 커밋 상태가 남습니다. 미체결·보유를 자동 삭제하거나 실패한 주문을 재전송하지 않습니다. 보고서 저장 자체가 실패할 수 있으므로 성공 출력이 없으면 완료로 판단하지 마세요.

## 입력 계약과 안전 경계

- `OFFLINE_PORTFOLIO_PLAN_V1`: `purpose=TEST_ONLY`, 같은 폴더의 `replayFile`, 정규화된 전체 재생 입력의 SHA-256 `replayInputHash`, `settings`, `commands`입니다. URL·상위 경로·외부 결과의 성공 플래그는 받지 않습니다. 파일별 읽기 상한 16 MiB, 명령 상한 10,000개입니다.
- 재생 원본은 [신호 재생 계약](SIGNAL_REPLAY.md)을 따릅니다. 저장된 차트 신호를 주문 허가로 신뢰하지 않고 카탈로그·보강·가격/호가/봉·120세션·시점별 이력·B/P를 다시 평가합니다. 입력 계산은 DB 임대 획득 전에 수행합니다.
- `settings.syntheticProfileHash`는 [기존 합성 프로필](../profiles/synthetic-v1.json) 전체의 정규화 해시입니다. 기존 시험 비용·예측·체결·호가 단위·환율 가정을 명시적으로 결합합니다. null/변경은 ABSTAIN입니다. 실제 비용/예측 프로필의 빈칸을 채우지 않습니다.
- `candidateOrder`는 모든 시험 종목의 `시장:instrumentId` 배열이며 중복/누락/알 수 없는 종목을 거절합니다. `candidateOrderMeaning=TEST_SEQUENCE_NOT_INVESTMENT_RANKING`을 요구합니다. 순서가 null이면 보류합니다. 수익률·AI 점수로 정한 우선순위가 아니며 B/P 동시 신호도 기존대로 보류합니다.
- `config`는 기존 운용금·USD 배정금·LOW/MEDIUM/HIGH·PILOT/STANDARD·예측 설정을 재사용합니다. 이 경로의 컨테이너 필드는 `mode=PAPER`, `scenario=B`, `market=KR`로 고정하지만 **실제 시험 대상의 시장/통화/세션은 각 자산 계약과 주문 스냅샷에서 읽습니다**. 모든 종목을 B 전략이나 KR로 취급한다는 뜻이 아닙니다.
- 각 `tick`은 명시적 가상 시각 `at`, 장부 관측 `accountAt`, 시험 환율 `fx.rate/at`, 종목별 출처/공개 시각/호가/잔량/직전 1분 거래량을 제공합니다. `frameAsOf`가 현재 시각과 일치할 때만 해당 시점 신호를 심사합니다. 진입 호가는 사전점검에서 선택한 원시 호가·거래량과 대조합니다.
- 실제 환전은 없습니다. USD 현금이 부족하면 KRW로 대신 매수하지 않습니다. 전체 현금·보유·미체결 예약은 KRW 환산 공통 한도로 심사하고, 노출은 기존의 보수적 단일 위험군으로 합산합니다. 종목 추가 매수/물타기는 차단합니다.

## 주문·보호·저장

공용 `approveEvaluation`은 기존 엔진의 승인 계산을 분리한 함수입니다. B/P 조건과 원본 수치를 바꾸지 않고 반올림·위험 수량·비용·합성 예측·경제성·스냅샷·예약을 재사용합니다. SQLite `BEGIN IMMEDIATE` 안에서 최신 상태를 읽고 후보 순서대로 예약하므로 먼저 예약된 금액을 다음 후보가 사용할 수 없습니다. 접수 직전에도 현재 입력을 재검사하며 승인 후 한도나 수량 조건이 변하면 보수적으로 거절할 수 있습니다.

모의 체결은 기존 지정가 시뮬레이터에 종목별 호가를 전달합니다. 이전 명령에서 저장한 의도만 다음 시각에 접수하고, 그 이후 실행 가능한 호가·잔량에서 부분 체결합니다. 다른 종목의 호가·세션·통화로 체결하거나 OHLC 접촉만으로 체결하지 않습니다. 부분 체결된 보유와 그 종목의 미체결 매수는 하나의 보유 슬롯으로 집계하도록 공용 가드를 정정했습니다. 보유·예약 위험 자체는 모두 합산합니다.

취소 요청 후 최종 확인 전 추가 체결을 허용하는 시험 모형이며, 최종 취소/체결 전에 예약을 해제하지 않습니다. `pause`는 신규 진입 중지·매수 취소, `liquidate(confirm=true)`는 봇 귀속 보유의 청산 요청입니다. 즉시 전량 매도 보장은 없으며 이후 호가가 필요합니다. 미체결 손절·UNKNOWN·잔여 보유를 완료로 표시하지 않습니다. 기존 모형대로 한 종목의 청산 요청도 다른 미체결 진입을 취소할 수 있습니다.

노출 중 가상 시각은 최대 1초씩 진행해야 하며 시각 건너뛰기는 거절합니다. 호가 누락/만료나 장부·환율 시점 오류는 신규 진입을 보류합니다. 모든 보유의 현재 bid를 먼저 표시한 뒤 종목별 주문을 처리합니다. 가상 결제는 명시적 시험 단계에서 처리하며 실제 T+N 결제 제도와 다릅니다.

매 명령에서 통화별 원금±누적 체결대금/수수료와 순현금, 누적 매수−매도와 보유 수량, 미체결 수량과 현금/위험 예약, 스냅샷/종목/통화 연결을 대조합니다. 오류 시 해당 트랜잭션 전체를 롤백합니다. 명령 ID는 입력 해시에 묶고 신호는 시장·종목·봉 시각에 묶어 epoch 변경 후에도 중복 승인하지 않습니다.

## 재시작과 제한

2026-09-14 추가: 같은 다종목 엔진을 사용하는 [독립 웹 화면](PORTFOLIO_WEB.md)을 제공한다. 웹에서 만든 합성 실행만 복구하며 이 CLI의 임의 DB를 직접 여는 기능은 없다. 아래 사용자용 웹 화면 미구현 설명은 2026-09-13 CLI 검증 당시의 상태다.

`PortfolioPaperEngine`의 명시적 `resume`은 같은 실행 해시의 전용 DB만 읽기 전용 사전 대조 후 재개합니다. 처음 상태는 RECONCILING이고 자동 RUNNING이 아닙니다. 미제출 의도는 취소하며 이미 접수된 주문은 취소 확인까지 예약을 유지합니다. 이후 호가로 취소/부분 체결을 대조하고 `reconcile`·`start`를 명시해야 합니다. UNKNOWN은 자동 해결하지 않습니다. **이 복구 API는 격리 시험으로 검증했지만 사용자용 재개 CLI·웹 복구 화면은 아직 없습니다.** `portfolio:run`을 다시 실행하면 새 독립 실험이 만들어지며 이전 DB를 이어 쓰지 않습니다.

1회 실행은 종목별 1개 선언 세션으로 제한합니다. 알려진 장중 기업행동 예정이 있으면 새 진입을 보류하고, 보유/미체결 중 효력이 발생한 기업행동이 확인되면 자동 수량 조정·체결을 잠그고 미해결로 남깁니다. 이 경로에 기업행동 후 보유 대조/잠금 해제 기능은 없습니다. 과거 이력의 시점별 분할 조정과 보유 중 기업행동 회계는 다른 문제입니다.

아직 제공하지 않는 범위는 실제 전 시장 수집, 뉴스·테마/추천 선정, 실제 예측 모델·수익성, 실계좌 자격/잔고·실주문, 다일 보유/배당 회계, 웹 UI 연결·자동 타이머·장기 운영입니다. 실제 자료·이용 조건/비용 확인은 별도 과제이며 이 CLI 실행이 그 승인을 대신하지 않습니다. 새 설치·전체 앱 E2E·실제 전원 차단/디스크 장애·OS 격리·실제 주문 정확성을 이번 시험으로 검증했다고 주장하지 않습니다.

## 개발 검증

```powershell
node work/verify-portfolio.mjs
```

기존 설치에서 타입·린트·형식·엔진 빌드, 명시적으로 열거한 관련 시험, 웹 빌드와 원본 37개 보존을 확인하고 `work/portfolio-verification/<실행 시각>/report.json`에 기록합니다. 전체 `npm test`나 사용자 앱 E2E를 실행하는 명령은 아닙니다. 강제 종료 시험은 자신이 만든 별도 자식 프로세스와 임시 SQLite만 대상으로 합니다. 합성 모의 성공은 실제 투자 위험이나 수익을 보장하지 않습니다.
