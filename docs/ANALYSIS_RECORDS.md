# 모의 엔진 기록으로 분석 준비

기록 전용 합성 모의 실행의 판단·체결·비용·청산을 읽어 선택 기간의 최소 자료를 분석 승인 화면에 연결합니다. 고정 예시와 달리 엔진 장부를 대조한 수치입니다. 여전히 로컬 모형이며 실제 Codex·시장·계좌·주문·수익성 향상과 연결하지 않습니다.

새 다종목 서버는 승인에 코드/실행 버전을 함께 묶고 [별도 모형 프로세스](ANALYSIS_MOCK_PROCESS.md)에 최소 JSON만 전달합니다. 원본 스냅샷/DB는 자식에 넘기지 않습니다. Windows·Node 24.20.0 전용 제한이며 실제 Codex나 OS 샌드박스는 아닙니다. 아래 기간·집계·원본 대조 계약은 변경하지 않습니다.

## 사용 순서

[README 환경과 설치](../README.md#실행-환경)가 먼저 필요합니다. 기존 의존성을 사용하며 키나 추가 패키지는 필요 없습니다. 프로젝트 루트에서 `npm run build` 후 `npm run portfolio:web`를 실행합니다. 실행 주소·코드·저장 종료는 [다종목 안내](PORTFOLIO_WEB.md)를 따릅니다. 기존 서버는 자동 교체되지 않습니다.

1. 기록이 없다면 [새 기록 전용 모의 실행](PAPER_LEARNING_BRIDGE.md#1-새-기록-전용-모의-실행)의 합성 생성/기록 명령을 먼저 실행합니다. `PAPER_LEARNING_RECORDED`와 새 `databasePath`를 확인합니다. 학습 변환·등록은 분석에 필요 없습니다.
2. 웹에 로그인하고 **Codex 분석 · 모형** 메뉴를 엽니다. `기록 전용 실행`에서 원하는 `run-...`를 고릅니다. 목록은 폴더 이름만 읽으며 DB를 열지 않습니다. 새 CLI 실행 후에는 메뉴를 다시 열어 목록을 갱신합니다.
3. **선택 기록 읽기 전용으로 가져오기**를 누릅니다. 선택 DB의 장부/감사/명령/체결을 검증하고 별도 로컬 스냅샷을 만듭니다. 원본 DB를 이관하거나 재생하지 않습니다. 이때 모형 호출은 없습니다.
4. 스냅샷 범위 안에서 시작/종료를 UTC ISO 문자열로 입력합니다. 예: `2026-09-10T01:00:00.000Z`. **이 기록·기간으로 분석 요청 만들기**를 누릅니다. 빈 기간/잘못된 시각/한도 초과는 거절합니다.
5. 집계·판단별 내역 및 `전달 예정 자료 전체 보기 (JSON)`을 확인합니다. 두 동의 → **이 자료의 모형 전달 승인** → **승인된 모형 1회 실행** 순서입니다. 기존 [승인·만료·복구 계약](CODEX_ANALYSIS_MOCK.md#승인실행복구-계약)을 유지합니다.
6. 정상 결과는 `모형 결과 검증 통과`, `LOCAL_MOCK_RECORD_RESULT_V1`, 선택 자료와 같은 집계/근거 해시입니다. 호출은 요청당 1회, 외부 호출 0이며 거래·정책·모델 자동 적용은 없습니다. 새로고침/서버 재시작 후에도 완료 결과를 조회합니다.

현재 선택은 기록 CLI의 `run-.../paper.sqlite`만 지원합니다. 기존 웹 실험의 자동 기록·과거 DB 소급 변환·임의 파일 업로드·임의 경로 입력·뉴스 원문·자유 질문은 지원하지 않습니다.

## 기간과 손익의 의미

선택 규칙은 `DECISION_COHORT_INCLUSIVE_AS_OF_EVENTS_V1`입니다. 시작과 종료 시각 사이에 발생한 **판단**만 고르고, 그 판단에 연결된 체결/청산 중 종료 시각 이하의 사건만 집계합니다. 양 끝은 포함합니다. 기간 이전 진입이 기간 중 청산되더라도 포함하지 않습니다. 따라서 계좌 일별 손익·잔고·수익률이 아닙니다.

제외 판단/체결 수도 종료 시각까지 알려진 사건만 셉니다. 전체 스냅샷의 최종 해시/버전/시각은 출처 추적 정보이며 과거 시점의 예측 특성이 아닙니다.

| 상태 | 처리 |
| --- | --- |
| ABSTAIN | 진입 보류. 완료 거래나 수익 0으로 바꾸지 않음 |
| NO_FILL_AS_OF | 승인 판단은 있으나 종료 시점 매수 체결 없음. 최종 취소 여부를 미래 상태로 추정하지 않음 |
| OPEN_OR_UNRECONCILED | 일부 체결/미청산/최종 대조 미확정. 확정 손익 null |
| CLOSED_RECONCILED | 종료 시점까지 체결 수량·대금·수수료·청산 사건 대조 완료 |
| COST_UNRESOLVED | 청산은 대조됐으나 운영비 배분 미정. 확정 순손익으로 내놓지 않음 |

금액은 `decimal.js`로 계산하고 문자열로 보존합니다. KRW/USD를 따로 집계하며 서로 합산하지 않습니다.

```text
청산 grossPnl = 매도 체결대금 합 - 매수 체결대금 합
청산 netAfterRecordedFees = grossPnl - 매수/매도 체결 시 인식한 fee 합
```

미청산 대금/인식 수수료는 표시하지만 확정 청산 손익에 합치지 않습니다. 해당 통화에 대조 완료 청산이 없거나 청산 중 비용 미확정이 있으면 합계는 null입니다. 미국 거래는 원화 환산 `netPnl`을 달러 값으로 복사하지 않습니다.

종료 시각 이하 운영비 사건이 있으면 `paid`와 무관하게 배분 미확정으로 남깁니다. 미래 비용이나 구독비를 임의 배분하지 않습니다. 스프레드는 체결가에 반영됐으며 예상 adverse buffer를 실제 비용으로 다시 차감하지 않습니다. 체결 fee는 합성 장부 값으로 실제 세금·환전·운영 총비용 검증이 아닙니다.

## 전달 자료와 제외 자료

모형에는 다음 허용 필드만 담은 `ENGINE_RECORD_ANALYSIS_BUNDLE_V1`을 전달합니다.

- 실험/내보내기/장부/감사/정책 해시, 스냅샷 시각·버전, 선택 기간과 제외 수.
- 판단·종목의 해시 별칭, 시장·통화·B/P·판단 시각/결과, 계획 수량·진입/손절 가격.
- 조건 통과/실패/누락/해당 없음과 사유의 개수, 체결 수/수량/대금/fee, 청산 시각·상태·손익.
- 미청산·운영비 미확정 및 합성 자료의 한계 표시.

계좌 식별자·파일 경로·폴더 이름·증권/AI 키·원본 주문/포지션 ID·종목명 원문·자유 텍스트 사유·trace 원문·원본 봉/뉴스는 전달하지 않습니다. 해시 별칭은 완전 익명화가 아닙니다. 조건/사유 개수는 원문의 의미나 진실성을 검증한 값이 아닙니다. 현재 분석은 기계적 기록 대조이며 뉴스 해석·차트 전체 재계산·최적 매매 규칙 제안이 아닙니다. RVOL 독립 재계산은 별도 [학습 변환 경로](LEARNING_RVOL_SOURCE.md)에서 수행합니다.

전체 원본 내보내기는 서버의 전용 로컬 아카이브에만 보존합니다. 이 파일에는 원래 자유 텍스트/메타데이터가 포함될 수 있으므로 공유하지 마세요. 모형 입력 JSON과 전체 아카이브를 혼동하지 않습니다.

## 저장·설정·검증 경계

| 설정/파일 | 기본값과 역할 |
| --- | --- |
| `PORTFOLIO_RECORDS_ROOT` | 선택, 비밀값 아님. 기본 `data/paper-learning-runs`; 읽을 기록 전용 루트. 안전한 예: `data/my-paper-records` |
| `PORTFOLIO_WEB_ROOT` | 기존 선택 설정, 기본 `data/portfolio-web`; 웹·분석 저장 위치 |
| `codex-analysis/sources/<exportHash>.json` | 웹 루트 아래 원본 스냅샷. 같은 해시는 재사용, 정상 파일 자동 삭제 없음 |
| `codex-analysis/mock.sqlite` | 요청/승인/최소 자료/결과/사건 전용 저장소. 거래 DB와 별개 |

서버 시작 전 PowerShell의 `$env:PORTFOLIO_RECORDS_ROOT = 'data/my-paper-records'`처럼 지정합니다. `.env` 자동 로딩이나 브라우저에서 루트 변경은 없습니다. 명시적으로 기록한 합성 실행만 있는 로컬 폴더를 사용하세요.

1. 기존 `exportPaperLearning`의 읽기 전용/query-only 트랜잭션으로 장부·감사/명령 체인·기록을 대조합니다. 기존 `verifyPaperExport`로 체결/비용/청산과 정책 결합을 검사합니다.
2. 내보내기를 해시 이름으로 고정하고 최소 자료를 생성합니다. 임시 파일 독점 생성·fsync 후 게시합니다. 실패한 `.partial`도 자동 삭제하지 않습니다.
3. 승인 직전, 실행 직전, 결과 반영 직전에 보관 스냅샷에서 같은 기간 자료를 재계산해 비교합니다. 변경/누락 시 보류합니다. 실행 전 실패는 호출 0, 실행 중 실패는 호출 1·결과 미반영입니다.
4. 원본 실행 DB가 진행돼도 승인 스냅샷을 최신값으로 바꾸지 않습니다. 최신 기록/다른 기간은 다시 가져와 새 요청/새 승인을 받아야 합니다.
5. 저장 최소 자료의 산식/통화/기간/상태와 모형 결과의 집계/근거 목록을 대조합니다. 고정 예시 V1은 이전 형태 그대로 지원합니다.

루트 밖 경로/UNC/확인된 심볼릭 링크·junction·파일 하드링크는 거절합니다. 단일 분석 writer를 전제로 하며 로컬 관리자의 동시 경로 교체·전체 해시 재작성까지 막는 OS 보안 인증은 아닙니다. 읽기 전용 SQLite도 동시 실행 상황에서 sidecar 메타데이터가 절대 생성되지 않는다는 보장은 아닙니다.

한도: 목록 루트 100항목, 원본 DB 256MiB, 내보내기 하나 16MiB, 보관 루트 10항목/64MiB(미완성 포함), 선택 판단 100건, 최소 자료 128KiB. 개수/수량/버전은 10,000 이하, 금액은 정수 30자리/소수 40자리 이하입니다. 분석 자료 보호 한도이며 원본 매매 정책을 바꾸지 않습니다. 기존 요청 100개·상태 본문 4MiB·결과 16KiB도 적용해 먼저 닿은 한도에서 보류합니다. 자동 삭제/회전·장기 대용량 성능은 제공/검증하지 않습니다.

## 로컬 API와 검사

인증된 동일 출처 요청만 받습니다. POST는 세션 쿠키·`x-csrf-token`·JSON·8KiB 제한을 적용합니다. 임의 경로/추가 필드는 거절합니다. 401/403/409/503 의미는 [기존 API](CODEX_ANALYSIS_MOCK.md#로컬-api)와 같습니다. 오류에 원본 경로나 임의 예외 내용을 노출하지 않습니다.

- `GET /api/codex-records`: `{ "runs": ["run-TEST01"] }` 같은 폴더 이름 목록.
- `POST /api/codex-records`: `{ "type": "inspect", "runId": "run-TEST01" }`. 응답은 `sourceId/runHash/from/to/decisions/fillEvents/revision`; 원본 내보내기는 응답하지 않음.
- `POST /api/codex-analysis`: `type=create-record`, 새 UUID `id`, inspect 응답의 `sourceId`, UTC `period:{from,to}`. 이후 approve/run/cancel은 기존 해시 계약. 동일 ID/내용은 재사용하고 다른 자료/기간/예시 유형은 충돌로 거절.

구현: [자료 스키마](../src/core/analysis-record-schema.ts), [선택·집계·검증](../src/core/analysis-records.ts), [읽기 전용 출처](../src/server/analysis-record-source.ts). 기존 설치 상태의 프로젝트 루트에서 실행합니다.

```powershell
npm run typecheck
npm run lint
npm run format:check
npm run build
node --test --test-concurrency=1 dist/runtime/tests/analysis-records.test.js dist/runtime/tests/analysis-records-http.test.js dist/runtime/tests/codex-analysis.test.js dist/runtime/tests/codex-analysis-http.test.js
npm run test:e2e -- tests/browser/analysis-records.spec.ts tests/browser/codex-analysis.spec.ts
npm run verify:originals
```

격리 합성 DB/서버에서 경계·변조·통화·미확정·승인·재조회 및 Edge 화면을 검사합니다. 실행 결과/실패 이력은 [PROGRESS · 공개 요약](PROJECT_STATUS.md)에 구분합니다. 전체 제품 회귀·새 설치·실제 시장/수익성·실제 Codex 프로토콜/인증/사용량·OS/전원 고장·장기 성능·모든 브라우저·전체 자료 보안/권리 감사는 미검증입니다. 원본 불변 확인은 시험 DB의 전후 바이트 비교이며 사용자 DB를 열어 감사한 것이 아닙니다.

다음 단계에서도 최소 자료 외 파일/명령/네트워크 접근을 기술적으로 제한하고 실제 Codex 호출은 별도 승인해야 합니다. 이번 모형 승인을 실제 전송 승인으로 재사용하지 않습니다.
