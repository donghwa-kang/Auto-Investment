# AI 자동매매 프로그램 구현 프롬프트 v1.0

작성일: 2026-09-11  
대상 기준: 공통 거래 정책 v2.3 / 테마 확장 v1.3 / B·P 공용 전략 정의 v1.0  
이번 산출물: 개발 에이전트에게 전달할 작업 지시문. 프로그램 구현이나 실거래 승인을 대신하지 않는다.

## 사용 방법

현재 프로젝트를 개발 에이전트에 열어 주고, 아래 **「개발 에이전트에게 전달할 프롬프트」부터 「프롬프트 끝」까지** 전달한다. 다른 프로젝트에서 사용할 때는 아래 참조 파일과 의존 파일을 같은 상대 경로로 함께 제공한다. 프롬프트만 복사하고 원본 정책을 생략하면 동일한 기준을 구현할 수 없다.

이 프롬프트는 첫 실행에서 **1차 로컬 오프라인 모의매매 구현**만 요청한다. 전체 제품 방향과 후속 단계도 설명하지만 실계좌 연결·실시간 외부 수집·유료 AI 호출·실주문까지 한 번에 허용하지 않는다.

# 개발 에이전트에게 전달할 프롬프트

## 1. 역할과 완료할 결과

너는 금융 거래 소프트웨어의 시니어 풀스택 아키텍트이자 위험관리 엔진 개발자, 테스트 엔지니어다. 모든 사용자 설명·문서·화면은 한국어를 기본으로 한다. 코드 식별자는 명확한 영어를 사용한다.

목표는 기존 정책을 실행 가능한 코드로 옮기되, 처음에는 실제 돈이 움직일 수 없는 개인용 프로그램을 만드는 것이다.

이번 작업의 완료 결과는 다음과 같다.

1. Windows PC에서 로컬로 실행되는 관리 화면과 별도 수명 주기를 가진 거래 엔진.
2. 운용금·위험도·시장·실험 설정을 서버가 검증하는 시작 절차.
3. 동일한 정책/전략 평가기에서 생성되는 진입 후보와 거래 보류 사유.
4. 비용·현금·위험 예약을 반영하는 모의 주문, 체결·보호·청산 상태 관리.
5. 프로그램 재시작 후 보존·대조되는 장부, 주문, 손실 한도 및 감사 기록.
6. 실주문 경로 차단과 대표적인 장애·경계 조건을 입증하는 자동 시험.
7. 실제 설치·실행·검증 결과에 맞는 README와 PROGRESS, 요구사항 추적표.

이 프롬프트를 구현 작업으로 전달받았다면 설명이나 계획만 제시하고 끝내지 말고, 승인된 1차 범위를 코드와 시험으로 완성한다. 다만 새로운 금융 정책·외부 접근·유료 사용 승인이 필요하면 해당 기능을 차단한 채 이유를 보고하고, 독립적으로 가능한 로컬 구현을 계속한다. 수익을 보장하거나 미검증 기능을 운영 준비 완료라고 표시하지 않는다.

## 2. 작업 전 반드시 읽을 자료와 우선순위

프로젝트 루트는 현재 작업 디렉터리로 판별한다. 사용자 PC의 절대 경로를 소스 코드에 박아 넣지 않는다. 적용되는 AGENTS.md와 기존 README.md, PROGRESS.md, docs/, 코드·매니페스트·잠금 파일·변경 상태를 먼저 확인한다.

자료 사용 규칙:

- 상위 실행 환경 지침·적용 AGENTS.md를 준수한다.
- 이 프롬프트는 구현 범위와 품질 요구를 정한다. 투자 조건의 새 원본이 아니다.
- 투자 수치·상태·산식은 위 최신 정책과 가이드를 함께 대조한다. 의미 충돌이 있으면 더 편한 쪽을 임의 선택하지 말고 해당 판단을 차단하고 차이를 보고한다.
- 이전 파일은 보존한다. 정책을 실행하기 편하도록 원본 값을 변경하거나 null을 채우지 않는다.
- 아래 요약과 원본이 다르면 이 요약으로 원본을 덮어쓰지 않는다.
- 필수 자료가 없으면 경로를 보고한다. 정책 의존 기능은 막고, 정책과 독립적인 프로젝트 기반 작업만 진행한다.
- 시작 시 원본 해시를 저장하고 완료 시 대조한다. 결과·문서·코드·시험 사이의 요구사항 추적표를 만든다.

기존 248개 통과는 명세·독립 산식의 과거 검사 결과다. 실제 엔진·API·동시성·수익성을 검증한 결과가 아니므로 새로운 프로그램 테스트를 따로 작성한다.

## 3. 이번 실행의 권한과 경계

### 허용

- 프로젝트 안에서 소스·로컬 설정 예시·합성 시험 자료·시험·문서를 작성한다.
- 환경에서 허용된 범위로 개발 의존성을 설치하고 공식 문서를 확인한다. 실제 지원 버전과 설치 명령을 확인하고 잠금 파일을 사용한다.
- 별도 시험 데이터베이스로 비파괴적인 단위·통합·E2E·재시작·장애 시험을 수행한다.
- 로컬 관리 서버와 엔진을 실행·종료하고 결과를 검증한다.
- 비용·투자 정책에 영향을 주지 않는 내부 파일 분리·구조·UI 배치는 합리적으로 결정하고 기록한다.

### 이번 범위 밖

- 실제 계좌 조회·증권사 인증·주문·취소·조건주문 등록·환전·자금 이동.
- 유료 AI/뉴스/시세 호출, 구독 신청 또는 사용자 자료의 외부 업로드.
- 크리덴셜을 찾거나 출력하는 작업. 사용자가 API를 발급했다는 사실은 이번 사용 승인이 아니다.
- 클라우드 배포·외부 공개·원격 접속 개방·컴퓨터 시작 시 자동 등록·예약 작업 생성.
- 사용자 수동 보유 자산을 조작하는 기능의 활성화.
- Git 커밋·푸시·공개 전환, 사용자 파일 삭제·데이터 초기화.

공식 문서 조회와 패키지 다운로드는 애플리케이션의 금융/AI 연동과 구분한다. 앱의 초기 런타임은 외부 서비스 없이 동작해야 한다. 환경의 승인·네트워크 제한을 우회하지 않는다.

## 4. 제품 구조와 기술 선택

Windows 개인 사용자 1인·배정 포트폴리오 1개를 첫 지원 범위로 한다. 국내·미국은 그 포트폴리오 안의 시장 구분이며 별도 손실 예산이 아니다.

기존 프로젝트 기술이 있으면 먼저 재사용 가능성을 평가한다. 빈 프로젝트의 기본 제안은 다음과 같고, 실제 설치 전 현재 공식 문서·런타임 호환성·라이선스를 확인한다.

- 화면: React + TypeScript, Vite 기반의 로컬 관리 UI.
- 엔진/로컬 API: 지원되는 Node.js LTS + TypeScript strict. HTTP 프레임워크는 호환성 확인 후 하나만 선택한다.
- 영속화: 로컬 SQLite를 우선 검토하되 트랜잭션·동시성·복구·드라이버의 Windows 지원을 입증한다. 부적합하면 변경 근거를 먼저 남긴다.
- 금액 계산: 정확한 decimal 연산 또는 단위를 명시한 정수 연산. JavaScript number로 금액·호가 경계·위험 비교를 계산하지 않는다.
- 시험: 단위/통합 시험기와 브라우저 E2E 도구를 실제 환경에 맞춰 선택한다. 성능·지원 버전을 추측하지 않는다.

TypeScript strict와 런타임 입력 검증은 필수다. 프레임워크 목록은 새 거래 기준이 아니다. 불필요한 마이크로서비스·메시지 브로커·다중 사용자 인증·클라우드 DB를 처음부터 도입하지 않는다.

권장 책임 분리:

- apps/web: 상태 표시와 사용자 명령. 최종 거래 승인·브로커 비밀값·직접 주문 권한 없음.
- apps/engine: 로컬 API, 실행 조정, 저장·재생, 위험·주문 처리.
- packages/domain: 통화·종목·주문·정책·결정 타입.
- packages/policy: 정책 로더·유효성 검증·버전/해시 결합.
- packages/strategy: 순수 지표 계산과 B/P 평가기.
- packages/risk: 금액·잔여 위험·수량·경제성 검사.
- packages/simulator: 가상 시계·주문·체결·장애 시나리오.
- packages/storage: 장부·이벤트·트랜잭션·복구.
- tests/fixtures: 합성 데이터와 시험 전용 프로필.
- docs/: 구조·정책 대응·시험·운영 한계.

이는 제안 경로다. 단일 책임을 유지하면서 더 간단한 구조로 통합할 수 있다. 백엔드는 Controller-Service-Repository 책임을 구분하고 전역 오류 처리·구조화 로그·파라미터 바인딩을 적용한다.

브라우저를 닫거나 새로 고쳐도 엔진의 보유 관리가 중단되면 안 된다. UI 수명과 엔진 수명을 분리하고 상태는 엔진을 기준으로 한다. PC 종료·절전·네트워크 장애에 대한 무중단 보장은 하지 않는다. 백그라운드 도우미를 시작한다면 Windows에서는 숨김 실행을 사용하고 사용자에게 종료 방법을 제공한다.

## 5. 모드·샘플·런타임 상태를 혼동하지 말 것

정책 운용 모드는 BACKTEST / PAPER / LIVE를 그대로 사용한다. DEMO는 별도 실거래 모드가 아니라 데이터의 출처 표시다.

첫 실행 상태:

- mode=PAPER.
- 데이터 출처=SYNTHETIC_FIXTURE, 화면에는 DEMO / 합성 데이터라고 상시 표시.
- 시작 전 실행 상태는 STOPPED.
- 위험도 화면 제안은 LOW지만 사용자 선택·확인 또는 명시적 실험 명세가 없으면 시작하지 않는다.
- 실제 주문 경로는 구현·등록하지 않는다. 환경변수·HTTP 요청·설정 파일에 LIVE나 live_enabled=true를 넣어도 거절한다.
- 가짜 브로커 토큰이 환경에 있어도 읽거나 전송하지 않으며 실제 금융 네트워크 호출 수는 0이어야 한다.

원본 JSON의 execution_adapter=NONE과 미구현 플래그는 작성 당시 명세 상태다. 모의 엔진을 만들기 위해 원본을 SIMULATOR나 true로 바꾸지 않는다. 별도의 런타임 설정·실험 명세·구현 증거에서 모의 어댑터의 존재를 표현하고 base_policy_hash에 연결한다. 선언형 고정 스키마를 그대로 사용자가 설정하는 런타임 스키마로 오용하지 않는다.

Demo/Paper/Backtest 실행마다 계정 별칭·DB/실험 ID·자료/모델/정책 버전·시계·난수 시드를 구분한다. 합성 데이터 성과를 실제 백테스트 성과나 검증 실적으로 합산하지 않는다. 결과가 없는 곳에 랜덤 수익률·AI 추천 점수·체결 성공률을 표시하지 않는다.

## 6. 최초 사용자 흐름과 로컬 명령

1. UI에 엔진 연결 상태·최근 heartbeat·데이터 출처·PAPER 표시·미검증 상태를 보여준다.
2. 운용금, 위험도, 시장, 대상 선정 방식, 실험 데이터/프로필을 선택한다.
3. 서버가 입력과 정책·필수 자료·장부·미체결·손실 래치·실행 소유권을 검증한다.
4. 통과하면 등록된 실험 명세로 실행하고, 미달이면 구조화된 사유를 표시한다.
5. 후보 선별→B/P 신호→근거/예측→독립 위험 심사→모의 주문→체결·보호·청산→장부 기록 순서로 작동한다.
6. 포지션 보호·장애 감시는 새로운 15분봉이나 AI 작업 완료를 기다리지 않는다.

시작·설정 변경·중지·모의 청산 명령은 서버의 상태 변경 API로 구현한다. 최종 경로/요청 스키마를 문서화하고 요청 ID, 설정 버전, 중복 방지 키 및 성공/거절 이유를 반환한다. 단순 GET으로 상태를 바꾸지 않는다. API 응답 성공과 체결 완료를 구분한다.

권장 실행 상태는 STOPPED / PREFLIGHT / RUNNING / ENTRY_PAUSED / RECONCILING / LIQUIDATING / HALTED / ERROR다. 이는 앱 제어 상태이며 브로커 주문·보호 상태를 대체하지 않는다. 각 상태의 진입 조건, 허용 명령, 재시작 후 동작을 정의·시험한다.

미래 실시간 수집기는 시간표를 재확인해야 하지만 이번 합성 실행은 거래소 달력·서머타임·휴장·조기 종료를 표현하는 시험 달력으로 같은 판단 경로를 검증한다.

## 7. 정책·자금·위험 엔진

정책 값은 버전이 있는 설정에서 읽는다. UI·전략·주문 코드마다 숫자를 중복 하드코딩하지 않는다. 원본의 수식 문자열을 eval/Function으로 실행하지 말고 명명된 타입 안전 함수로 구현하고 추적표로 연결한다.

핵심 불변 조건:

- 입력 A는 원화 양의 정수, 0 < A <= 5,000,000. 누락·문자 오염·비정수·범위 초과는 거절한다.
- K_t=max(0,min(A,E_t,E_day_open)).
- 신규 위험·보유 상한과 기간 손실 한도의 기준 자본을 혼동하지 않는다.
- LOW/MEDIUM/HIGH는 각각 1/4·1/2·1. HIGH도 기존 상한을 넘지 않는다.
- 유효 상한=floor(K_t × 기본 bps / 10000 × 단계 배율 × 낙폭 배율 × 수준 배율). 모든 배율 후 원 단위로 한 번 내림한다.
- 적용 항목은 회당 위험·종목별 금액·전체 금액·전체 미청산 위험·상관 위험군 위험의 다섯 가지다.
- 기간 손실·낙폭 중지·외화 자산·횟수·보유 수 등 비축소 가드는 원본대로 유지한다.
- 비용·위험 추정액은 원본대로 보수적으로 올림하며 수량은 유효 거래 단위로 내린다.
- 기존 위험·미체결 예약·동시 후보·상관/테마 중복·기간 잔여·낙폭 여유·비포지션 위험 버퍼를 함께 검사한다.
- 현금·종목별/전체 금액·호가/거래량 제한·비용을 함께 만족하는 최대 수량을 다시 계산한다. 한 주 불가하면 거래하지 않는다.
- AI가 한도·위험도·신호·손절·자격을 변경하거나 예외 승인을 할 수 없다.
- 종목 위험군 자료나 필수 비용/환위험 프로필을 모르는데 분산 효과를 가정하지 않는다.
- 레버리지·신용·공매도·소수점 거래를 이번 작업으로 허용하지 않는다. SOXL 감시 전용을 유지한다.

독립 계산 기준 예시: A=K=500만 원, PILOT, 낙폭 축소 없음에서 회당 위험은 하/중/상 1,250/2,500/5,000원, 종목별 금액 상한은 125,000/250,000/500,000원이다. 하의 상관 위험군 상한은 1,562원이며 낙폭 축소까지 적용하면 781원이다. 실제 사용 가능 위험은 잔여 예산 때문에 더 작을 수 있다.

수량 예시: 위험 예산 1,250원, 매수가 50,000원, 손절가 49,000원, 주당 비용 150원, 고정비 0이면 위험 기준 1주다. 고정비 200원이 추가되면 1주 비용 포함 위험 1,350원으로 0주다. 이 예시는 실제 종목/브로커 비용이 아닌 합성 검산이다. 경제성 가드도 별도로 통과해야 한다.

## 8. 통화·장부·저장

- KRW·USD 현금과 결제 채권·채무·증권·비용을 통화별로 기록하고 정책상 원화 환산 위험을 별도 집계한다.
- 외화 현금도 외화 자산 노출에 포함한다. 환전 전후·매수/매도 결제 전후에 같은 자산/비용을 중복 계산하지 않는다.
- 환율의 방향·단위·관측/수신 시점·출처를 저장한다. 누락/기한 초과 환율로 임의 주문을 허용하지 않는다.
- 입력 운용금은 권한 범위다. 계좌 전체 현금이나 기존 수동 보유를 자동 편입하지 않는다.
- 한국/미국과 MARKET_SCAN/THEME_FOCUS/HYBRID는 동일 배정 장부·위험 예산을 공유한다.
- 위험일은 Asia/Seoul 09:00 경계, 위험주는 월요일 09:00, 위험월은 매월 1일 09:00를 따른다. 거래소 세션 달력과 분리한다.
- 입출금·자금 변경·수준 변경·재시작으로 손실/낙폭 래치를 초기화하지 않는다.
- 모든 자금/위험 예약은 서버의 단일 트랜잭션에서 검사·저장한다. 프런트 잠금이나 프로세스 메모리 변수만으로 원자성을 주장하지 않는다.
- 체결과 수수료 이벤트는 고유 키로 중복 제거하고 원본 이벤트 ID·버전·수신 순서를 추적한다.
- 손익·보유·현금·예약의 원장이 일관되게 커밋되도록 설계한다. 외부 주문과 DB를 하나의 원자적 트랜잭션처럼 가정하지 않는다.
- 원장과 감사 이벤트는 무단 수정이 쉬운 임시 배열로만 보관하지 않는다. 로컬 감사 로그를 절대 위변조 불가능하다고 주장하지 않는다.
- 백업·복구와 스키마 버전/마이그레이션을 정의한다. 시험 DB와 사용자 DB를 분리하고 초기화는 시험 범위에만 한정한다.

금액 DTO/저장 형식은 단위가 명시된 decimal 문자열 또는 정수로 일관되게 정한다. 표시 반올림값으로 거래 비교를 하지 않는다. 식별자는 시장·거래소·통화·주식 종류를 구별하고 같은 기업/ETF 구성의 중복 노출을 별도 관계로 관리한다.

## 9. 차트·데이터의 공용 평가기

같은 평가기를 BACKTEST와 PAPER에 사용하고 향후 LIVE도 그 평가기를 재사용할 수 있게 한다. 모드별로 다른 B/P 산식을 만들지 않는다.

- 완료 1분봉을 거래소 정규 연속장 시작에 맞춘 15분봉으로 집계한다.
- 종가 확정 시점, source timestamp, received_at/available_at, revision, as_of를 구분한다.
- 판단 시점 뒤에 알려진 가격 수정·뉴스·공시·구성종목을 과거 판단에 넣지 않는다.
- 가격은 시점 보존 분할 조정 신호와 원시 주문 가격을 구분하고, 분할 시 거래량·호가·보유 수량도 일관되게 처리한다.
- 휴장·조기 종료·거래정지·누락 봉·0 거래량·기업행동·세션 경계를 시험한다. 없는 봉을 정상 거래 봉처럼 채우지 않는다.
- SMA20/60, Wilder ATR14, EMA20, VWAP 근사, RVOL, ORH, 변동성 백분위수를 공용 정의대로 구현한다.
- B/P의 엄격 부등호와 포함 부등호, 초기화·워밍업·동일 세션 참조를 그대로 보존한다.
- 벤치마크와 거래 가능한 대용 상품은 명시적 프로필로 구분한다. 거래량 없는 지수의 VWAP을 만들어내지 않는다.
- 매수/손절 호가 반올림 후 거리·위험을 다시 검사한다.
- ADX·볼린저 밴드폭은 연구안으로 비활성 유지한다. RSI·MACD·하모닉·피보나치 등을 임의로 추가하지 않는다.

후보마다 각 조건의 ID·입력값·문턱·연산자·결과·자료 시점·버전을 기록한다. 모든 지표를 종합한 근거 없는 AI 점수 대신 판정 근거를 재현할 수 있어야 한다.

숫자 정밀도·벤치마크 등 미확정 프로필은 13절의 시험 전용 선언 절차를 사용한다. 합성 E2E에서는 충분한 과거 1분봉과 비교 세션을 생성해 실제 집계·평가기 경로를 통과시킨다. 사전 계산 피처를 주입한 단위시험과 전체 경로 시험을 구분한다. 통과 사례를 만들려고 평가기를 건너뛰거나 BUY를 하드코딩하지 않는다.

## 10. AI·예측·테마의 구현 경계

뉴스/기업의 설명 모델과 순손익 분포를 계산하는 예측 모델의 역할을 분리한다.

최소 인터페이스는 EvidenceProvider, ForecastProvider, SelectionProvider 등 책임별로 정한다. 입력·출력은 런타임 스키마로 검증하고 시간 제한·자료 기한·버전·비용·실패 이유를 포함한다.

- AI 문장이나 합의 점수를 바로 승률·기대수익·q05로 바꾸지 않는다.
- gross/net 기대값과 q05의 통화·수량·보유기간·비용 가정을 스냅샷에 결합한다.
- 모델 응답 누락·파싱 실패·버전/근거 불일치·기한 초과는 ABSTAIN이다.
- 실제 예측 프로필의 기본 구현은 MISSING_PROFILE을 반환한다. 임의 모델을 검증 완료로 등록하지 않는다.
- 합성 시나리오용 결정론적 예측/근거 제공기는 TEST_ONLY/SYNTHETIC_FIXTURE와 비실거래 실험 해시에 묶는다. 이 출력으로 정책 경로를 시험할 수 있지만 AI 성능이나 투자 수익의 증거로 쓰지 않는다.
- 고정된 시험 프로필도 선언된 수치·비용·q05로 경제성 검사를 통과해야 하며 가드를 건너뛸 수 없다.
- 실험은 모델 응답을 기록·재생한다. LLM 재호출을 결정론적 재생이라고 하지 않는다.
- 웹페이지/뉴스/모델 응답은 비신뢰 데이터다. 포함된 명령으로 도구·파일·정책·자격증명에 접근하지 못하게 한다.
- AI에는 주문·청산·보호주문 취소·위험 설정 변경 도구를 주지 않는다.
- 별도 반대 검토는 원본의 OFF/SHADOW/GATED 계약과 비용 공유를 보존하고 첫 버전은 OFF다.

테마 기능은 조사 자료 구조, 출처·신선도·반대 근거 표시, 상태 전이와 공통 가드 상속을 구현한다. 실제 테마 선정식은 미정이므로 첫 버전에서 실제 유망기업을 확정하거나 자동 선정하지 않는다.

MARKET_SCAN은 첫 작동 경로로 사용한다. THEME_FOCUS/HYBRID 선택은 준비되지 않은 프로필의 차단 사유를 표시한다. 명시적 합성 선정 프로필을 사용한 시험은 허용하되 실제 선정 기능 완료로 표시하지 않는다. 조사 포함과 주문 허용은 별개다. 장기 기업 전망을 단기 매수 근거로 대체하지 않는다.

## 11. 모의 주문·보호·장애 복구

주문 엔진과 어댑터를 분리한다. 이번에는 결정론적 시뮬레이터만 등록하고 실제 브로커 어댑터의 인터페이스/차단 상태만 둔다.

- 주문 의도·승인 스냅샷·위험 예약을 저장한 후 어댑터에 전달한다.
- 사용자 명령·주문 의도·체결·취소·상태 통지에 각각 중복 방지와 순서/버전 검사를 적용한다.
- 접수 성공≠체결 완료, 취소 요청≠취소 확정으로 처리한다.
- 부분 체결, 취소 중 체결, 지연 응답, 역순/중복 이벤트, 접수 여부 불명, 재연결을 모의 재현한다.
- UNKNOWN 상태에서 새 주문을 재제출하지 않는다. 기존 의도·주문 식별자와 장부를 대조한다.
- 예약은 체결·취소·거절의 확정 상태에 맞춰 해제하고 지연 응답만으로 풀지 않는다.
- 프로그램 귀속 수량과 수동 보유 수량을 구별한다.
- 원본 청산/보호 상태 계약과 초기 목표가·최대 보유·종가/이벤트 청산 규칙을 구현한다.
- 손절 확대·물타기·미검증 시장가 대체는 금지한다. 보호주문에 문제가 생기면 신규 진입 차단과 기록/경고를 우선한다.
- 가격 접촉만으로 체결됐다고 하지 않는다. 같은 봉에서 목표/손절이 모두 닿았는데 순서를 모르면 유리하게 선택하지 말고 명시한 보수적 모형 또는 UNRESOLVED로 처리한다.
- 슬리피지·스프레드·거래 비용을 반영하되 실제 체결가에 반영한 비용을 중복 차감하지 않는다.
- 미체결·미해결·시험 종료 시 남은 보유를 결과에서 지우지 않는다.
- 엔진의 단일 writer 소유권과 fencing epoch를 저장소 수준에서 검증한다. 두 번째 엔진이나 예전 소유권의 명령이 거래 상태를 변경하지 못하게 한다.
- 프로세스 종료 후 재시작 시 저장 상태를 대조하고, 불명확하면 RECONCILING/차단 상태로 복구한다. 자동으로 RUNNING이나 신규 주문 제출 상태로 돌아가지 않는다.
- DB 쓰기 실패·디스크 부족·큐 적체·시계 이상을 시험한다. 신규 위험을 늘리지 않고 보호/대조 경로의 가능한 동작과 한계를 기록한다.

주문 경로의 정확히 한 번 처리를 외부 시스템 전체에 보장한다고 주장하지 않는다. 재시도 가능한 이벤트, 중복 제거, 지속 상태, 불명 상태의 대조를 구체적으로 입증한다.

## 12. 중지·청산·위험도 변경 UX

| 동작 | 첫 버전의 허용 범위와 필수 동작 |
| --- | --- |
| 신규 거래 중지 | 모의 신규 진입을 차단하고 미체결 진입 주문 취소를 대조. 기존 보유의 보호·청산 관리는 계속 |
| 프로그램 매매분 청산 | 모의 장부의 프로그램 귀속 수량만 정리. 진행/부분 체결/차단/완료를 구분 |
| 선택 계좌 전체 청산 | 첫 버전 비활성. 수동 보유까지 포함할 수 있는 별도 후속 기능으로 이유와 승인 필요성을 표시 |
| 브라우저 종료 | 엔진 종료나 청산으로 간주하지 않음 |
| 엔진 정상 종료 | 신규 진입 중지·저장·대조 및 남은 모의 보유/주문을 명시하고 종료 |
| 강제 종료 후 재시작 | 저장 상태 복구·대조 전 신규 진입 금지 |

실제 전체 계좌 청산 기능을 이 프롬프트의 부수 작업으로 구현/활성화하지 않는다. 일반적인 STOP 명령으로 수동 자산을 팔지 않는다.

위험도 변경은 원본 29절을 따른다.

- 상향은 중지·귀속 포지션 0·모든 주문 최종 대조·사용자 확인 및 모드별 가드 통과가 필요하다.
- 하향은 즉시 신규 진입 차단·미제출 승인 무효화·진입 취소 대조를 시작한다.
- 새 상한을 초과하면 REDUCTION_PENDING으로 표시하고 검증된 모드별 청산 경로를 사용한다. 첫 버전에서는 시험된 모의 청산 프로필만 사용한다.
- 취소 중 체결·낮아진 한도·보호 수량 변경을 함께 대조한다.
- 설정 epoch가 바뀌면 이전 승인·큐 작업을 폐기하고 손익·손실 래치를 보존한다.
- 낮은 위험도를 선택했다는 이유로 손절가를 자의적으로 옮기지 않는다.

화면은 버튼을 누른 사실보다 엔진의 확인된 상태를 표시한다. 청산이 막혔는데 완료나 안전으로 표시하지 않는다.

## 13. 미확정 항목 때문에 생기는 구현의 빈틈 처리

현재 null/미검증을 없애는 것이 완료 목표가 아니다. 다음 분리를 사용한다.

| 미확정 항목 | 이번 구현에서 할 일 | 하지 말 것 |
| --- | --- | --- |
| 지표 정밀도·호가/벤치마크 매핑 | 결정론적 합성 시험 전용 프로필을 별도 파일로 선언·해시·경계 시험 | 원본 null을 운영 확정값으로 덮어쓰기 |
| 과거/실시간 시세·뉴스 공급 | 데이터 인터페이스·오프라인 fixture·출처/시점 검사 | 유료 가입, 실제 수집 시작, 이용 권리 가정 |
| 수익 예측·보정 | 기본 MISSING_PROFILE 차단, 시험용 예측 fixture | 임의 승률·검증된 기대값 생성 |
| 운영비·0건 기간 예산·환위험 버퍼 | 합성 실험 비용/환율/스트레스 조건을 명시하고 비용 경로 시험 | 실제 비용을 몰라 0원·위험 없음 처리 |
| 실제 체결·청산 프로필 | 모의 프로필과 장애 주입 시험 | 실제 보호 가능·시장가 복구 가능 판정 |
| 테마 선정식·실사 | 데이터 구조·샘플 화면·미정 상태·차단·시험 선정 프로필 | 샘플 기업을 실제 추천 명단처럼 제시 |
| 감사 보관 기간 | 이번 로컬 시험 기록 자동 삭제 비활성, 후속 정책 과제로 남김 | 사용자의 실제 기록을 임의 삭제 |
| 증권사 API 계약·계좌 자격 | 미연동/미검증 상태, 후속 확인 목록 | 문서나 API 키 발급만으로 거래 가능 판정 |

시험 프로필에는 purpose=TEST_ONLY, provenance=SYNTHETIC_FIXTURE, 정의 버전/해시, 생성 규칙/시드, 허용 모드, 실거래 금지 표식을 넣는다. 불충분한 실제 입력을 이 프로필로 자동 대체하지 않는다.

시험용 규칙 정의와 전략 성과 검증은 다른 차원이다. PAPER/BACKTEST는 정의된 미검증 실험을 허용할 수 있지만, 비용·수량·상태 가드는 그대로 적용한다. 테스트 통과 기록이 LIVE 허용 플래그로 연결되면 안 된다.

## 14. 관리 화면 요구

한국어 중심의 차분한 거래 관리 화면으로 구현한다. 토스 로고·화면을 복제하지 않는다. 수익을 암시하는 장식·가짜 실시간 움직임은 넣지 않는다.

다섯 영역:

1. 대시보드: 데이터 출처·모드·엔진 상태·운용금·통화별 현금·미실현 포함 손익·잔여 위험·보유·오류.
2. 후보/판단 기록: 시각·전략·조건별 값·통과/탈락 이유·기한·근거/예측 상태.
3. 테마/기업 조사: 조사 출처·갱신일·반대 근거·미정/만료 상태. 샘플은 명시적으로 구분.
4. 주문/보유: 접수·부분 체결·취소 대기·보호·청산·귀속·대조 상태.
5. 검증/설정: 실험·정책 버전·해시·시험 결과·자금·위험도·연결/미연결 상태.

필수 UX:

- 합성 데이터·미검증·실거래 잠금 표시를 첫 화면과 주문 영역에 지속 표시한다.
- 데이터 없음/로딩/오류/지연/연결 끊김 상태를 구분한다.
- 누락 값은 0이나 정상으로 바꾸지 않는다.
- 금액·통화·시간대를 명확히 표시하고 계획 위험과 매수 금액을 구분한다.
- 하/중/상 선택 시 적용되는 실제 금액을 보여준다. UI 값은 참고이며 서버가 재계산한다.
- 장애 경고는 색만으로 전달하지 않고 사유·발생 시각·현재 조치·가능한 다음 행동을 표시한다.
- 키보드 조작·라벨·초점·확인 결과·모바일 좁은 화면을 고려한다.
- 주문/판단 표는 페이지 단위/가상화 등으로 대량 기록에 대응하고 상태 갱신으로 전체 화면을 매번 다시 그리지 않는다.
- 연결이 끊기면 마지막 관측 상태라고 표시한다. 화면의 오래된 RUNNING을 현재 정상으로 보이지 않게 한다.

## 15. 보안·운영 성능

- 관리 API는 loopback으로만 바인딩한다. 0.0.0.0·LAN·공용 인터넷 노출을 기본으로 하지 않는다.
- localhost라고 무인증 상태 변경을 허용하지 않는다. 로컬 세션 인증, Origin/Host 검증, CSRF 대응, 요청 크기 제한을 구현하고 시험한다. WebSocket을 쓰면 연결 Origin/세션도 검증한다.
- 상태 변경 API·WebSocket 메시지·파일 입력은 런타임 스키마로 검증한다. 프런트 검증만 신뢰하지 않는다.
- SQL은 파라미터 바인딩을 사용하고 뉴스·로그·기업 설명은 안전한 텍스트로 렌더링한다. 임의 HTML·코드·파일 경로 실행을 막는다.
- 비밀값을 브라우저 저장소·공개 환경변수·URL·로그에 넣지 않는다. 첫 버전은 외부 API 비밀값 자체가 필요 없어야 한다.
- 사용자 파일/원문을 AI에 자동 업로드하지 않는다.
- 이벤트 큐·DB 기록·UI 갱신은 용량/지연 한도를 정하고 적체 시 신규 진입을 차단한다.
- 차트·과거 자료는 증분 계산·캐시를 사용하되 데이터/정책 버전에 묶어 무효화한다.
- CPU 집약 작업·대량 조사·AI 대기를 보호/청산 처리와 분리한다.
- 원본의 30초 신호 기한과 자료 최대 나이 등을 가상 시계로 시험한다. 만료 신호를 처리량 부족 때문에 연장하지 않는다.
- 성능 목표는 측정 환경·자료 크기·측정 구간과 함께 기록한다. 단일 PC 측정으로 실시간 거래 SLA를 보장하지 않는다.
- 실제 네트워크가 필요한 기능은 다음 승인 단계에서 별도 프로세스/권한/비용 경계를 설계한다. PAPER 엔진에 거래 자격증명을 넣지 않는다.

## 16. 필수 시험과 검증 증거

기존 고정 스키마 검사 외에 실제 구현 함수를 호출하는 시험을 작성한다. 기대값을 같은 함수로 다시 계산하는 동어반복 시험만 만들지 않는다.

| 시험 그룹 | 반드시 확인할 사례 |
| --- | --- |
| 입력·설정 | 0·음수·500만 초과·비정수·누락·알 수 없는 위험도·잘못된 모드 거절 |
| 모드 격리 | LIVE 요청·live_enabled=true·환경변수 조작·가짜 크리덴셜 존재에도 외부 금융 호출 0 |
| 위험 계산 | 100만/300만/500만 × 세 위험도 × PILOT/표준 × 낙폭 여부, 내림 경계 |
| 수량·경제성 | 한 주 불가·고정비·비용 증가·q05 경계·잔여 위험 소진·강제 최소 주문 금지 |
| 장부·통화 | USD 현금/주식·결제 채권/채무·발생비용·환율 기한·입출금 낙폭 중복/초기화 없음 |
| 동시성 | 동시에 두 후보가 들어와도 예약 합계가 상한 이하, 중복 명령/다중 엔진 차단 |
| 전략 | B/P 각 포함/엄격 경계, ATR/EMA 초기화, RVOL 0/누락, 호가 반올림 후 거리 |
| 시점·달력 | 미완료 봉·수신 지연·미래 자료 수정·세션 경계·미국 DST·휴장·조기 종료 |
| 스냅샷 | 정책/수량/가격/비용/예측/설정 epoch 변경 시 이전 승인 무효, TTL 연장 없음 |
| AI·선정 | 프로필 누락·응답 오류/지연·근거 불일치·샘플/실제 혼용·프롬프트 주입 차단 |
| 주문 상태 | 부분 체결·취소 중 체결·거절·중복/역순·UNKNOWN·보호 미확인·과매도 방지 |
| 재시작 | 저장 전후/주문 접수 전후/부분 체결 후 종료를 재현하고 이중 주문·이중 손익 없음 |
| 중지·변경 | ENTRY_PAUSED에서도 보호 유지, 하향 중 체결, 초과 상한 청산 대기, 상향 조건 거절 |
| 청산 | 프로그램 귀속만 청산, 수동 귀속 보존, 미체결을 완료로 표시하지 않음 |
| 모의 체결 | 가격 접촉만으로 확정 안 함, 한 봉 내 목표/손절 순서 불명, 시험 종료 잔여 보유 |
| 저장 실패 | 트랜잭션 실패·DB 잠금·디스크 오류 시 예약/원장 정합성 및 신규 진입 차단 |
| 웹 보안 | 잘못된 Origin/Host·미인증 명령·CSRF·SQL 입력·HTML/스크립트 문자열 |
| UI E2E | 입력→사전 점검→시작→후보→모의 주문/보류→중지→재시작, 오류·빈 상태 |
| 재현성 | 같은 자료·정책·시계·시드·기록 모델 출력으로 같은 신호/결정/장부 결과 |
| 문서 | 실제 실행 명령·환경변수·상태·링크와 코드 일치, 없는 기능/시험 통과 주장 없음 |

테스트 데이터베이스에서 실제 트랜잭션/복구를 시험한다. PowerShell 산식 검산만으로 엔진 동시성 시험을 대체하지 않는다.

같은 결정론적 실행 결과 비교는 의미 있는 이벤트 순서·결정·금액에 적용한다. 실행마다 달라지는 진단용 wall-clock 등은 별도로 정의하되 거래 판단 관련 값을 임의 제외하지 않는다.

코드 작성 후 실제 존재하는 명령으로 타입 검사·린트·관련 단위/통합·빌드·핵심 E2E를 실행한다. 사용자 요구사항별로 시험 이름·명령·결과·증거 파일을 연결한다. 도구/환경 때문에 실행할 수 없으면 미검증으로 남기고 실패와 구분한다. 브라우저/네트워크 보안 차단을 다른 경로로 우회하지 않는다.

이번 합성 시험은 전략 수익성 백테스트가 아니다. 실제 데이터·비용·체결 모형이 없으면 PF·수익률·승률 등 성과 합격을 판정하지 않는다.

## 17. 단계별 구현 범위와 종료 조건

### 이번에 수행할 1차: 오프라인 모의 엔진과 관리 화면

아래 기능 단위를 PROGRESS에 추가하고 각 단위의 자동 시험·필요한 수동 확인까지 끝난 경우에만 완료 표시한다.

1. 기반·문서: 실행 가능한 프로젝트·런타임 검증·정책 로더·실험 설정·읽기 쉬운 오류 및 README.
2. 정책·장부: decimal/통화·위험 계산·현금·손익·원자적 예약과 독립 기대값 시험.
3. 자료·전략: 합성 시계/달력/자료·B/P 공용 평가기·조건별 로그와 시점/경계 시험.
4. 주문·복구: 모의 어댑터·부분 체결/취소/보호/청산·writer/재시작·장애 시험.
5. 화면·제어: 다섯 화면의 1차 범위, 시작/중지/모의 귀속 청산/수준 변경 및 API/E2E.
6. 통합 검증·인계: 합성 통과/보류/장애 시나리오, 외부 금융 호출 차단, 재현 가능 실행 방법·증거·미검증 보고.

없는 공급원·실사·실시간 기능은 설명 가능한 비활성 상태로 구현한다. 그러나 이번 범위의 장부·규칙·모의 주문·저장은 성공을 고정 반환하는 목 객체나 화면상의 연출로 대체하지 않는다.

### 후속 2차: 별도 지시 후

실제 데이터 공급·권리·비용과 프로필을 확정하고 과거 데이터 재생, AI/테마 추가 가치, 비용·체결 모형, 표본 외·봉인 평가, 실시간 모의매매를 구현·수행한다. 통과 표본·기간·문턱은 원본 정책을 적용하며 편의상 줄이지 않는다. 불확실하거나 성과 미달이면 해당 전략은 비활성 유지한다.

### 후속 3차: 별도 명시적 승인 및 검증 후

증권사 계좌별 계약·인증·주문·보호·복구와 운영 프로필을 확인하고, 원본의 모든 실거래 승격 조건과 사용자 승인을 충족한 범위에서만 소액 실거래를 검토한다.

이 프롬프트는 2·3차 외부 작업을 자동 승인하지 않는다. 1차 완료 후 계획만 기록하고 중단한다. 미검증 실거래 스위치를 만들고 사용자가 알아서 켜도록 넘기지 않는다.

## 18. 문서·진행 기록과 최종 보고

프로젝트 구현을 시작할 때 README가 없으면 확인된 목적·현재 상태·실행 조건부터 작성한다. 기존 README가 있으면 보존·갱신한다. 실제 코드와 매니페스트·잠금 파일을 확인한 명령만 적는다.

README에는 현재 기능/미구현 기능, 준비 환경, 설치·실행·정상 확인, DEMO/PAPER 구분, 시작/중지, 데이터 보존·복구, 테스트 방법, 네트워크/수익성/운영 한계를 넣는다. 비밀값 대신 안전한 예제 설정을 제공한다. 과거 문서 단계의 README 미작성 결정은 실제 구현을 시작하는 시점부터 새 실행 문서 작성으로 전환한다.

PROGRESS는 기존 정책 작업과 기록을 보존한 채 프로그램 구현 항목을 추가한다. 정책 문서의 91%대 진행률을 프로그램 구현률로 제시하지 않는다. 전체 진행률을 표시할 때는 미완료 항목을 포함해 최하위 체크 수로 다시 계산하고, 정책/프로그램 범위도 구분한다. 기존 시각 검토 미완료 항목을 이번 코드 작성만으로 완료 처리하지 않는다.

정책 대응표에는 요구사항 ID, 원본 파일/절 또는 JSON 경로, 구현 위치, 시험 이름, 상태, 미확정을 기록한다. 변경한 기준·확정한 시험 전용 가정·검증할 수 없었던 항목을 구분한다.

최종 답변은 다음 순서로 작성한다.

1. 이번에 실제 작동하는 기능과 실행 가능한 범위.
2. 핵심 아키텍처와 생성/변경 파일 링크.
3. 실제 확인한 설치·실행·정상 확인 명령.
4. 실행한 검사와 통과/실패/미검증, 데이터 출처.
5. 성능 측정 결과 또는 측정 전 상태와 필요한 최적화.
6. 원본 정책 보존 여부, 남은 문제와 후속 단계에서 필요한 사용자 결정.
7. 계좌 연결·실주문·환전·유료 AI 호출을 수행하지 않았다는 확인.

오류 없이 실행된다는 사실과 수익성·실거래 안전성이 검증됐다는 주장을 구분한다. 환경 제한으로 1차 완료 조건을 충족하지 못했다면 완료라고 쓰지 말고 남은 항목과 재현 방법을 제시한다.

이제 원본 파일과 작업 환경을 확인하고, 이번에 허용된 1차 구현을 진행하라.
