# 테마별 기업·ETF 조사 및 지속 거래 목록 관리 v1.1

작성·상품 구조 확인: 2026-09-10  
상태: 개정 기능 명세. 수집기·화면·자동 갱신·거래 기능 미구현. 실거래 비활성화.

개정일: 2026-09-10. [이전 v1.0](THEME_RESEARCH_GUIDE_v1.0.md)은 보존한다. 공통 v2.1의 모드·장부·전역 금지·검증 계약을 적용하며 [검토·검증 보고서](TRADING_POLICY_REVIEW_v2.1.md)에서 미확정을 확인한다.

목적은 테마별 대표기업·성장 후보·관련 ETF를 조사하여 지속적으로 관리할 거래 후보 집합을 만드는 것이다. 조사 대상을 계속 추적한다는 뜻이지 끊임없이 매매하거나 장기 보유한다는 뜻은 아니다. 이번 작업에서 실제 유망기업 순위를 확정하거나 개별 기업 실사를 수행하지 않았다.

[공통 거래 기준 v2.1](AI_TRADING_GUIDE_v2.1.md)와 [공통 위험 설정](AI_TRADING_POLICY_v2.1.json)을 그대로 상속한다. 이 확장은 종목 선정과 조사만 추가하며 운용금·손실 한도·PILOT·당일 청산·레버리지 제한을 완화하지 않는다. [확장 설정](THEME_RESEARCH_POLICY_v1.1.json)은 실행 코드가 아닌 정책 계약이다.

## 1. 시장 탐색 기능과의 관계

- `MARKET_SCAN`: 기존 v2의 시장별 유동성 상위 최대 100종목 감시 방식. 기존 기본값을 변경하지 않는다.
- `THEME_FOCUS`: 승인된 테마와 검증된 선정 정책으로 정한 집중 목록 안에서만 신규 진입한다. 목록 밖 종목과 시장 지수는 참고 정보로 분석할 수 있다.
- `HYBRID`: 두 경로의 후보를 합쳐 중복을 제거한 뒤 공통 순위·비용·위험 검사를 한 번 적용한다. 모듈마다 별도의 자금·손실 한도를 주지 않는다.

모드 변경은 사용자 설정 변경으로 기록한다. 최초 테마·선정 정책 버전·허용 상품군 승인은 사용자가 한다. 이후 구성 종목 갱신은 검증된 규칙으로 자동화할 수 있지만, 새로운 테마·레버리지·미검증 전략을 AI가 자의적으로 활성화할 수 없다. 현재 모듈은 비활성화 상태로 추가하며 계좌 연결이나 예약 작업을 생성하지 않는다.

## 2. 테마와 대상 분류

테마는 단순 인기 키워드가 아니라 제품·고객·매출·투자 지출로 연결되는 경제적 가설이다. 예시 분류는 AI 인프라, 반도체, 전력·송배전, 로봇·자동화 등이며 지금 유망하다고 확정한 목록은 아니다. 같은 기업이 여러 테마에 속할 수 있지만 이것을 서로 독립된 투자 기회로 세지 않는다.

각 테마에 `theme_id, name, definition, included_businesses, exclusions, value_chain_roles, evidence_ids, thesis, counter_thesis, invalidation_conditions, approved_at, version`을 저장한다. 테마의 경계·수혜 경로·반증 조건이 없으면 자동 선정에 사용하지 않는다.

| 역할 | 선정에 필요한 근거 | 잘못된 대체 기준 |
| --- | --- | --- |
| 대표기업 후보 | 해당 사업의 실제 규모·점유율·고객 채택·공급망 역할과 동종 비교 | 시가총액이 크거나 유명하다는 이유만으로 대표 지정 |
| 성장 후보 | 매출·수주·사업화·마진·현금흐름 개선의 확인된 근거와 반대 시나리오 | 주가 급등·검색량 증가를 미래 성장으로 간주 |
| 테마 ETF 후보 | 실제 기초지수·구성종목·노출 비중·유동성·구조 | 상품 이름에 테마 단어가 있다는 이유만으로 편입 |

대표기업과 성장 후보는 중복 역할을 가질 수 있다. 역할은 조사 분류이며 매수 추천이나 수익률 순위가 아니다.

초기 용량 시험값은 활성 테마 최대 5개, 테마당 대표기업 최대 3개·성장 후보 최대 3개·ETF 최대 2개이다. 이는 상세 조사 목록의 상한이며 적합한 대상이 적으면 빈자리를 채우지 않는다. 중복 제거 후 집중 거래 감시 목록은 전체 최대 20개다. 실제 동시 보유는 기존 PILOT 1개·표준 2개를 유지한다.

## 3. 기업별 조사 파일

각 회사에는 종목 코드만이 아니라 발행사 식별자와 상장 시장·통화·주식 종류를 함께 연결한다. 다른 시장의 동일 기업 주식·예탁증서도 경제적 중복 노출로 식별한다.

조사 항목은 다음과 같다.

1. 사업 구조: 주요 제품·고객·경쟁사, 테마와 실제 매출의 연결, 사업부별 비중, 공급망의 역할.
2. 재무: 최근 연간 보고 최대 3개와 중간 보고 최대 8개를 확보하고, 매출·영업이익·마진·영업현금흐름·설비투자·현금·차입금·희석 주식 수를 기록한다. 분기·반기·연간 주기를 구분하고 없는 분기를 만들어내지 않는다.
3. 성장 근거: 수주·고객 채택·가동률·출하·경영진 전망. 계약 체결과 단순 협의, 확정 매출과 수주잔고를 구분한다. 회사 주장은 회사 주장으로 표시한다.
4. 경쟁력: 가격 결정력, 전환 비용, 기술·특허, 생산 능력, 고객 집중도. 점유율의 시장 정의·기간·분모를 함께 보존한다.
5. 가치평가: 동종·자기 과거 대비 가격, 적용 가능한 이익·매출·현금흐름 지표, 성장 기대의 반영 정도. 적자 기업의 PER처럼 의미 없는 지표는 N/A로 표시한다.
6. 위험: 차입·유동성·증자·회계·지배구조·소송·수출 규제·고객 이탈·산업 순환 및 가격 하락에 취약한 조건.
7. 예정 사건: 실적·주주총회·분할·배당·자금 조달 등 확인 가능한 일정과 불확실성.
8. 거래 적합성: 호가·스프레드·거래대금·변동성·갭·주문 및 보호 경로. 기업의 질과 별도로 평가한다.
9. 종합 결론: 투자 가설·반대 근거·가설 무효화 조건·현재 미확인 사항·다음 확인 시점. 장기 전망을 15분봉 매수 확률로 바꾸지 않는다.

기간·통화·연결/별도·회계 기준·단위가 다른 수치를 직접 비교하지 않는다. 누적 중간 보고에서 분기값을 도출할 때는 동일 기준의 차감 가능성을 확인하고 파생값임을 남긴다. 비교 불가능하거나 필수 항목이 누락되면 해당 선정 프로필은 보류한다. 금융업 등 다른 재무 구조에 제조업 지표를 강제로 적용하지 않는다.

국내 공시·재무 자료는 [금융감독원 OpenDART](https://opendart.fss.or.kr/intro/main.do), 미국 제출 공시·XBRL 자료는 [SEC EDGAR API](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)를 우선적인 원천 후보로 사용한다. 이 서비스가 모든 사업부 자료·점유율·실시간 수급·애널리스트 전망을 제공한다는 뜻은 아니다. 실제 수집은 API 이용 조건·식별자·접근 범위 확인 후 구현한다.

## 4. ETF는 별도 상품 조사 파일 사용

ETF를 하나의 영업회사처럼 분석하지 않는다. 운용사·기초지수·산출 방식·구성종목과 가중치·상위 종목 쏠림·테마 노출·지수 변경·재조정·보수·규모·유동성·괴리·추적 오차·배당·통화·파생상품·배율·재설정 기간을 확인한다. 구성종목 변경 이력과 자료 기준일을 보존한다.

| 상품 예시 | 확인한 성격 | 이 기능의 초기 처리 |
| --- | --- | --- |
| SOXX | 반도체 분야 주식 지수를 추종하는 일반 ETF | 조사·감시 가능. 공통 자격·데이터·전략·주문 검증 후에만 주문 후보 |
| SOXL | 반도체 기초지수의 일일 수익률 +300%를 목표로 하는 레버리지 ETF | 조사·감시만 허용. 기존 정책대로 OBSERVE_ONLY, 자동 매수 비활성화 |

상품 구조 근거: [iShares SOXX](https://www.ishares.com/us/products/239705/ishares-semiconductor-etf), [Direxion SOXL](https://www.direxion.com/product/daily-semiconductor-bull-bear-3x-etfs). SOXL의 목표는 하루 단위이며 여러 날 누적 수익률의 3배 보장이 아니다. 현금으로 ETF를 매수해도 상품 내부 레버리지는 사라지지 않는다. SOXX의 가격에 3을 곱해 SOXL의 가격·수익 경로를 대체하지 않는다.

SOXL을 조사 대상에 넣는 것은 레버리지 거래 승인이나 기본예탁금 자격 충족을 의미하지 않는다. ETF별 운용사 자료를 독립적으로 확인하며, 현재 구성종목·가격·수수료·매매 자격을 영구 상수로 저장하지 않는다. 위 표는 매수 추천이 아니다.

## 5. 근거 저장과 선정 규칙

조사 결과의 각 사실에 `source_url, document_id, field, value, unit, period_start, period_end, published_at, received_at, available_at, revision, fact_or_estimate`를 연결한다. 서술에는 근거 ID와 반대 근거 ID가 필요하다. 유료 원문 보관·모델 입력은 이용 권한에 맞게 처리한다. API 키·계좌 개인정보는 조사 모델에 보내지 않는다.

뉴스 중복은 원 사건으로 합치고, 회사 발표와 이를 옮긴 기사들을 독립 확인 여러 건으로 세지 않는다. 소셜 인기·언급량은 발견 보조이며 사실 확인을 대체하지 않는다. 나중에 수정된 공시나 지금의 대표기업 목록을 과거 시점에 소급 적용하지 않는다.

선정 정책은 테마 관련성, 사업상 대표성 또는 성장 증거, 재무 건전성, 가치평가 위험, 거래 적합성을 각각 평가한다. 한 개의 AI 100점 점수로 합쳐 자동 승인하지 않는다. 숫자·출처·비교 집합을 표시하고 회사의 질·장기 전망·현재 거래 기대값을 별도 필드로 둔다.

자동 순위에는 시장·업종·역할별로 사전 등록된 `selection_policy_version`이 필요하다. 해당 버전은 비교 집합, 필수 입력, 정규화·결측 처리, 우선순위·동점 규칙, 편입·유지·퇴출 조건을 명시해야 한다. 정의가 없으면 자동 선정하지 않는다. 정의된 미검증 초안은 BACKTEST/PAPER에서 실험 목록으로 시험할 수 있으나 실거래 목록으로 승격하지 않는다. 표본 외 검증과 사용자 승인이 있어야 LIVE에 사용한다. 현재 선정 정책은 UNVALIDATED이며 실제 순위 산식의 최적성은 주장하지 않는다.

지정 종목을 사용자가 추가해도 LIVE의 자격·데이터·선정 및 매매 전략 검증을 건너뛸 수 없다. 연구·모의 시험은 11절의 별도 가상 권한으로 처리한다. 장기 매출 전망이 좋아도 현재 가격·비용·신호가 불리하면 거래를 보류한다.

## 6. 조사 상태와 주문 권한 분리

조사 상태는 `DISCOVERED, RESEARCHING, RESEARCH_READY, STALE, REJECTED`로 관리한다. `RESEARCH_READY`는 필수 자료와 근거가 준비되었다는 뜻일 뿐 매수 허가가 아니다. LIVE 권한은 `broker_eligible, product_profile_validated, selection_validated, research_current, in_active_list, strategy_validated, user_live_authorized, global_guard_clear`를 모두 요구한다. 불명확한 항목은 실패다. 연구·모의에는 LIVE 승인을 요구하지 않고 정의된 실험·가상 입력·선정 규칙·전역 가드를 판정한다.

테마 경로는 실행 모드에 맞는 위 권한과 공통 v2.1의 데이터·시간·기대값·위험·주문 검사를 적용한다. 활성 목록에 들어갔다는 이유로 무조건 매수하지 않고, 포지션이 없더라도 조사를 계속할 수 있다.

- 정기 갱신으로 목록에서 빠짐: 신규 매수·미체결 진입을 중지하고 취소를 대조한다. 기존 포지션은 보호·시간 청산을 유지하며 즉시 매도 사유로 바꾸지 않는다.
- 필수 데이터 만료·중요 공시 확인 대기: 해당 종목 신규 매수를 중지한다. 가용 정보로 반대 시나리오를 검토하되 AI 서술만으로 보호주문을 해제하지 않는다.
- 공통 위험 한도·거래 불능·보호 실패: 기존 복구·청산 규칙이 우선한다.
- 주식 수량이 0이 되어도 연결된 미체결·보호주문을 모두 대조할 때까지 주문 관리 대상에서 제거하지 않는다.

보호 실패·정지·안전상 조사 만료 상태는 시장 탐색·다른 테마로 우회할 수 없다. 안전상 전역 금지와 단순 해당 목록 순위 탈락을 구분한다. 동일 종목에는 전역 상태와 하나의 주문 의도 체계를 사용한다.

## 7. 지속 갱신과 비용

아래는 향후 구현할 갱신 계약이며 현재 스케줄러를 실행한 것이 아니다.

- 매 거래 세션 전: 신규 공시·기업행동·실적 일정·상품 구조·매수 자격과 조사 신선도 확인.
- 거래 중: 기존 뉴스 수집 상태와 실시간 시장 조건 감시. 중요한 변경이 감지되면 해당 조사 버전을 만료시키고 재검토 전 신규 매수를 막는다.
- 매주: 승인된 정책으로 목록 편입·유지·퇴출을 재평가하고 근거를 기록. 구성 변경은 해당 시장 다음 정규 세션 전 버전 스냅샷으로 적용한다. 중대한 금지 사유는 정기 갱신까지 기다리지 않는다.
- 달력 월간 점검 및 보고서 만료 이전, 실적·핵심 사건 발생 시: 테마와 기업 가설을 재작성한다. 단순히 날짜만 바꾼 보고서를 최신 조사로 취급하지 않는다.

매월 같은 날짜 갱신만으로 31일 간격이 생기지 않게 보고서의 reviewed_at+30일을 별도 만료 시각으로 예약한다. 보고서 본문이 30일을 넘거나, 새 중요 자료가 나왔는데 아직 반영하지 못했거나, 세션 전 원천 확인이 실패하면 해당 종목을 STALE로 처리한다. 재무자료 자체가 몇 달 전이라는 이유만으로 만료시키지는 않는다. 해당 회사의 공시 주기와 실제 최신 제출 여부를 확인한다. 정정·핵심 지표·테마 근거의 미해결 충돌은 해소 전 주문 차단 사유다.

전체 시장·테마 모듈의 AI 후보 정밀 분석은 합계 최대 5개/완료 봉이다. 운영비 배분은 공통 v2.1의 동일 기간 총비용/총거래 수 및 0건 처리 규칙을 사용한다. 상세 조사·모델·데이터·서버 비용도 기존 월 추가 비용 한도 min(A의 0.20%, 10,000원)를 함께 사용한다. 모듈을 추가했다고 별도 예산이 생기지 않는다. 실제 비용이 넘으면 범위 축소나 운영 계획 변경을 요청하고, 필요한 갱신이 불가능하면 신규 매수를 보류한다. 보유분 보호·청산은 계속한다.

정적 공시·원문은 허용 범위에서 캐시하고 변경 부분만 재분석한다. 보유 종목의 안전 관련 갱신을 우선하고, 동일 기업이 여러 테마에 있어도 같은 원문을 반복 구매·분석하지 않는다.

## 8. 테마 집중과 중복 노출

동일 테마의 회사·ETF는 초기 정책에서 같은 위험군으로 묶는다. 테마가 여러 개인 종목은 중복 연결된 전체 군에 속하며, v2의 업종·구성 중복·상관 규칙도 함께 적용한다. 테마 하나당 전체 자금의 고정 비율을 배정하거나 테마 수만큼 위험 예산을 늘리지 않는다.

ETF의 회사별 경제적 노출은 유효한 구성·파생상품 자료로 살펴본다. 일반 ETF는 검증된 구성 비중을 사용하며 레버리지 ETF는 현물 보유 비중만으로 추정하지 않는다. 파생 노출을 확인할 수 없으면 정확한 분산 수치를 출력하지 않고 보수적으로 묶거나 거래를 보류한다.

SOXX와 반도체 기업들을 함께 보유한다고 산업 위험이 자동으로 분산되는 것은 아니다. 시장 탐색형과 테마형이 같은 종목을 선택해도 후보·포지션·미체결·현금·위험은 한 번만 계수한다. 후보 합치기는 확정된 종목 식별자로 수행한다.

## 9. 화면과 저장 계약

향후 화면에는 테마 목록, 대표·성장·ETF 역할, 종목별 조사 상세, 근거·반대 근거, 자료 기준일, 보류·퇴출 이유, 조사 상태와 주문 허용 상태를 나란히 표시한다. ‘유망’ 표시에 매수 버튼 상태나 확정 확률의 의미를 부여하지 않는다.

상세 화면은 사업·재무 추이·경쟁 비교·가치평가·위험·이벤트·가격과 거래량·ETF 구성·과거 판단 변경 이력으로 나눈다. 출처 링크 없는 사실, 데이터 없음과 0의 혼동, 연구 후보를 실거래 승인으로 보여주는 표현을 금지한다.

설계 책임은 원천 수집·정규화, 근거 저장, 기업/ETF 조사, 테마 선정, 거래 신호, 공통 위험·주문 처리로 분리한다. 조사 모델은 주문을 직접 실행하지 않는다. 현재 저장 계약은 명세이며 실제 데이터베이스·API·UI를 구현했다고 주장하지 않는다.

## 10. 검증과 완료 조건

테마와 기업 선정 과정까지 포함하여 당시 알 수 있었던 전체 파이프라인을 v2 기준으로 검증한다. 현재 승자 목록을 과거 전체 기간에 고정한 백테스트는 선정 성과의 근거로 쓰지 않는다. 테마 선택형과 기존 시장 탐색형의 순손익·낙폭·비용을 같은 자금·기간·위험 한도로 비교한다. 더 긴 보유기간을 원하면 별도의 스윙·장기 전략으로 검증하며 이 기능 추가만으로 v2 당일 전략을 변경하지 않는다.

필수 수용 조건은 다음과 같다. 아래는 향후 구현 테스트 요구이며 현재 통과한 실행 테스트가 아니다.

- 테마 중복·동일 기업 복수 상장·ETF 구성 중복이 있어도 후보·위험이 중복 배정되지 않는다.
- 좋은 기업 평가와 나쁜 거래 신호가 함께 있으면 신규 주문을 하지 않는다.
- SOXX 조사 준비 완료라도 전략·계좌 자격이 미확인이면 신규 주문을 하지 않는다.
- SOXL이 조사 목록에 있어도 기존 레버리지 제한으로 매수하지 않는다.
- 새 공시·정정·자료 만료·수집 실패 시 관련 종목 신규 매수를 막고 보호·대조는 유지한다.
- 목록 퇴출·모드 변경·미체결 체결 경합에서 매도 가능 수량과 보호 상태를 대조한다.
- 시장·테마 병행 시 월 비용·봉당 AI 분석 5개·보유 수·손실 한도가 공통으로 적용된다.
- 사전 등록되지 않은 선정 기준·모델 버전은 자동 편입을 확정하지 않는다.

현재 검증 범위는 공식 상품 구조·원천 서비스 확인, 문서 및 설정의 정적 일치·링크·Markdown 구조 점검이다. 개별 기업 실사, 선정 모델·수익성, API 수집·실계좌 거래, 실제 화면 표시는 미검증이다.

## 11. 모드·선정·목록의 실행 계약

### 11.1 실험과 실제 운용 분리

공통 v2.1의 BACKTEST/PAPER는 SIMULATOR_ONLY이며 live_enabled나 사용자 실거래 승인을 켜지 않아도 정의된 가설을 시험할 수 있다. experiment_manifest_ready, selection_rules_defined, research_inputs_valid_for_experiment, in_experiment_list, strategy_rules_defined, global_guard_clear가 필요하다. 실제 계좌 자격은 없거나 UNKNOWN이어도 가상 자격 가정을 명시해 시험할 수 있다. 다만 현재 SOXL의 OBSERVE_ONLY 정책을 이 기본 전략 실험의 주문 경로에서 우회하지 않는다. 별도 연구 자료 분석은 가능하다.

LIVE는 6절의 모든 LIVE 권한과 공통 검증·실행 경로를 요구한다. ‘조사 완료’, ‘사용자 관심종목’ 또는 AI 점수는 LIVE 허가가 아니다. 종목 선정 상태와 전략 검증 상태는 다른 버전이다. mode/계좌/종목 목록 변경 시 이전 승인 해시를 폐기하고 새로운 모드의 가드를 재검사한다.

### 11.2 재현 가능한 선정 프로필

각 테마·시장·역할의 selection_profile은 다음 필드를 모두 정의해야 한다.

- id/version/status/approved_at, 적용 테마·시장·상품군·역할.
- as_of와 비교 모집단 구성 규칙 및 스냅샷. 현재 생존 기업만 소급 사용 금지.
- required_fields: 단위·기간·정규화·비교 가능성·원천·필수/선택·결측 처리.
- inclusion_predicates / retention_predicates / exclusion_predicates: 허용된 필드와 비교 연산으로 표현한 명시적 조건.
- ordered_sort_keys: 각 필드의 asc/desc·동점 순서. 마지막 키는 canonical instrument ID.
- role_capacity와 cross_theme_priority: 각 테마 최대 3/3/2, 전체 감시 20개를 넘지 않도록 적용 순서.
- snapshot_effective_at, 다음 정기 갱신, 중요한 사건에 대한 즉시 금지 조건.
- 검증 범위, 표본 외 결과, 조사 가설과 신호의 구분.

임의 실행 코드나 웹 문구를 선정 조건으로 실행하지 않는다. 승인된 필드·유한 숫자·명시적 비교 연산만 허용하는 선언형 계약을 사용한다. 프로필의 지표·가중치·문턱은 업종과 자료 제공 범위가 정해진 뒤 검증할 사항이며 이번에 최적값을 만들어내지 않는다. 현재 selection_profiles=[]이며 실제 기업 명단도 비어 있다. 이것은 문서 누락을 숨긴 기본값이 아니라 해당 기능의 명시적인 초기 차단 상태다.

알고리즘의 순서는 고정한다: 시점별 모집단 → 전역 금지 제거 → 역할별 필수 자료/편입 조건 → 등록된 키로 정렬 → 역할별 정원 → 등록된 테마 우선순위 → 종목 ID 중복 제거 → 전체 20개 상한 → 다음 세션 전 확정 스냅샷. 부족한 정원을 채우려고 조건을 낮추지 않는다. 유지/퇴출 조건도 등록된 조건으로 평가하며 장중 AI가 순위를 다시 만들어 즉시 편입하지 않는다.

하나의 기업이 여러 테마/역할에 속해도 자료·분석·주문 의도는 중복 생성하지 않는다. 다른 시장 주식/예탁증서는 별도 거래 종목이지만 동일 발행사·경제적 위험으로 연결한다. 동시에 발생한 시장·테마 신호는 공통 최종 수량·비용·기대값 순위와 원자적 예약을 한 번 적용한다.

### 11.3 갱신·퇴출과 감사

안전상 이유의 제외는 global_deny_reason, 선정 순위 탈락은 source_membership_removed로 저장한다. 전자는 모든 매수 경로를 차단하고, 후자는 해당 목록만 제외한다. HYBRID에서 재등장해도 global_deny를 먼저 검사한다. 기존 보호·청산은 어느 경우에도 목록 제거만으로 해제하지 않는다.

보고서 해시는 원문 ID·사실/추정·기준일·수신 시각·수정 버전·작성 모형을 포함한다. 같은 자료를 다시 요약한 것만으로 reviewed_at을 갱신하지 않는다. 필수 원천 확인과 중요 변경 반영이 있어야 한다. 30일 만료는 달력 월간 실행과 별개로 관리한다.

## 12. 추가 검증과 미확정

PAPER에서 미검증 선정 프로필을 시험하는 경로, LIVE에서 이를 거절하는 경로, undefined 프로필 거절, 동일 입력 정렬·동점 재현, 자료 누락·정정·31일 월간 경계, 전역 금지 우회, 퇴출 중 부분 체결을 각각 시험한다. 이 요구는 실제 수집기·UI·계좌 시험이 끝났다는 뜻이 아니다.

사용자 결정 또는 추가 증빙이 필요한 항목은 활성 테마·시장 우선순위, 업종별 선정 지표와 비교 집합, 데이터 계약·월 비용, 승인 권한·보관 기간이다. 보유기간은 기존 당일 최대 90분을 유지한다. 장기 기업 조사와 단기 거래 성과의 관계는 전체 파이프라인 비교로 검증하며 장기 보유로 자동 전환하지 않는다.
