## 2. 무엇을 바꾸고 무엇을 유지했는가

| 항목 | 기존 기준 | 개정 |
| --- | --- | --- |
| 위험·보유·손실·청산 | 통합 계좌 한도와 B/P 당일 거래 | 모든 기존 숫자 유지. AI·실험이 안전장치를 해제하지 못함 |
| 전략 정의 | 문서의 B/P 계산식 중심 | 공용 JSON 정의·파일 SHA-256·동일 평가기 재생 계약 추가 |
| 현실적 체결 | 지연·부분 체결 고려 요구 | 필수 모형 입력·미확정 체결 상태·검증 등급·비용 중복 금지 구체화 |
| 추가 기능 평가 | 단순 모형과 AI 비교 | Q/QN/QT/QNT/QNTC 모듈 비교, 공통 달력·출발 모집단·비용·봉인 소진 규칙 |
| 반대 근거 | 본 분석에서 반대 근거 기록 | 별도 검토 OFF/SHADOW/GATED, 1후보·1회·재시도 0의 시험 상한 |
| 테마 조사 | 상세 조사·주기 갱신·선정 계약 | 장중은 유효 캐시만, 장기 성장과 당일 신호 분리·공통 B/P 적용 |
| 실거래 승격 | 기본 검증·승인 필요 | 공유 정의/재생·체결 현실성·미래 데이터·활성 모듈 검증 조건 추가 |

새 정밀도·벤치마크·체결·검토 프로필을 근거 없이 채우지 않았다. 기존의 정의되지 않은 선정/예측/청산 프로필도 그대로 차단 사항이다. 특히 OFF인 추가 검토만 생략할 수 있고 필수 위험 검사까지 생략할 수는 없다. 숫자는 유지했지만 B/P의 이전 봉 참조를 같은 세션의 연속 유효 봉으로 명확히 제한하여, 세션 경계·거래 중단을 넘는 후보는 제외한다. 이는 신호 의미의 보수적 명확화이며 실제 거래 결과까지 이전과 동일하다는 주장이 아니다.

500만 원 최초 배정 예시에서 표준 1회 계획 위험 10,000원, 최초 PILOT 5,000원, 표준 전체 보유 상한 200만 원, PILOT 100만 원, 일 손실 중지 30,000원을 유지한다. 실제 한도는 당시 자산·기간 기준·낙폭 축소·기존 예약에 따라 더 작아진다. 계획 위험/중지선은 갭·미체결로 넘어설 수 있으며 확정 최대 손실액이 아니다.

## 4. 검증 결과

최종 오프라인 검사 **175/175 통과, 실패 0, 종료 코드 0**. 실행 환경은 PowerShell 7.6.5다. 첫 검사 174개 통과 후, GATED 검토 응답 해시 결합을 추가하고 전체 175개를 다시 실행했다.

- 기존 자금·위험·달력·유니버스·비용·청산·장부·보안 등 11개 설정 구역과 B/P 본문의 기존 수치·연산자 보존 대조.
- 공통/테마/공유 전략 JSON의 고정 정적 스키마, 의도적인 잘못된 입력의 거절, 버전 참조·전략 파일 SHA-256 대조.
- 변경 시 주문 승인을 무효화할 스냅샷 필드, OFF/SHADOW/GATED 권한 분리, 기한·예산·프로필 미정 시 처리 계약.
- 미래 자료가 과거 계산을 바꾸지 않는 합성 사례와 고의 누수를 탐지하는 대조 사례. 실제 B/P 전체 계산기 시험 아님.
- 지정가 접촉만으로 체결 확정 금지, 부분/미체결 상태·비용 중복 방지·무거래일 비용의 독립 검산.
- 이번 작업 전 존재한 산출물 **10개 모두 SHA-256 일치**. 이전 버전 보존 확인.
- 개정 산출물 6개의 제한적인 API 키·Bearer·개인키·깨진 문자 패턴 검색에서 해당 패턴 미발견. 전체 비밀값 형식·Git 기록·외부 서비스 검사는 아님.
- Markdown 문서 3개의 변환·표 셀·코드 블록·내부 링크 실재 검사 통과. 실제 화면 표시는 미검증.

상세 결과는 work/policy_validation_v2_2_results.json에 보관한다. **175개는 정책 정적 검사와 독립 검산 사례의 수이며, 실거래·수익성·실제 동시성 테스트의 통과 수가 아니다.**

검사 스크립트는 work/validate_policy_v2_2.ps1이며 프로젝트 루트에서 PowerShell 7.4 이상으로 다음 명령을 실행한다.

```powershell
pwsh -NoProfile -File work/validate_policy_v2_2.ps1
```

스키마는 고정된 이번 정책 산출물의 정적 회귀 검사이며, 임의 사용자 설정을 받아 실거래를 실행하는 범용 검증기가 아니다. 순수 함수 사례는 실제 공유 평가기·시장 체결기·동시성 시험을 대신하지 않는다. 미래 자료 검사도 합성 예제의 검사 원리만 확인하며 실제 B/P 전체 파이프라인 누수 제거 완료를 주장하지 않는다.

## 5. 남은 차단 조건과 후속 작업

- 실행 코드 없음: 공유 지표/전략 평가기·체결기·원천 수집·장부·예약·단일 writer·계좌 재연결·스케줄러·UI 미구현.
- 전략 미검증: 실제 데이터 백테스트, Q/QN/QT/QNT/QNTC 비교, 예측 보정·모의 전진·실거래 수익성 미수행.
- 공급·운영 프로필 미확정: 과거 호가·뉴스·기관 자료 이용권과 비용, 0건 기간 운영비 예산, 외화 스트레스, 감사 보관 기간.
- 신규 프로필 미확정: 지표 정밀도/시장 벤치마크, 체결 모형, 반대 검토 모형·시간·최대 비용. 반대 검토와 테마 모듈은 비활성화.
- 기존 토스 차단 유지: REST 조건주문 수정 수량의 설명/스키마 충돌, 이전 AsyncAPI 재조회 실패, 계좌별 주문·부분 체결·취소 경합 미검증. 이번에 재시험하여 해결한 것으로 표시하지 않음.
- 테마 목록/선정 정의 미확정: 실제 기업 명단·개별 기업 실사 미수행. SOXL은 3배 일일 레버리지 ETF로 계속 감시 전용.
- 시각 검토 미완료: 이전 로컬 미리보기 보안 차단을 우회하지 않음. Markdown 변환은 실제 화면 확인과 다름.
- 활성화 권한 별도: 이번 사용자 요청은 기준 개정이며 실제 계좌 접속·주문·환전·실거래 시험의 승인이 아님.

다음 단계는 거래 실행보다 먼저 **데이터·비용·필수 프로필 확정 후 공유 평가기와 가상 체결기 구현 및 검증**이다. 이 문서만 보고 실거래를 켜지 않는다.
