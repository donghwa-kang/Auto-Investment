# AI ETF 자동매매 통합 작동 기준 v1.0

작성·공개 자료 확인일: 2026-09-10  
상태: 구현 가능한 연구 명세 / 전략 수익성 미검증 / 기본 모드 PAPER

이 문서는 약 500만 원의 자금을 가진 개인이 뉴스·시장·가격·거래량 등을 AI로 종합하여 자동매매하는 프로그램의 판단·실행·중단 기준이다. 모든 시장에서 수익을 내는 완벽한 매매 기준은 존재하지 않는다. 여기서 완성하려는 것은 **각 상황에서 무엇을 해야 하는지 검증할 수 있는 작동 규칙**이다. 비용 차감 후 수익 가능성은 별도의 실험으로 판정한다.

앞선 대화의 80% 확률, 손익비 2:1, 100회 모의매매, 손절 1만 원 등은 검증된 최적값이나 합의된 위험 한도가 아니었다. 이번 문서의 일관된 시험 설정으로 대체한다. 손절가와 손실 한도는 대응을 시작하는 기준이며 실제 손실의 상한을 보장하지 않는다.

## 1. 근거와 설계값을 구분하는 법

- **확인된 사실**: 상품·API의 공식 설명, 연구가 실제로 다룬 결과와 적용 범위.
- **운영 규칙**: 데이터 시점 보존, 중복 주문 방지, 위험 한도 우회 금지처럼 프로그램이 지켜야 할 조건.
- **시험 설정**: 15분봉, 거래량 1.5배, ATR 1.5배, 각 손실 한도 등 이 문서에서 제안한 초기값. 수익성이 입증된 숫자가 아니다.
- **미확정 조건**: 데이터 공급원·이용 비용·실계좌 상품 자격·주문 세부 동작. 충족 여부를 확인하기 전 실거래 승격 불가.

공개 연구·증권사의 설명을 종합했으며, 특정 운용사의 비공개 매매 규칙이나 성과를 재현했다고 주장하지 않는다. 미국 금융회사에 대한 감독 지침은 시스템 설계 참고이며 한국 개인에게 그대로 적용되는 법적 의무라는 뜻이 아니다.

## 4. 데이터 계약: 판단 당시에 알 수 있었던 정보만 사용

모든 관측값은 최소 `source_id`, `instrument_id`, `event_at`, `published_at`, `received_at`, `available_at`, `revision_id`, `quality_status`를 가진다. 해당하지 않는 시각은 명시적 null과 사유를 저장한다. 판단 시각 `t`에서 `available_at <= t`인 데이터만 허용한다. 실제로 수신하기 전 공개된 뉴스라도 수신 전 판단에 사용하지 않는다.

- 시간은 UTC로 보관하고 세션 해석은 `America/New_York`로 한다. 미국 거래일이 한국 달력의 날짜와 달라도 거래 카운터는 미국 세션에 묶는다.
- 15분봉은 정규장 개장부터 고정 구간의 완성된 1분봉 15개로 만든다. 누락 봉을 임의의 0 거래량으로 채우지 않는다. 공급원이 무거래 구간임을 확인한 경우만 별도 규칙으로 처리한다.
- 수정된 기사·공시·경제 수치를 과거 최초 발표값에 덮어쓰지 않는다. 백테스트는 당시 버전을 사용한다.
- 분할·병합·배당·종목 및 벤치마크 변경을 기록한다. 지표용 조정 가격과 실제 주문 가격을 분리하며 분할 시 거래량 단위도 맞춘다.
- 학습 데이터 공급원과 실시간 공급원의 봉·호가 범위가 다르면 대조 기간을 거쳐 교정한다. 통합시장 거래량과 특정 시장 거래량을 섞지 않는다.
- 시세 WebSocket의 체결 틱 단순 합계만으로 거래량이나 정밀 VWAP을 확정하지 않는다. 유실이 가능한 전송 구조이므로 완료된 REST 봉 등과 대조한다.

신규 주문용 데이터 품질 시험값은 다음과 같다. 이 수치를 충족하지 못하면 거래 횟수를 줄이거나 중단하며, 지연 데이터를 실시간이라고 취급하지 않는다.

| 검사 | 신규 주문 허용 조건 |
| --- | --- |
| 매수 대상 호가 | 원천 타임스탬프가 판단 시각에서 2초 이내, 가격·수량 유효 |
| 시계 | 외부 기준 시계와 오차 500ms 이내 |
| 봉 확정 | 종료 후 30초 내 필요한 1분봉·15분봉 검증 완료 |
| 주문 직전 | 호가·현금·미확인 주문·한도를 다시 검사. 계좌 REST 스냅샷 5초 이내 |
| 뉴스 공급 상태 | 최근 5분 내 수집 작업 성공. 관련 뉴스 0건과 수집 실패를 구분 |
| 환율 | 최근 60초 내 관측, 통화·평가 방향 명시 |
| 일정·참조 데이터 | 당일 일정 갱신 성공, 필요한 과거 60거래일 이상의 시계열 확보 |

뉴스가 없는 날은 유효한 상태이다. 뉴스 수집 실패를 중립 뉴스로 바꾸지 않는다. 모델이 처음부터 해당 변수를 사용하지 않는 버전은 운용 가능하지만, 운용 중 임의로 입력을 빼고 같은 모델을 계속 쓰지 않는다.

## 5. 지표를 계산하는 정확한 정의

이하 수치·기간은 모두 시험 설정이다. SOXX 실험과 SOXL 실험에서 거래 대상 `X`의 가격·ATR·비용은 각각 직접 계산한다.

- `C[t]`, `H[t]`, `L[t]`, `V[t]`: 완료된 15분봉 종가·고가·저가·거래량.
- `SMA_n`: 과거 완료된 정규장 일봉 종가 n개의 단순 평균. 당일 미완성 일봉 제외.
- `TR[t] = max(H[t]-L[t], abs(H[t]-C[t-1]), abs(L[t]-C[t-1]))`.
- `ATR14[t]`: 정규장 15분봉 TR의 Wilder 평균. 초기 14개 TR의 산술평균 이후 `(13 * ATR_prev + TR[t]) / 14`. 전일 마지막 정규장 종가와의 개장 갭 포함.
- `VWAP_approx[t]`: 당일 개장 후 완료된 1분봉에 대해 `sum(((H+L+C)/3)*V) / sum(V)`. 정밀 체결 VWAP이 아닌 봉 기반 근사치임을 이름과 로그에 표시한다.
- `RVOL[t] = V[t] / median(직전 20개 정상 거래일의 동일 세션 위치 15분봉 거래량)`. 현재 봉은 분모에서 제외. 조기 폐장 등 비교 불가능한 구간은 제외하며 유효 표본 20개 미만이면 신호 미생성.
- `ORH`: 당일 개장 후 최초 30분의 고가 최댓값. 30분 종료 후 고정.
- `spread_rate = (ask-bid) / ((ask+bid)/2)`. `bid > 0`, `ask >= bid` 필요.
- `relative_strength`: SOXX와 QQQ 각각의 당일 첫 정규장 유효 체결가 대비 완료 봉 수익률의 차이.

## 6. 매수 후보를 만드는 단일 규칙

이 전략의 가설은 “업종 추세가 우호적일 때 거래량이 동반된 개장 범위 돌파 중, AI가 비용 대비 결과가 양호할 것으로 평가한 경우를 선택한다”이다. 뉴스 호재가 반드시 있어야 하는 전략은 아니다.

다음 조건을 **모두** 만족해야 AI가 판단할 매수 후보가 된다.

1. **거래 창**: 개장 45분 후부터 종료 100분 전까지의 완료된 15분봉에서만 판단한다. 일반적인 09:30~16:00 세션에서는 10:15~14:15 봉 종료 시각이 해당한다. 조기 폐장은 달력으로 다시 계산한다.
2. **일간 업종 추세**: 전일 SOXX 종가 > 전일 기준 SMA50, SMA20 > SMA50.
3. **시장 지지**: 전일 QQQ 종가 > 전일 기준 SMA50. 현재 완료 봉에서 SOXX 종가 > SOXX VWAP 근사치, `relative_strength >= 0`.
4. **새 돌파**: 거래 ETF의 직전 완료 봉 종가 `C[t-1] <= ORH`, 현재 `C[t] > ORH + 0.05*ATR14[t]`.
5. **거래량 확인**: `RVOL[t] >= 1.5`.
6. **추격 제한**: `0 < C[t]-VWAP_approx[t] <= 1.5*ATR14[t]`. 이후 실제 매수 지정가도 신호 종가에서 `0.1*ATR14[t]` 이상 높일 수 없다.
7. **극단 상황 제외**: 현재 `ATR14[t]/C[t]`가 직전 60개 정상 거래일의 동일 시간대 값의 95백분위 이하. 백분위는 오름차순 `ceil(0.95*n)`번째 값으로 정의한다.
8. **체결 여건**: `spread_rate <= 0.001`(0.10%), 양쪽 호가 유효. 주문 수량은 최우선 매도호가 잔량의 10% 및 직전 완료 1분봉 거래량의 1% 이하.
9. **이벤트 창**: FOMC 결정·기자회견, CPI·미국 고용보고서 등 등록된 고충격 이벤트의 30분 전~30분 후에는 신규 진입 금지. 진행 중 기자회견은 종료 시각을 확인한 뒤 30분까지 금지. 시각 미확정이면 해당 예정 시각 이후 신규 거래를 보류한다.
10. **운영 조건**: 데이터·모델·계좌 검사 정상, 포지션 0, 미확인·미체결 진입 주문 0, 종료되지 않은 이전 보호주문 0, 손실·횟수 제한 정상.

이벤트 일정은 [연준 FOMC 달력](https://www.federalreserve.gov/monetarypolicy/fomccalendars.htm), [미국 노동통계국 발표 일정](https://www.bls.gov/schedule/2026/home.htm) 등 공식 출처를 이용한다. 회의 개최일과 성명 발표·기자회견 시각을 구분한다. 차단 시간을 30분으로 정한 것은 이 문서의 시험 설정이다.

규칙이 엄격해도 성과가 좋아진다는 보장은 없다. 시장 추세·상대 강도·RVOL 조건을 추가할 때마다 개선 여부와 거래 표본 감소를 비교한다. 거래가 적다는 이유로 실시간으로 문턱을 낮추지 않는다.

## 7. AI의 종합 판단 계약

AI의 핵심 역할은 후보마다 **어떤 근거가 유효하고 서로 모순되는지, 정해진 청산 규칙하에서 비용을 이길 가능성이 있는지**를 평가하는 것이다. 별도 AI 여러 개의 다수결을 신뢰도의 증거로 삼지 않는다.

### 7.1 뉴스·문맥 처리

언어 모델에는 수집한 원문과 식별 가능한 사실만 제공한다. 모델 기억에서 과거 사건·실적·현재 주가를 보충하지 않는다. 공개 자료의 명령문이나 임의 URL을 주문·설정 변경 명령으로 해석하지 않는다.

결과 필드는 사건 종류, 관련 기업·ETF, 원문 근거 ID, 최초 공개·실제 수신 시각, 새 사실, 긍정·부정 영향 경로, 반대 근거, 미확인 사항, 데이터 품질이다. 없는 수치·기관 거래·컨센서스는 `unknown`으로 둔다. 같은 발표를 인용한 기사 10개는 사건 하나로 묶는다.

실적이 좋다는 기사만으로 “예상 상회”라고 만들지 않는다. 발표 당시 확보된 컨센서스가 있을 때만 서프라이즈를 계산한다. 뉴스의 긍정도는 실제 주가 상승 확률과 별개이다. AI 생성 정보는 부정확하거나 허구일 수 있으므로 원문과 교차 확인한다. [FINRA AI 정보 주의사항](https://www.finra.org/investors/insights/artificial-intelligence-and-investment-fraud)

### 7.2 예측과 점수의 의미

가격·시장·유동성·뉴스 특징을 종합하는 모델은 9절의 고정 청산 정책을 적용했을 때의 **전체 거래 결과 분포**를 예측한다. 간단한 통계 모델을 비교 기준으로 두고 복잡한 모델의 추가 가치를 검사한다. 모델 유형 자체를 수익 근거로 사용하지 않는다.

- `gross_R`: 비용 전 실제 모의 손익 / 최초 가격 위험액 `R0`.
- `net_R`: `(실제 모의 손익 - 거래비용 - 배분 운영비) / R0`.
- `p_profit`: `net_R > 0`일 확률. “다음 봉 상승 확률”과 혼용하지 않는다.
- `expected_net_R`: 같은 청산·비용 모형에서 추정한 순 기대값.
- `net_R_q05`: 동일 모형의 순손익 하위 5% 분위수. 손실 한도가 아니라 꼬리 손실 추정치.
- `distribution_status`: 학습 데이터 범위 내인지, 필요한 특징·유사 시장 표본이 있는지.

시간 청산·익절·손절을 모두 결과에 포함한다. `상승 확률 × 목표가 수익 - 하락 확률 × 손절액`처럼 두 결과만 있다고 가정하지 않는다. 손익비 2:1만으로 기대값이 양수가 되는 것도 아니다.

### 7.3 시험 승인 조건

6절 후보 조건과 8절 위험 검사에 더해 다음을 충족해야 모의 주문을 승인한다.

- 해당 데이터·종목·청산 정책·보유기간으로 검증된 모델 버전이며, 입력·출력 스키마 검사 통과.
- `expected_net_R >= 0.15`. 이 값은 초기 시험 문턱이며 수익 보장이 아니다.
- 하위 5% **총 원화 손실 추정치**가 1회 위험 예산의 2배를 넘지 않는다. 더 극단적인 손실은 여전히 가능하다.
- 필수 수치 특징 중 하나라도 학습 표본 0.5~99.5백분위 범위를 벗어나거나 학습되지 않은 사건 종류이면 `ABSTAIN`. 이상치 기준도 검증 대상이다.
- 뉴스 추출 결과와 원문의 중요 수치·시각 불일치, 필수 데이터 결측, 모델 만료·시간 초과이면 `ABSTAIN`.
- 15분봉 종료 후 30초 안에 의사결정 완료. 늦으면 해당 신호를 버린다. 최종 주문 호가·수량은 다시 계산한다.

`p_profit`는 과거 시간 외 데이터에서 보정하고 신뢰도 구간별 실제 성과를 보고한다. 최소 승률 80%나 언어 모델의 자기 확신 점수는 매수 조건으로 쓰지 않는다. 예측이 정량 검증되지 않은 언어 모델 판단은 관찰 기록만 남기며 실거래 주문을 승인할 수 없다.

반환 계약은 `decision_id`, `as_of`, `valid_until`, `strategy/model/data_version`, `action(ENTER/HOLD/ABSTAIN/EXIT_REVIEW)`, `evidence_ids`, `counter_evidence_ids`, `p_profit`, `expected_net_R`, `net_R_q05`, `quality_flags`, `reason_codes`이다. `EXIT_REVIEW`는 v1에서 기록용이고 임의 즉시 매도 권한이 아니다. 9절 청산 정책을 바꾸려면 그 정책으로 새로 검증한다.

## 8. 100만 원 시험 배정금의 위험 예산

이 설정은 사용자에게 이미 확정된 손실 허용액이 아니라 보수적인 시작 제안이다. 500만 원 전체가 아닌 **전략 배정금 100만 원**을 기준으로 계산하여 대기 자금으로 손실률이 작게 보이지 않게 한다.

| 항목 | 계산·초기 금액 | 발동 동작 |
| --- | --- | --- |
| 1회 계획 위험 | `min(현재 전략 순자산, 당일 개장 순자산) * 0.25%`, 최대 5,000원. 초기 2,500원 | 손절 거리·비용에 맞춰 수량 제한 |
| 최대 보유금 | `min(500,000원, 현재 전략 순자산의 50%)` | 주문 전 수량 제한 |
| 일일 손실 | 개장 순자산 대비 1%, 초기 10,000원 | 신규 진입 차단·미체결 진입 취소·확인된 보유 수량 청산 시도 |
| 주간 손실 | 미국 거래 주 첫 개장 순자산 대비 2.5%, 초기 25,000원 | 같은 동작 후 다음 주 전 점검 필요 |
| 고점 대비 낙폭 | 입출금 조정 전략 순자산 고점 대비 5%, 초기 고점 100만 원이면 50,000원 | 장기 중지, 자동 재시작 금지 |
| 연속 손실 | 비용 차감 후 음수인 완료 거래 2회. 0원 거래는 연속 손실을 초기화하지 않음 | 해당 세션 신규 진입 종료 |
| 진입 횟수 | 부분 체결을 포함하여 하루 최대 2개의 신규 포지션 | 이후 진입 차단 |
| 실패 신호 제한 | 하나의 신호에서 주문 의도 1개, 세션당 신규 진입 의도 최대 4개 | 미체결 재추격 제한 |
| 재진입 | 청산 확정 후 30분 이상 경과, 새로운 돌파 조건 필요 | 이전 신호 재사용 금지 |
| 운영비 | 데이터·서버·AI 합산 추가 지출 시험 예산 월 10,000원 | 진입 분석 지출 제한. 보호·청산 서비스는 유지 |

일·주 손익은 실현손익과 현재 보유 주식·외화현금의 평가손익 및 발생 비용을 포함한다. 개장 전 자금·포지션 대조를 완료하고 기준값을 저장한다. 일일 이익이 나도 손실 기준선을 낮추거나 위험 예산을 늘리지 않는다. 수동 입출금이 생기면 단위 순자산 방식으로 기준을 조정하여 입금으로 과거 낙폭을 지우지 않는다.

당일 가격 위험 예산이 작으면 1주도 살 수 없을 수 있다. 최소 수량을 맞추려고 예산을 늘리지 않는다. 월 1만 원 안에 필요한 데이터 품질을 구할 수 있다는 뜻도 아니다. 공급 비용이 예산을 넘으면 데이터·운용 계획을 재검토하며, 부족한 데이터로 실거래를 대신하지 않는다.

### 수량 계산

`P`는 비용 계산에 사용하는 최악 허용 매수 지정가(USD), `S`는 최초 손절 트리거(USD), `f`는 위험 평가용 KRW/USD, `B`는 1회 원화 위험 예산이다.

```text
q_risk = 아래 조건을 만족하는 가장 큰 0 이상의 정수 q

q * (P - S) * f + C_stop(q) <= B

q_final = min(q_risk,
              금액 한도 내 수량,
              실제 가용 USD 현금과 주문 수수료로 살 수 있는 수량,
              최우선 매도호가 잔량의 10% 이하 수량,
              직전 완료 1분봉 거래량의 1% 이하 수량)

R0 = q_final * (P - S) * f
```

`C_stop(q)`는 매수·손절 매도 수수료·부과금, 예상 불리한 체결, 예상 환전 마찰·단기 환위험 버퍼를 포함하는 수량별 모형이다. 호가 기반 진입 가격에 이미 반영된 스프레드를 다시 더하지 않는다. 비례 수수료·최소 수수료가 있으므로 단순 나눗셈보다 정수 수량을 검사한다. 거래 가능한 금액은 실제 토스증권 응답을 사용한다.

가상의 계산 예: `B=2,500원`, `P=$40`, `S=$39.20`, `f=1,400원/USD`, 예시 비용 `C_stop(q)=150원*q`이면 1주 위험은 1,270원이다. 2주는 2,540원으로 한도를 초과하므로 위험 기준 수량은 **1주**, 매수금은 56,000원이다. 이는 실제 시세·환율·수수료가 아닌 산식 설명용 숫자이다.

배정금 전액을 투자할 필요가 없다. 불확실성과 변동성이 클수록 허용 수량이 작아지는 것이 정상이다.

## 9. 손절·익절·시간 청산의 우선순위

최초 손절은 `S = min(L[t], L[t-1]) - 0.1*ATR14[t]`, 계획 위험 거리 `D=P-S`로 정의한다. `0.8*ATR <= D <= 2*ATR`를 만족하지 않으면 거래하지 않는다. 너무 먼 손절가를 맞추기 위해 위험 예산을 키우거나 너무 좁게 손절가를 옮기지 않는다. 손절가는 주문 호가 단위에 맞춰 아래로 내리고 수량을 다시 검사한다.

진입 체결 후에는 실제 평균 체결가 `F`를 기준으로 최초 가격 위험 거리 `d=F-S`, 익절 트리거 `T=F+2*d`를 확정한다. 매수 체결 전 고정한 손절 `S`를 낮추지 않는다. 평균 체결가가 예상보다 유리하여 `d<=0`가 되는 등 계약이 깨지면 보호 상태를 확인하고 청산 복구 절차로 간다. 진입 손익 모형도 이 체결 규칙을 사용한다.

청산 사유가 여러 개 발생하면 아래 순서로 처리한다. 판단은 우선순위를 정할 뿐 추가 매도 주문을 동시에 여러 개 생성하지 않는다.

1. **이미 발생한 체결 이벤트 반영**: 실제 잔여 수량을 먼저 갱신한다. 잔여 0이면 추가 매도 금지.
2. **위험 한도·보호 실패**: 8절 한도 도달, 보호주문 실패 또는 보호되지 않은 체결 수량 감지 시 10절 절차로 청산한다.
3. **손절**: 검증된 증권사 조건주문의 트리거 규칙에 따라 청산한다. AI의 재승인을 기다리지 않는다.
4. **익절**: `T`에서 전량 청산을 시도한다. 부분 익절·추적 손절·손절가 상향 변경은 v1에서 섞지 않는다.
5. **시간 청산**: `min(최초 체결+90분, 정규장 종료-10분, 다음 등록 고충격 이벤트-15분)`에 남은 전량 청산을 시도한다. 후보의 예상 보유 가능 시간이 30분 미만이면 진입하지 않는다.

장 종료·거래정지·네트워크 장애로 청산이 미완료되면 다음 날까지 보유할 수 있다. 이를 “당일 청산 성공”으로 기록하지 않는다. 잔여 노출·보호주문 상태를 알리고 재개 가능 시 복구한다. 보유 주식이 0이어도 USD 현금의 환율 위험은 남는다. 자동 원화 환전은 v1 기본 범위에 넣지 않고 평가손익에 반영한다.

손절 시장가의 체결가는 트리거와 달라질 수 있고, 손절 지정가는 체결되지 않을 수 있다. 따라서 계획 손실액은 확정 상한이 아니다. [Investor.gov 손절 주문 설명](https://www.investor.gov/introduction-investing/general-resources/news-alerts/alerts-bulletins/investor-bulletins-15)

## 10. 주문·장애·복구 계약

### 상태와 의미

```text
STARTUP_RECONCILE → READY → ENTRY_PENDING
ENTRY_PENDING → PARTIALLY_FILLED / OPEN_PROTECTED / READY
PARTIALLY_FILLED → OPEN_PROTECTED / EXIT_PENDING / HALTED_UNCERTAIN
OPEN_PROTECTED → EXIT_PENDING → COOLDOWN → READY
어느 상태에서든 불확실성 발생 → HALTED_UNCERTAIN
확인 가능한 위험 청산 필요 → EXIT_PENDING
손실·장기 한도 발동 → 청산 절차 완료 후 HALTED_RISK
```

`HALTED`는 신규 위험을 늘리지 않는다는 뜻이다. 이미 존재하는 보호주문·잔고 감시·청산 기능까지 종료하지 않는다. `HALTED_UNCERTAIN`은 계좌 상태를 모르므로 확인 없이 추가 매수나 중복 매도를 하지 않는 상태이다. 프로그램 종료와 보유 종목 청산은 다른 동작이다.

### 진입과 보호

- 거래 의도를 DB에 먼저 기록하고 안정적인 `clientOrderId`를 생성한다. 계좌·종목 잠금으로 한 번에 하나의 주문 의도만 처리한다.
- 주문 전 확인한 ask를 호가 단위로 올림한 시장성 지정가를 사용한다. 지정가가 신호 종가+0.1ATR을 넘거나 수량 조건을 위반하면 신호를 취소한다. 미체결 잔여는 10초 후 취소를 요청하며 가격을 올려 추격하지 않는다.
- 매수 접수 응답과 체결은 다르다. 체결 이벤트·REST 주문 내역·보유 수량으로 확인한다. HTTP 시간 초과는 주문 실패로 간주하지 않는다.
- 부분 체결이 발생하면 체결된 수량부터 보호한다. 잔여 매수와 보호 매도의 공존 가능 여부, 조건주문 수량 처리, 계좌의 반대 미체결 주문 제한을 사전 검증한다.
- 초기 운영 경로는 증권사 서버 측 보호주문이 확인되는 구성만 허용한다. OCO라는 이름만으로 부분 체결까지 원자적으로 보호된다고 가정하지 않는다.
- 첫 체결 수신 후 5초 내 해당 체결 수량의 유효 보호 상태를 확인하지 못하면 미체결 매수를 취소하고 복구 청산 절차를 시작한다. 5초는 대응 목표이며 무노출 보장이 아니다.
- API의 실제 조건주문 트리거·매도 가능 수량·반대 주문 제한·부분 체결 동작으로 이 경로를 안전하게 구현할 수 없으면 해당 실거래 경로는 비활성화한다. 검증된 대체 경로 없이 로컬 타이머로 우회하지 않는다.

### 중복 매도 방지와 복구

서버 보호주문과 로컬 청산 의도가 겹치면 계좌별 하나의 청산 조정기가 처리한다. 먼저 보호주문·발동 후 생성된 자식 주문·기존 매도·매수 잔여·실제 잔고를 대조한다. 필요한 취소의 최종 상태가 확인되고 미확인 주문이 없을 때만 남은 매도 가능 수량으로 새 청산 주문을 낸다. 취소 확인 전 이미 체결된 수량은 새 주문에 포함하지 않는다.

취소·발동·체결이 경합해 상태가 불명확하면 반복 매도 대신 `HALTED_UNCERTAIN`, 높은 우선순위 알림, REST 재대조를 수행한다. 시스템이 계좌 상태를 확인할 수 없을 때 즉시 청산을 보장할 수는 없다. 사용자가 토스 앱에서 확인·수동 조치할 복구 안내를 제공한다.

주문 결과가 불명확한 재시도는 원래 주문과 식별자를 유지한다. 멱등성 보존 기간·수정 가능 범위는 최신 API 상세 스키마를 검증한다. 결과 확인 전 새로운 ID로 같은 주문을 다시 내지 않는다. 실제 거래 결과가 확정된 뒤에만 다음 상태로 이동한다.

### 연결·인증

최신 토스증권 개요는 REST와 WebSocket을 지원한다. 시세 채널은 유실 가능하고 주문 이벤트도 연결이 끊긴 구간은 재전송하지 않는다. 재연결 시 REST 주문·잔고 대조가 필요하다. 토큰은 클라이언트당 하나만 유효하므로 발급을 중앙에서 직렬화한다. 구독은 전체 교체 방식이므로 부분 업데이트로 주문 구독이 사라지지 않게 한다. 연결·호출 제한은 최신 스키마와 응답 헤더를 따른다. [토스증권 최신 API 개요](https://openapi.tossinvest.com/openapi-docs/overview.md), [공식 API 명세](https://openapi.tossinvest.com/openapi-docs/latest/openapi.json)

시세나 AI만 실패하면 신규 진입을 차단하고 서버 보호를 유지한다. 주문 연결이 실패하면 재시도·인증 갱신·재대조를 수행하며 새 위험을 만들지 않는다. 다시 연결되어도 최소 60초 정상 상태와 필요한 봉·주문·잔고 대조가 끝난 뒤 READY로 돌아간다. 일일 한도 중지는 다음 미국 세션에 사전 검사 후 해제할 수 있지만 주간·고점 대비 한도 및 보호주문 사고는 점검 기록 없이는 자동 해제하지 않는다.

동일 계좌의 사용자 수동 거래를 발견하면 전략 장부와 대조하고 불일치 상태를 중지한다. 프로그램에 배정되지 않은 종목을 임의로 매도하지 않는다. 전략과 같은 종목을 수동으로 거래하면 귀속 확인이 끝날 때까지 운용을 멈춘다.

## 11. 비용과 성과의 계산

순손익에는 매수·매도 수수료, 실제 발생하는 거래 관련 부과금, 스프레드·슬리피지, 환전 비용, FX 평가 변화, 데이터·서버·AI 운영비를 반영한다. 이미 체결가에 들어간 비용이나 ETF 시장가격에 반영된 펀드 비용을 중복 차감하지 않는다.

확인되지 않은 토스증권 수수료 숫자를 하드코딩하지 않는다. 실제 계좌의 수수료·거래 조건을 조회하고 버전을 저장한다. 해외주식 연간 세금은 개인의 다른 계좌·거래와 과세연도에 영향을 받을 수 있으므로 거래별 임의 고정 세율로 계산하지 않는다. 거래비용 차감 후 세전 성과와 별도 세금 추정을 구분한다.

거래 후보의 기대값 평가에는 주문 수량에 따른 거래비용과 운영비 배분액을 포함한다. 배분액은 직전 완료 20거래일의 하루 평균 운영비를 하루 평균 완료 거래 수로 나눈 값으로 하고 분모 최솟값은 1이다. 모의 기록이 없으면 사전에 정한 일 운영비 예산 전액을 후보 1건에 배분한다. 예상 거래 횟수를 늘려 비용을 작게 보이게 하지 않는다. 실제 거래가 없었던 날의 운영비도 일별 손익에서 전액 차감한다.

성능 지표는 전략 배정금 기준 순손익, 전체 준비 자금 기준 수익률, 전략 최대 낙폭, 최악 일·주, 평균 순손익/R, 순이익 거래 비율, Profit Factor, 보유시간, 시장 노출시간, 비용 비중, 실제 슬리피지, 미체결률, 주문 사고 수다. 일별 순수익률 기반 Sharpe를 계산할 경우 사용 기간·무위험수익률·연율화 방법을 함께 표시한다.

“최대 낙폭 5% 이하” 같은 목표를 실현손익만으로 검사하지 않는다. 장중 평가손실, 주문 지연, 갭·거래정지 및 잔여 외화 노출을 포함한 상황을 별도로 보고한다.

## 12. 검증 설계와 실거래 승격 기준

아래 통계 문턱도 제안한 시험 정책이다. 통과하더라도 미래 수익 보장이 아니며, 표본 수만 채웠다고 통과하지 않는다. 실제 수행 전에는 결과를 빈 값이 아닌 **미검증**으로 표시한다. 백테스트가 가상의 과거 결과라는 점은 [Investor.gov 성과 주장 안내](https://www.investor.gov/introduction-investing/general-resources/news-alerts/alerts-bulletins/investor-bulletins-47)를 참고한다.

### 12.1 데이터와 시간 분리

- 목표 데이터 기간은 최소 36개월이며 상승·하락·고변동 구간을 별도로 평가한다. 필요한 시점별 뉴스·호가가 없으면 기간을 확보한 것처럼 주장하지 않는다.
- 마지막 6개월은 최종 시험으로 봉인한다. 나머지에서 학습 12개월 → 보정·설정 선택 3개월 → 시험 3개월을 3개월씩 이동한다. 전처리·변수 선택·확률 보정도 해당 시점 이전 자료로만 수행한다.
- 경계에서 라벨의 보유 구간이 겹치는 표본은 제거한다. 같은 날·동일 뉴스의 상관관계를 고려하고 최소 한 거래일의 간격을 둔다. 임의 섞기 검증은 사용하지 않는다.
- 과거 기사의 당시 본문만 넣어도 현재 언어 모델이 후일 사건을 알고 있을 수 있다. 과거 LLM 뉴스 분석은 이 한계를 표시하고, 실시간으로 당시 생성·보관한 출력에 대한 전진 검증을 필수로 한다.
- 전체 시험한 변수·전략·문턱·프롬프트 조합을 기록한다. 최종 6개월 결과를 보고 다시 고르면 그 기간은 더 이상 최종 시험이 아니다.

### 12.2 체결과 비용 재현

- 신호 봉 종가에 바로 샀다고 가정하지 않는다. 데이터 수신·AI 응답·주문 지연 이후의 유효 호가, 정수 수량, 취소·부분 체결을 반영한다.
- 동일 봉에서 익절·손절이 모두 닿으면 틱 자료로 순서를 확인하거나 불리한 체결 순서를 사용한다. 모르는 순서를 수익이 큰 쪽으로 선택하지 않는다.
- 호가 데이터가 없으면 보수적 가정의 탐색 시험으로만 분류한다. 그 결과만으로 초단기 체결 성능 검증을 완료하지 않는다.
- 기본 비용과 불리한 체결비용 2배 시나리오를 각각 검사한다. 2배는 스프레드·슬리피지 추정에 적용하며 세금·ETF 비용을 중복 확대하지 않는다.
- SOXL은 실제 가격·병합·상품 변경 이력을 사용한다. SOXX의 누적 수익률을 3배 해서 SOXL 백테스트를 만들지 않는다.

### 12.3 비교 실험

같은 기간·후보·위험 예산·청산 규칙에서 다음을 비교한다.

| 실험 | 목적 |
| --- | --- |
| 거래하지 않는 현금 장부 | 운영비를 지불하면서 거래할 경제적 이유가 있는지 확인 |
| SOXX 단순 보유 및 노출을 맞춘 비교 | 시간·변동성·위험 차이를 표시하여 단순 대안과 비교 |
| 6절 규칙만 적용 | AI 없이 발생하는 성과·손실을 확인 |
| 규칙 + 시장·가격 수치 모델 | 수치 예측의 추가 가치 확인 |
| 규칙 + 수치 모델 + 뉴스·문맥 AI | AI 추가 비용을 포함한 개선 여부 확인 |

기관 보유·옵션·소셜 자료는 추가 실험에서만 편입한다. 없는 자료는 만들어 채우지 않는다. AI가 거래를 거부한 후보도 결과를 기록하되, 거부된 후보의 손익이 관측 반사실적 모의 결과라는 점을 표시한다.

### 12.4 승격 판정

1. 시간 외 시험에서 완료 거래 200건 이상, 거래일 120일 이상, 봉인 시험 완료 거래 50건 이상을 확보한다. 부족하면 표본 부족이며, 조건을 완화해서 개수를 채우지 않는다.
2. 기본 비용 차감 순손익 > 0, 순손익 기반 Profit Factor >= 1.2. 손실 거래가 거의 없어 분모가 불안정하면 별도 표본 부족 표시를 한다.
3. 일별 손익을 날짜 순서 블록으로 재표집한 95% 신뢰구간에서 평균 순손익 하한 > 0. 시험 초기값은 5거래일 블록·10,000회, 1·10거래일 블록 민감도도 표시한다. 상관·비정상성·반복 실험의 한계가 있으므로 이를 성공 확률 95%로 부르지 않는다.
4. AI 추가형의 일별 순손익 개선을 동일 날짜의 규칙 기준과 짝지어 비교한다. 95% 구간 하한이 0 이하이면 AI의 추가 가치 미입증. 그 버전의 AI 자율 실거래 승격은 보류한다.
5. 불리한 체결비용 2배에서도 순손익 > 0. 설정 주변 ±20%의 사전 지정 가능한 조합 중 70% 이상에서 순손익 > 0. 실제로 시험한 조합 수를 기록한다.
6. 시험 배정금·동일 위험 설정에서 최대 낙폭 <= 5%. 최악의 장중·갭 시나리오도 따로 보고한다. 브레이커로 조기 중단된 기간의 이후 성과를 누락하지 않는다.
7. 같은 고정 버전으로 실시간 모의 운용 최소 60거래일 및 완료 거래 50건을 모두 충족한다. 예상과 실제 데이터·모의 체결의 차이를 설명할 수 있어야 한다.
8. 아래 장애 수용시험이 통과하고, 실제 계좌의 허용 상품·조건주문·부분 체결·수수료·데이터 권한이 확인되어야 한다. 모의 검증과 실계좌 검증은 따로 표시한다.
9. 실거래를 별도로 활성화한 뒤에는 처음부터 500만 원 전액을 투입하지 않고 100만 원 배정·작은 정수 수량 한도로 관찰한다. 초기 소액 검증도 손실이 발생할 수 있다. 증액은 별도 버전·검토로 처리한다.

AI 추가 가치가 확인되지 않으면 뉴스 해설이나 거래 일지 용도로 유지할 수 있다. 이 경우 “AI가 수익을 개선했다”고 표시하지 않는다. 거래 기회가 적어 위 조건을 충족하는 데 오래 걸릴 수 있으며, 100회라는 숫자 하나를 안전 인증처럼 사용하지 않는다.

## 14. 운용 중 기록·감시·재학습

각 신호와 비거래 판단에 입력 스냅샷, 출처·수신 시각, 모델·프롬프트·설정 버전, 승인·거부 사유, 당시 비용 추정, 주문 의도·응답·체결, 보호 상태, 실현·평가 손익을 기록한다. 상세 내부 사고과정을 저장하도록 요구할 필요는 없으며 검증 가능한 근거와 결정을 저장한다. API 비밀키·인증 헤더·계좌 개인정보는 분석 AI에 보내거나 로그에 남기지 않는다.

매일 미국 장 종료 후 주문·잔고·조건주문·비용 대조, 사고·미완료 청산 확인, 달력·데이터 버전 기록을 완료한다. 손익은 거래일 기준으로 일관되게 집계한다.

- 실제 손절 손실이 계획 위험 예산의 2배 초과 또는 보호 사고 1건이면 장기 중지 후 원인 분석한다. 초과 손실을 막는다는 보장이 아니라 사고 대응 조건이다.
- 최근 20개 체결에서 비용 추정 대비 실제 슬리피지가 체계적으로 악화되거나 필수 데이터 분포가 이탈하면 신규 진입을 중지하고 비용·모델을 검토한다. 초기 정량 조건은 평균 실제 슬리피지 > 평균 예상 슬리피지의 2배. 예상값 0은 허용하지 않는다.
- 월 1회 성능·확률 보정·변수 기여·비용을 점검한다. 데이터 부족이면 갱신하지 않는다. 새 모델은 기존 모델과 관찰 모드로 비교한다.
- 손실을 만회하려고 위험 한도·주문 빈도·레버리지를 자동 확대하지 않는다. AI의 실시간 자기 학습으로 검증된 정책이 조용히 변하지 않게 한다.

## 15. 프로그램의 최종 의사결정 순서

다음은 언어·프레임워크에 독립적인 의사코드이며 실행 프로그램은 아니다.

```text
on_market_or_order_event:
    persist_and_reconcile_received_events()
    if account_or_order_state_is_uncertain:
        block_new_entries()
        reconcile_with_broker_and_alert()
        return

    enforce_existing_position_protection_and_exit_policy()
    if halted_or_position_exists_or_entry_order_exists:
        return

    if not completed_15m_signal_ready:
        return
    if not data_quality_and_calendar_and_risk_gates_pass:
        record(ABSTAIN, reason_codes)
        return
    if not deterministic_candidate_rule_passes:
        record(ABSTAIN, reason_codes)
        return

    proposal = build_entry_stop_target_horizon_and_costs()
    quantity = compute_integer_size_with_all_caps(proposal)
    if quantity < 1:
        record(ABSTAIN, INSUFFICIENT_RISK_BUDGET)
        return

    assessment = validated_ai.evaluate(snapshot, proposal, quantity)
    if not schema_evidence_distribution_and_net_expectancy_pass:
        record(ABSTAIN, reason_codes)
        return

    recheck_latest_quote_balance_orders_and_all_limits()
    if proposal_or_quantity_changed:
        recompute_cost_and_expected_return_within_signal_deadline()
    if deadline_expired_or_any_gate_failed:
        record(ABSTAIN, reason_codes)
        return

    persist_unique_order_intent()
    submit_to_selected_paper_or_explicitly_enabled_live_adapter()
    follow_order_state_machine_and_verify_protection()
```

**프로그램의 승인 문장:** “현재 사용 가능한 신뢰된 데이터에서 시장·가격 후보 조건이 충족되고, 검증된 AI가 고정 청산 정책과 모든 비용하에서 양의 기대값을 추정하며, 독립 위험 검사와 체결·보호 조건이 모두 통과할 때만 정수 수량으로 진입한다. 하나라도 불명확하면 신규 거래를 보류한다.”

## 16. 현재 완료 범위와 남은 사실 확인

완료한 것은 공개 자료 조사, 운용 규칙·시험 수치·산식·상태·검증 계획 작성이다. 토스증권 최신 공개 개요를 읽어 검색에 남은 REST 전용 구버전 설명과 현재 REST·WebSocket 설명을 구분했다. 실제 계좌나 API 비밀키를 사용하지 않았다.

백테스트, AI 모델 학습·보정, 실제 체결 시험, 상품별 조건주문 수용시험, 데이터 공급 계약, 사용자 계좌의 이용 자격, 수익률·최대 낙폭 측정은 **모두 미검증**이다. 특히 뉴스의 시점별 보관과 실제 주문 보호 동작이 확보되지 않으면 이 명세만으로 실거래를 시작할 수 없다.

자료 링크는 관련 주장 옆에 제공했다. 연구가 뒷받침하는 원칙과 이 문서가 새로 제안한 숫자는 구분했으며, 출처가 본 전략의 수익성을 인증하는 것은 아니다.
